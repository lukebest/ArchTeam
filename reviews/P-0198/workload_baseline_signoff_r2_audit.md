## 2. 签字 1：饥饿判定线和 lib all-on 后的裁决

### 2.1 判定线（审计定义；作者的「<1.2 = 轻微」不用）

指标 w = 某方向的 `inject_fail_<dir> / inject_succ`，即**每次成功注入伴随的阻塞环周期**。某 (端口角色, 环, 方向) **被判为下游饥饿，当且仅当下面四条都成立**：

| 条件 | 定义 | 理由 |
|---|---|---|
| S0 同质池 | 池内样本必须是同一 die 类型、同一物理环，CS 按**物理位置**排序；每个样本必须同时有 first 和 last | 防止 §2.3 里的混池和分母错配 |
| S1 统计 | 池化均值之比 R = mean(last)/mean(first)（8 种子 × 类 × die）；SE 由**按种子重采样**的 bootstrap 得到（5000 次）。要求 **R − 3·SE > 1.10**，且 **≥7/8 颗种子**的单种子 R_s > 1 | 3σ 对应用户给的「3σ_seed」。10% 是实质性门槛，与 makespan 阈值同一量级。7/8 是方向一致性 |
| S2 绝对下限 | 下游端 mean(last) **≥ 1.0 阻塞周期/注入**，且 last − first **≥ 0.5 周期** | 环每周期在一个 CS 前推一个 slot（top 2.5 GHz，1 周期 = 0.4 ns）。w < 1 表示平均等不到一个 slot 经过就注入成功了，谈不上「抢不到 slot」。一个 512 B 事务是 8 个 Dat flit，w=1 时整笔事务最多多出约 8 周期 ≈ 3.2 ns，相对 smoke 事务时延（summary `avg_latency` 数百 ns）不到 1–2%，低于任何 makespan 阈值。所以 w<1 的梯度在物理上不可能是 makespan 的瓶颈 |
| S3 方向 | **已核**：`TNetwork.cpp:83-106` 把 CC 邻居设成节点表的前一个（i−1），CW 邻居设成后一个（i+1）；`TCsHighWay.cpp:1135-1142` 表明 flit 送往该方向的邻居；top 的 Node_list 是 0..20。所以 **CW 往 CS 号增大的方向流，下游 = last；CC 往 CS 号减小的方向流，下游 = first**。判定时 cw 用 last/first，cc 用 first/last；sum 没有单一下游，不用于判定 | 作者对 cc 也用 last/first，取向反了 |

**判定线的灵敏度**：在 os16 下，对 lib_all_on，只要 S2 的下限 ≥ 0.22 周期/注入（远低于 1 个 slot），结论就不变（§2.2 里所有过 S1 的行，下游绝对值都 ≤ 0.222）。改用 95% bootstrap 下界 > 1.10 代替 3σ，结论也不变。

**判定线的辨别力（对照 none）**：
- none 的 AIC Dat r0/r1（sum）满足 S2：4.18 / 4.53 周期，Δ ≥ 1.5。95% CI 下界 1.10 / 1.24，但 R−3SE = 0.69 / 0.77，S1 不过。所以 none 的 AIC Dat 落在「95% 显著，3σ 不显著」的**趋势**区。
- none 的 top 3DIO cw 满足 S1（R=1.905，R−3SE=1.50，8/8），但 S2 不过（0.248）。

可见这条判定线既不是一律给 Y，也不是一律给 N。

### 2.3 作者 3DIO 1.785 / pooled 1.29 的成因（S0 违例）
1. **混了 die**：`pool_gradients` 的键是 (channel, ring)。dio 的 ring 0 同时包含 top die1/die2 的 3DIO DOWN 口（挂在 top ring0 的 CS 0,2,4,6,8,11,13,15，即读回数据送往 AIC 的路径）和 **bottom die0 H ring0 上的 3DIO**（raw 0x100–0x106）。用户说的「bottom-die 3DIO Dat H ring0」实际上**主要是 top die 的 3DIO**，混入了 bottom 的样本。
2. **CS 序错**：dio 的 cs 取的是 raw 端口号（`inject_wait.py` 只映射 AIC/HA）。bottom ring0 按 raw 排是 CS24, 1, 21, 4，不是物理顺序。
3. **分母错配**：28 个 bottom 样本 first 端有限（w=0）、last 端是 0/0。它们进了 firsts（全是 0），没进 lasts。验算：0.118749 × 121/149 = 0.096434，正好等于作者的 mean_first，所以 1.785 = 0.172/0.0964。**只取 top die 时 cw 是 1.450，sum 是 1.048（作者 1.290）。**

### 2.3b 端点指标的脆弱性和稳健替代
first/last 只看两个端点 CS；剖面不单调时会被单个端点主导。例如 os512 下，none 和 sub_rr 的 cc 剖面峰在 CS4，CS0 反而下陷，端点比值就看不到饥饿。所以本审计**另加一个稳健指标**：**半环均值比** = 下游一半 CS 的均值 / 上游一半 CS 的均值（cw 的下游是高 CS 一半，cc 的下游是低 CS 一半），沿用同样的 S1/S2。§2.4 和 §2.5 的裁决同时看这两种指标。

### 2.4 裁决（签字 1）
**签：lib all-on（smoke、os16、2 die、dest-shuffle 8 种子）后，按上面的判定线，下游饥饿 = 否。**
- 统计上站得住的梯度只有 top 3DIO Dat r0 cw，以及按正确取向的 cc（R 1.43，下游 0.136），两者下游绝对值都远低于下限。cw 的数字：R=1.45，8/8 种子，R−3SE=1.12。但下游绝对值只有 0.17 周期/注入（每 5–6 次注入才阻塞 1 个周期），远低于 1 个 slot。签为「**统计可见、物理上无关紧要的梯度**」，不是饥饿。
- AIC Req r0 cc 1.179：种子散布 0.28–5.41，CI 覆盖 1，绝对值 0.06。**否**。
- HA Dat ∞：绝对值 0.0002，n_inf=0。**否**。
- 未覆盖、不签的部分：top 3DIO→ring1 的 Dat、Rsp/Snp（AIC 不注入 Rsp/Snp，Snp 流量 0）、os≥128 下的饥饿（另见 §2.5 审计扩展：**os512 下是「是」**）、12+2 规模。
- 附注：lib 下 AIC Dat 的**绝对**等待（3–4 周期/注入）比 none 的上游端（2.6）还高，但没有下游斜坡。这是「全环拥挤」，不是「下游饥饿」，不属于闸门问题的定义。

- 稳健指标（半环均值比）在 os16 下：所有臂、所有 (角色, 环, 方向) 都**没有**同时过 S1+S2 的行。lib 只有 top 3DIO cc（0.121→0.160，R 1.32，过 S1，下游 0.16 ≪ 1）。逐种子下游半环都 ≤ 0.20。**os16 的「否」对指标选择稳健。**

1. **饥饿：os16 = 否（签）；os512 = 是（签，限于模型内、相对、2 die；物理位置未核）。**
2. **旋钮过 0.85：否（签）。** 机制旋钮在任何 outstanding 下都没有接近 0.85。低于 0.85 的行只出现在 os≥128，而且全部来自 sub_rr 这个基线修正。
3. **闸门：扩到 12+2 = 是**，依据是**饥饿这条腿在信封 outstanding（512）下成立**。
   - 理由：os16 的「否」是负载不足造成的。os16 下 FC 从不触发，所有下游等待 < 0.3 周期/注入，小于一个 slot。闸门问的是系统在真实负载下是否饥饿，而信封的 read outstanding 是 512（推导值，`TrafficGen.h:160-163`）。
   - 如果船长的本意是「只看作者的 os16 smoke」，那么两条腿都是否，**不扩**。这是本签字唯一的歧义点，需要船长确认他问的是哪个 outstanding。

### 什么会翻转结论
- **翻成「不扩」**：
  - (a) 船长明确以 os16 smoke 为准；
  - (b) top 3DIO 的物理挂法（DOWN 口挂在 CS 0–15、1×2 双环）被证明与平台不符，而按正确挂法重测后，下游半 < 1.0 周期/注入；
  - (c) 把饥饿下限提到 > 1.24 周期/注入（os512 lib 的下游半是 1.235；sub_rr 1.041 在下限 ≥ 1.05 时就翻转）；
  - (d) 补测 ring1 那一路和 12+2 后，ring0 的结果不再成立（这本身就是在扩规模）。
- **在 os16 下翻成「扩」**：任何机制旋钮相对 sub_rr ON 到 ≤ 0.85，或者某 (角色, 环, 方向) 的下游等待在 8 种子下 ≥ 1 周期/注入，并同时过 S1。按现有数据，两者都差得很远：最低 0.997；下游最高 0.22。
- **旋钮腿翻成「是」**：船长决定把 sub_rr 也算作旋钮（相对 none）。那样 os≥128 下 RS/AR/mix_L 过 0.85，但这仍然只是基线修正。
