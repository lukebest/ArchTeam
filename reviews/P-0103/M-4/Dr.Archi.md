# Dr. Archi · T1 微架构评审 · P-0103/M-4 MRDR

## 结论
致命缺陷

MRDR 在硅上是「55b 的 `G mod 9` 剩余树 + 两路 8b XOR 折叠压成 trit + 11b 接线反转 + 混合进制拼接」，不是表、不是预测器、也不是递归除法器；主路径无 FSM、无跨 DMC 借贷、无 `core_id`，这一点成立。作者掩盖的是熵预算：`BITREV11` 只能重排 `G[10:0]`，`H0/H1` 把更高位压成各 1 个 trit——信封内 `S=1.5MiB`（`δ=3072`）时 `q[6:0]` 只走 2 个 DMC 组，`t0'` 只把因子 3 救活，`n_DMC=6` 不是 384；`S=2MiB` 时 `p` 全冻，`n_DMC=3`。把「trit 解冻」写成「占用回到 384」是结构谎言，不是评测噪声。

## 五维打分
| 维 | 分 | 一句话理由 |
|---|---|---|
| 可行性 | 2 | 组合映射可综合、ID 合法，但 11b 熵在信封大步长上闭合，占用目标不可达 |
| 新颖性 | 3 | 「反转前注入 trit」有可证伪结构命题；XOR-fold 与 FFT 数位反转本身不新 |
| 预期收益 | 2 | 大步长 ~6 DMC、小步长 128-outstanding 窗口内仍 ~128；再叠加 2:1:1 偏置 |
| 评估可信度 | 2 | 自承非 `Z_3` 同态，却把 `t0'` 满写成 384；200 GE、1R/1 拍与电路不符 |
| 系统可组合性 | 2 | 无 `core_id`、不改 384/48；1R `GOOD_MAP` 与 DMC 2:1 热点会污染下游仲裁 |

## 最强反对意见
`BITREV11` 的 2-adic 熵被锁死在 `G[10:0]`（§2.2：`q[i]=p[10−i]`，`DMC=t0'+3·q[6:0]`），而 `H0=fold(A[26:19])=fold(G[17:10])` 只向 `t0'` 注入 1 个 trit、**不**把高位送进 128 组索引。`δ=3·2^{10}=3072`（`S=1.5MiB`）时 `G[9:0]` 冻、`p[10]` 每拍翻转，故 `q[6:0]` 只有 LSB 活 → 2 个组；`t0'` 即使满 `Z_3` 也只给出 `n_DMC=2×3=6`。§3 写「`q[6:0]` 的 128 组仍走、占用从 128 回到 384」把「奇数因子解冻」偷换成「组索引满扫」——这是电路拓扑决定的上界，改常数救不了。

## 评估层必须验证的一个假设
**H-MRDR-384**：对 sequential AP、`S=1.5MiB`（`δ=3072`）、8GiB 共享窗口，cycle 级闭合 `RADIX_SPLIT → TRIT_INJ → BITREV11 → DIGIT_DEC`（§2.2 公式，禁止关掉 `TRIT_INJ`），统计 distinct `DMC` 数 `n_DMC`。失败判据：`n_DMC < 128`（该电路的结构上界是 6；若实测 ≤6，则 §3 的「128→384」命题直接作废）。

## 微架构要点
- **MRDR 作为电路**：`MOD9_PRE` 是 55b `G=A[63:9]` 的 6b 块求和（`64≡1 (mod 9)`）+ 小宽度剩余，不是逐拍恢复除法器，也不是递归 residue 状态机；其后 `r→(t0,t1)`、两路 4b 奇偶折叠、`(H==3)?0:H`、两个 2b 模 3 加、`bitrev` 接线、`DMC/bank_in` 的 `×3` 移位加，全部组合。无映射 ROM，无额外互连 round-trip。§2.5「CSA 深 ~4 + XOR 深 3 + 模 3 加 <10 级、7nm 2 GHz 一拍」是发明的 STA：CSA 之后仍有 6–8b CPA 和 `mod 9` 压缩，深度被低估，但 2 GHz 一拍仍可能，**不是**时序死刑。
- **表/缓冲/端口**：映射路径无 RAM（§2.3）。`GOOD_MAP` 384×48b = 18432b 位图，1R、×1 共享给 120 核。每次请求若要 partial-good，应一次读出该 DMC 的 48b mask，再在 mask 上做组合探测——**不是** 18432 项表。致命缺口在端口：120:1 仲裁、请求队列、反压就绪信号全部缺席；§2.5「再 1 拍 SRAM」假定无冲突。若改成对 `b0/b1/b2` 三次探 SRAM，1R 下是 3 拍不是 1 拍（发明关系）。无 CDC、无跨时钟 FIFO。
- **FSM / 反压 / 死锁**：主路径无状态，无 livelock。`XOR_RETRY`（§2.4）最多 3 个组合探针（`b0`，`b0⊕h1[4:0]`，再 ⊕ `{h0[2:0],2'b01}`），`b≥48` 则 `−32`（落到 0..31，**不是** `+1` 扫描，DMC 锁定，满足「不跨 DMC 借 bank」）。未定义三探全 miss 时的行为（死 bank / 卡住 / 丢掉）。重试图：`⊕5b` 保持 bit5，故 0..31 与 32..47 不是强连通——0..31 回不到 32..47。1/3 图案杀 `bank_in%3=t1'` 时，XOR 非 `Z_3` 运算，存在两次仍停在被杀类的请求；无第三拍、无借用，硅上就是不可达 bank。
- **384/18432 拟合**：`DMC=t0'+3·q[6:0]∈[0,383]`、`bank_in=t1'+3·q[10:7]∈[0,47]` 与 `384=3×128`、`48=3×16` 接线一致；`die=q[6]` 给出 192/die，避开用 `DMC[8]` 切 die（§2.2，非发明）。`HA=local/2`、`pipe=local%2` 是 LSB 接线。容量数不改，只改交织，符合信封「只改 interleave」。
- **`core_id` / 3-adic / partial-good**：未用 `core_id`。`3|δ` 时 `t0=G mod 3` 冻，§1 正确指出「只反转不够」。`H1=fold(G[7:0])` 在 `δ=3/24` 且 `gcd(3,256)=1` 时可满扫，**bank trit 有活源**；`H0` 在 `δ=3` 靠 `G[9:0]` 进位，约每 341 拍才变——相对 128 outstanding，窗口内 `t0'` 冻，瞬时 `n_DMC≈128`（`X_rel` 仍是 3）。`δ≡0 (mod 9)`（`S=4608B` 及倍数）时 `t0,t1` 双冻，只剩 H 注入；长窗 visit-count 可能看起来像 384，占用不是。`H0/H1` 的 `{2,1,1}` 直方图（`3↦0`）在 `t0` 冻时把 DMC 三类打成 2:1:1，热类 1.5×、`min/mean≲0.75`——§3 写 0.7–0.9 方向对，但与「`t0'` 满则 Amdahl 项回 1」并列是自相矛盾。`S=12KiB`（`δ=24`）`p[10:3]` 仍活，不是杀手；杀手是信封上沿 `1.5MiB/2MiB`。
- **面积/功耗自洽**：55b 十操作数 6b CSA + 剩余绝不是「每核 ~200 GE」（§5）——量级更接近数百至 ~1k GE；相对 2×Die2 仍可忽略，但 200 GE 与「MOD9_PRE 是大头」互相打脸。`~10^{-4} mm²/核`、`0.1 mW @ 2 GHz` 与修正后的门数同阶，不构成面积爆炸。共享 `GOOD_MAP` `~10^{-2} mm²` 对 2.25 KB 偏肥，若真要 120 读口则完全不是这个数。
- **对照**：卡要求关掉 `TRIT_INJ` 的纯反转在 `S=3·2^k` 上 `n_DMC=128`（§4）。该对照只能证伪「反转就够」，**不能**证实「注入后是 384」——注入只加 1 trit。T0 的 `PASS_T1` 把直方图与非同态留给 T1；T1 结论是：即便 XOR-fold 经验上满 `Z_3`，384 占用在信封大步长上仍不成立。
