# M-3 注入–越过守恒窗（Inject–Pass Conservation Window, IPCW）

- problem: P-0221
- id: P-0221/M-3
- author: Jim Keller
- class: 事件守恒（inject 记账、越过段释放；不是速率桶、不是索取）

## 1. 根因

令牌桶按时间补充——没人注入也往桶里丢令牌，空转窗口会被上游瞬间吃成一段满突发。索取等下游已经饿了才动手，尾已经露出牙齿。

守恒更硬：段 s 上「已经答应会来占用的 flit」有个数上界。注入时对路径上每段 +1，**该 flit 离开该段** 时 −1。这是 in-flight 守恒，不是 dest outstanding（源端 FC），不是 RBRG GRANT（CSR 已死）。

HSSL 搞错上下游。CBC/AODI 不记账谁占用哪一段。本卡把账钉在段上。

## 2. 机制

### 2.1 环段

`(channel, sub-ring, direction, CS_i→CS_{i+1})`。Dat×2、Snp×1（`TMultiRing.cpp:223-231`）。每段 `inflight[s]` = 已注入、路径含 s、**尚未越过 s** 的 flit 数。

「越过」：flit 到达 `CS_{i+1}` 的入边后，本拍被弹出 **或** 转发到下一段。两种都使它不再占用 s。禁止用「改 empty」冒充越过。

### 2.2 结构

| 结构 | 容量 / 位宽 | 出处 / 假设 |
|------|-------------|-------------|
| `inflight[s]` | 饱和计数，宽 `⌈log2(C_ring)⌉` ≤6b（`CS_NUM≤64`） | 段主 CS |
| `I_max[s]` | 默认 **`⌊ρ_max·C_ring⌋`（假设 ρ_max=3/4）** | top `C_ring=21` ⇒ I_max=**15（假设）**；bottom V=38 ⇒ 28。**按该环真实 CS_NUM 算，禁止写死 15** |
| 突发预约 RESERVE | 同通道对向 1 槽 | 一次为 **同一事务剩余 beats** 预约 |
| 512 B / 64 B beat | 8 Dat beats / txn | `Endpoint.h:27` kBeatBytes=64；CHI Table 13-18 Size `0b110`=64 B；题面 512 B 请求 |
| RESERVE 载荷 | `src` 7–11b + `dst` 7–11b + `n_beats` 4b + `txn` 12b | NodeID/TxnID：Table 13-8/13-9 字段宽；dst 在 SNP 表无 TgtID——**Snp 预约用 FwdNID 或 ESL 元数据 dest，不发明 SNP Data** |
| NACK/ACK | 预约 flit 原路或继续走完一圈带回 | 任一路径段 `inflight+n_beats > I_max` ⇒ NACK，已加的段在回程 − |
| 本地 1 深预约寄存 | 仅 RESERVE 往返期间持有 **控制状态**（txn, n_beats, path），**无 Dat 副本** | 深度 1；不是 highway 队列 |
| i-tag | 库内 | 未 ACK 不得注入；i-tag 不能无账抢槽 |

**突发预约**：512 B = 8 拍。一次 RESERVE 为 8 拍一起占账，对向税 1/8，避免 CSR 那种每拍 GRANT。n_beats 随剩余减少。单拍 Snp / Req / Rsp：n_beats=1。

**不是** 源端 FC：FC 的窗口在 dest 事务数；IPCW 的窗在 **路径每一段的 in-flight**。同一 dest、不同路径段，账不同。
**不是** CSR：payload 不上桥、无 CAM latch、无扇入会合。预约只改计数。
**禁止** 借 Snp 运 Dat。

### 2.3 同拍规则

1. NIC 有待注入 txn：对向发 RESERVE（对向忙则等）。`n_beats = min(剩余, 8)`。
2. RESERVE 沿 **对向** 走；每到一个 CS，若该 CS 的正向出边 ∈ 预约路径：试 `inflight += n_beats`，若超过 `I_max` 则打 NACK 位，回程把已成功的加账减回去。
3. 回到源或走满一圈：ACK ⇒ 允许随后至多 `n_beats` 拍在空槽时注入（仍过路优先）。NACK ⇒ fail-wait，指数退避上限 `C_ring`，重试。
4. 正向 flit 越过段 s：段主 `inflight[s] -= 1`（按拍，不是按 txn）。
5. 事务提前结束（dest 早完成）：源发 RELEASE（对向，剩余 beats），段主减回未越过的预留。禁止悬挂账。
6. 不丢 flit。NACK 时数据仍在端点 outstanding，不在环上。

对账不变式（硬）：

```
inflight[s] == (#RESERVE 成功拍) − (#已越过拍) − (#RELEASE 未越过拍)
```

探针 `inflight_mismatch` 必须 ≡0。

### 2.4 环段密度上界

无缓冲环上，路径含 s 的在途 flit 至多 `I_max` 个。每个这种 flit 越过 s **恰好一次**、占 s **恰好一拍**。

任取连续 `C_ring` 拍的窗（一圈）：

```
过路占用拍数(s, C_ring) ≤ I_max
ρ_transit(s, C_ring) ≤ I_max / C_ring ≤ ρ_max
```

**论证**：

1. 窗开始时 inflight ≤ I_max。窗内新 ACK 的拍会抬 inflight，但任何时刻 inflight ≤ I_max（准入谓词）。
2. 窗内越过次数 = 窗内占用拍数（一对一，每拍每段 0/1 槽）。
3. 若占用拍数 > I_max，则某时刻必须有 >I_max 个「已答应未越过」——与准入矛盾。
4. 更短窗可以更满（I_max 个连续拍挤在一起）：**上界按圆周窗陈述**，短窗允许突发，但突发长度 ≤ I_max。这与「逐节点 cap」不同：cap 不管这 I_max 是 1 个上游还是 15 个上游贡献的。
5. 预约往返最多 `C_ring` 拍的账是 **已经加上的** inflight，不是额外占用正向槽。对向 RESERVE 占对向段——对向有自己的 `inflight` 与 I_max，对称执行。

默认假设 ρ_max=3/4、top 21 ⇒ I_max=15 ⇒ `ρ≤15/21≈0.714`。**假设，未测。**

### 2.5 时序

| 事件 | 周期 |
|------|------|
| RESERVE 一圈 | ≤ `C_ring` |
| 8 拍 Dat 突发注入 | ACK 后按基线抢空槽 |
| 越过减账 | 同拍 |
| NACK 重试 | ≤ `C_ring` 退避 |

插入：每 8 拍 Dat 最多 1 条对向控制。Snp 每条 1 预约——Snp 稀疏，税小。

## 3. 为什么尾会动

`I_max < C_ring` 强制圆周上留空。空槽不是日历造的，是 **账上不能再答应更多过路**。下游看见的空槽速率下界 ≈ `1-ρ_max`（圆周平均）。扇入尾节点不再面对 `ρ=1` 的进边。

相对基线（假设）：无 CC / 逐节点 cap 都没有「15 个承诺」这个合计锁。源端 FC 锁 dest 不锁段。i-tag 不记账。CSR 的 GRANT 是扇入会合税；本卡 ACK 只改计数，payload 按基线走。

`ipcw-off` 必须让推理 last-completion 变差。只报 inflight 更平滑、makespan 不动 = 淘汰。

## 4. 失败模式

- 预约税 ≥ 收益（CSR 覆辙）：8 拍打包是为了这个。若 cycle 上 ACK 等待主导尾，卡死，不要改叙事成「更公平」。
- 双向对称预约把对向也打满：分列。
- RELEASE 丢了：inflight 悬挂，段永久拒新注入。看门狗 `T_hang=4·C_ring` 强制清账并计数 `release_watchdog`。清的是 **账**，不是环上数据。
- 把 NACK 写成丢 Dat：非法。
- I_max=C_ring：上界退化成废话。实现必须按 `⌊ρ_max·C_ring⌋`。

## 6. 评估

主指标推理 makespan / 最差节点。基线：无 CC、逐节点 cap、源端 FC、i-tag。消融 `ipcw-off`。Snp 15:1 分列。圆周窗 `ρ` 必须钉上界。

## 7. 可证伪

1. **H-CONSERVE**：`inflight_mismatch≡0` 且 `ρ(C_ring) ≤ I_max/C_ring`。
2. **H-SUM-NOT-NODE**：基线存在「节点 cap 全合规、段 ρ=1」；on 后段 ρ 下降且尾下降。
3. **H-TAIL**：off makespan > on。
4. **H-NO-CSR**：`Dat_beats_held_at_RBRG≡0`。
5. **H-NO-DROP**：completions 完整。
