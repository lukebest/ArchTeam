# M-7: RBRG 出队隔孔

- problem: P-0221
- author: 保守架构师
- style: conservative / implementable

## 1. 根因分析

冻结信封同 P-0221。RBRG 把整条源环在一个着陆 CS 灌进目的环（`TMultiRing.cpp:534-557`）。逐节点上限和三项先例（`experiment_srcfc`、i-tag、动态 leaf-tag）都把桥当成「又一个 NI」：srcfc 在 **源** 环按注入失败扣令牌；i-tag / leaf-tag 是目的环上某 CS 的饥饿/设备预留。桥可以在目的环连续吃空槽，着陆点下游环段被 **外源列车** 填满，本地 KV / 集合 rank 饿死。

库内 RBRG 只在 `getCredit(dir)>0` 时出队（`TNetworkInterfaceRbrg.cpp:147-155`），出缓冲 15 深（`port_ChangeRing_cc.toml:11`）。**没有「忙仍切入」**。本卡不删缓冲、不加线、不改 flit。只加一条着陆侧仲裁：桥每成功出队 1 拍，下一拍目的环空槽 **禁止再给桥**，留给着陆 CS 本地设备或继续前送。

一圈仍按链路和：目的环若是 top = 42，bottom H = 72–76，V = 132/148/152。桥隔出去的孔到达下游 k 跳要 `k·L_link` 拍。

## 2. 机制

### 结构

每个 RBRG 口、每个通道、每个子通道、每个目的方向一份本地 1-bit `GAP`。Dat 2 子环独立。Snp `GAP_EN_SNP=0`。

1. RBRG `xfer` 成功把队头写入目的环空槽后：`GAP ← 1`。
2. 下一拍若目的环该向仍空且 `GAP=1`：`rbrg_grant=0`，队头留在 **既有** 15 深出缓冲；`GAP ← 0`。该空槽走着陆 CS 的 `tryLocalToWay` / i-tag / leaf-tag（本地设备可注），或空着 `xfer` 到下一 CS。
3. 既有 `getCredit` 不变。缓冲满则源环按原 credit 停，合法下一跳仍在。
4. 过路不进本逻辑。不改 `NetworkFlit`。不走 `NetworkFlowCtrl` 反传（那是源环令牌路径，`docs/flowcontrol_setup.md:30-53`）。

与 M-6 的差别（若两卡同时存在也不互相依赖）：M-6 是 **注入者自己** 欠孔；本卡是 **桥欠孔、着陆本地优先吃孔**。受益者是着陆点设备，不是桥下游更远的站。

### 数据路径与状态机

两状态。每拍目的环着陆 CS、每方向：

1. `rbrg_grant = credit>0 && slot_empty && !GAP && !itag_leaf_reserved_for_local`。
2. grant 则出队、`GAP=1`。
3. 否则若 `GAP=1` 且槽空：`GAP=0`，槽给本地仲裁。

同拍 1-bit。`L_link` 后孔出现在着陆+1 CS。

## 3. 第一性原理与逐环段密度上界

着陆环段 `ℓ`。拆 `O_ℓ = T_up ∨ I_rbrg ∨ I_loc`。

**桥项：** 每次 `I_rbrg=1` 后，下一个目的环空槽 `I_rbrg=0`。故桥对空槽的占用满足 `λ_rbrg ≤ h_ℓ/2`，其中 `h_ℓ` 是着陆段空槽率。桥贡献密度

\[
\rho_ℓ^{\mathrm{rbrg}} \le \tfrac12(1-\rho_{\mathrm{tr}}-ρ_{\mathrm{loc,compete}}).
\]

在桥主导、本地竞争弱时 `ρ_ℓ^{\mathrm{rbrg}} ≤ 1/2`。桥不能再打出连续列车。

**下游 `ℓ+1`：** 桥让出的孔经 `L_link`（2/3/4 拍）到达。若本地不抢，孔率 ≥ `λ_rbrg`；若本地抢（本卡允许），着陆设备先解饿，这是本卡的主受益者。更远下游 **不** 由本卡保证——不加孔保护位（加位=加线），也不走反向环通知上游。

**过路上游 `T_up→1`：** 无空槽，闸不触发，本卡零操作；诚实失效，不得写成收益。

不丢：队头留 15 深既有出缓冲。不把出缓冲当新队列。

## 4. 推理收益与失效条件

推理（主）：decode KV / 集合过桥后，着陆点附近 rank 是 straggler。桥隔孔把空槽留给这些 rank，`T_step` 的 max 项下降。主指标不是桥吞吐。

失效：几乎不过桥；或饥饿点在着陆点下游很远；或 `T_up=1`。出缓冲满把拥塞推回源环且 `T_step` 变差 → 失败，不得加深出缓冲。

训练大块（一句）：过桥拍数多，隔孔拉长桥注入，允许变差。

## 5. Cycle 级评估计划

### 基线

**B\***：`experiment_srcfc` + i-tag（`:1095-1110,:1151-1158,:894-950`）+ 动态 leaf-tag（`gen_config.py:359-362`）。本卡叠在 B\* 上。禁止调 ChangeRing 深度 / srcfc rate 当收益。

### 仿真器改动（新分支，不改 RTL）

1. `src/TNetworkInterfaceRbrg.cpp`：出队后置 `GAP`；下一空槽 `grant=0`。不改出缓冲深度，不改 `reInitializeNetworkFlit`。
2. `--cc-scheme rbrg-gap`。不要用 `CongestionCtrl` 令牌。
3. `infer-decode` 负载（同 M-6 配比）+ 过桥比例实测（`routes.csv`）。
4. 逐环段占用（着陆段与着陆+1 段分列）、桥出队/隔孔计数、出缓冲水位。

### 必须 cycle 级建模

- 1-bit `GAP`、credit、15 深既有缓冲、`L_link`。
- **不要** 令牌/ECN/删缓冲/flit 位/反向线。

### 消融与证伪

- G0：B\*。
- G1：B\* + 隔孔（HARD）。
- G2：隔孔但桥仍可连续出队（负对照）。

G1 的推理 `T_step` 须优于 G0。着陆段在 G0 已满且 G1 不可分 → 禁写因果。`T_mix≈1` 或 `r≈1` → 失败。Snp 超阈 → KILL。

## 6. 面积 / 功耗 / 延迟估算

每桥口每子通道每方向 1 flop，`<2 kGE`，0 新 SRAM，0 新 flit 位。出缓冲是既有 15。决策 +0；孔到下游 `L_link`。过路 +0。

## 7. 与已有功能 / 先例的区别

- **不是** srcfc：不在源环扣令牌；看的是目的环出队隔孔。
- **不是** i-tag / 动态 leaf-tag：不打标、不停 invalid；桥主动让普通空槽。
- **不是** change-ring 预留槽（`TCrossStation.cpp:137-177`）：那些是给桥留槽，极性相反。
- **不是** 令牌/信用/ECN/RPR/GSF：无窗口积分。
- **不是**「忙则切入 + 续行」：库已是空槽才写；本卡在空槽上再隔一次。
- **不加线 / 不占反向环。**
