# M-5: Base-3 Carry-Save Hash (B3CSH) — 三进位保存进位树

- problem: P-0103
- author: Jim Keller
- id: P-0103/M-5

## 1. 根因分析

整数取模在 `Z` 上线性。`δ` 的 3-adic 赋值 `v_3(δ) ≥ 1` 时，和式 `G0 + kδ` 的 `v_3` 下界把 `G mod 3` 冻住。DMC 因子 3 与这个赋值同构，占用 /3。

本卡打的环：**3-adic 赋值本身**。不在 `Z` 里做 `mod 9`，把地址位切成 3b 块，每块映到一个 trit，再用 `Z_3` 上的 carry-save 树相加。加法在基 3 里产生进位，进位权重是 3 的幂。AP 只要打翻某个 3b 块里的一个 2 幂位，该块的 trit 就变，树的输入就变。`δ ≡ 0 (mod 3)` 不再蕴含“所有 trit 输入常数”——那只对**按整数解释的 `G mod 3`** 成立，对按位切块不成立。

这张映射**不宣称**是 18432 上的双射。论证是统计平衡：8GiB 窗口里 2 幂轴仍打满 2048；trit 树是 3 值扩展器，AP 在被命名的块上仍有变化输入。

## 2. 机制

### 2.1 结构

1. **CHUNK8**：`A[32:9]` 共 24b，切成 8 个 3b 块。
2. **TRIT_ROM**：8 份 8×2 LUT（3b 地址 → trit 0..2）。同一张表复制 8 次，或 8 路并行组合。
3. **CSA_Z3**：`Z_3` 全加器树。每个 CSA：3 个 trit → 2 个 trit（和 + 进位，进位权重 ×3）。深度 4。
4. **GF2_11**：11×11 接线，2-adic 的 DMC/bank 位。输入不用“冻奇数类”的算术 `G mod 3`，用 bit 的 GF(2) 混合，并混入高于 11b 的位。
5. **PACK_SEL**：与 M-2 同类，48 输入 select-k。禁止 `+1`，禁止对 `N_good` 再 mod 3。

无 FSM。无 stride 锁。1 拍组合树。

### 2.2 数据路径

块划分（必须写清，后面要点名谁在 `δ = 3, 9, 24` 下翻转）：

```
C0 = A[11:9]    = G[2:0]
C1 = A[14:12]   = G[5:3]
C2 = A[17:15]   = G[8:6]
C3 = A[20:18]   = G[11:9]
C4 = A[23:21]   = G[14:12]
C5 = A[26:24]   = G[17:15]
C6 = A[29:27]   = G[20:18]
C7 = A[32:30]   = G[23:21]
```

8×2 ROM，地址 0..7 → trit。直方图 3,3,2（8 不能被 3 整除）：

| c | 0 | 1 | 2 | 3 | 4 | 5 | 6 | 7 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| trit | 0 | 1 | 2 | 0 | 1 | 2 | 0 | 1 |

`#(0,1,2) = (3,3,2)`。`c` 跑满 8 点时 trit 盖满 `Z_3`。

`Z_3` CSA：`s, cy ∈ {0,1,2}`，`a+b+c = s + 3·cy`（整数等式，`cy = ⌊(a+b+c)/3⌋`，`s = (a+b+c) mod 3`）。输入最大 6，`cy ≤ 2`。每个 CSA 是 3×3×3 → 2 trit 的 27 项 LUT，或 2b 加 + 比较。

树（8 个重量 1 的 trit `w0[0..7]`）：

```
// 层 0：两组 3:2，剩 2 个旁路。深度 1
(s0, c0) = CSA(w0[0], w0[1], w0[2])       // s0 重量 1，c0 重量 3
(s1, c1) = CSA(w0[3], w0[4], w0[5])
p0 = w0[6]; p1 = w0[7]

// 层 1：重量 1 的 4 个（s0,s1,p0,p1）再压。深度 2
(s2, c2) = CSA(s0, s1, p0)                // c2 重量 3
// p1 旁路

// 层 2：重量 1 的 (s2, p1) 与 0 补成 3:2，或 2:2 加。深度 3
(s3, c3) = CSA(s2, p1, 0)                 // s3 = 重量 1 的最终 digit d0
                                          // c3 重量 3

// 层 3：重量 3 的 (c0,c1,c2,c3) 压成 2 个 digit。深度 4
(s4, c4) = CSA(c0, c1, c2)                // s4 重量 3，c4 重量 9
(s5, c5) = CSA(s4, c3, 0)                 // s5 重量 3 = d1；c5 重量 9
(d2,  _) = CSA(c4, c5, 0)                 // d2 重量 9；第三输入 0
```

输出三个 trit：`d0, d1, d2`。整数和 `Σ trit(Ci) ∈ [0, 16]`（每块最大 2），故 `d2 ∈ {0,1}`，几乎不取 2。**不能把 d2 直接当 DMC trit**——那会缺一类。混：

```
r_hash  = d0 + 3 · d1                     // Z_9，bank 奇数 + 备用
dmc_odd = (d0 + d1 + d2) mod 3            // 混低高 digit，d2∈{0,1} 仍能让和跑满 Z_3
```

2-adic 11×11 接线。不宣称双射。混入高位，避免大 `2^m` 步长把 `G[10:0]` 冻死：

```
// i = 0..10
p_mix[i] = G[10−i] ⊕ G[11+i]              // G[11]..G[21] = A[20]..A[30]
                                          // 三角 + 反转：对角 1，高位抽头 1
```

`G[21]` 存在于 8GiB 作业里（8GiB = 2^{33}B，`A[32]` 活）。矩阵在 GF(2) 上是 `I_rev + [0 | I]` 的 11×11，秩需要在模型里算一次；**这里不声称秩 11**。统计：8GiB 顺序窗口 `G` 跑 2^{24} 个块，2 幂轴 2048 点被扫多次。

装配：

```
DMC     = dmc_odd + 3 · p_mix[6:0]        // 384 = 3×128
bank_in = (r_hash mod 3) + 3 · p_mix[10:7]  // 48 = 3×16；r_hash∈0..8，mod 3 是 d0
die     = p_mix[6]
local   = dmc_odd + 3 · p_mix[5:0]
HA      = local / 2
pipe    = local % 2                            // 192 DMC/die，不是 DMC[8]
```

`r_hash` 的高 trit `d1` 不进 bank_in，避免和 `dmc_odd` 共享太多线性依赖。它参与 `dmc_odd` 的和。

### 2.3 容量 / 端口 / 位宽

| 结构 | 容量 | 位宽 | 端口 | 副本 |
| --- | --- | --- | --- | --- |
| TRIT_ROM ×8 | 8 项 × 2b，×8 = 128b | 3b→2b | 组合 LUT | ×120 |
| CSA_Z3 × ~8 | 每 CSA 27 项 LUT 或 ~20 GE | 2b×3 → 2b×2 | 组合 | ×120 |
| GF2_11 | 11 个 XOR2 | 11b+11b → 11b | 接线+XOR | ×120 |
| GOOD 掩码 | 384 × 48b | 48b | 1R 共享 | ×1 |
| select-k | 48 输入前缀 | 48b / 6b | 组合 1 份 | ×1 共享 |

树深度 4 级 CSA。每级 ~2b 加，总深度 ~8 级 2b 加，1 拍。

### 2.4 Partial-good

packed select-k，同 M-2 精神，禁止顺序跳。

```
k      = (r_hash mod 3) + 3 · p_mix[10:7]   // 已混合，0..47
mask   = GOOD[DMC]
N_good = popcount(mask)
i*     = min{ i | prefix_pop(mask, i) == (k mod N_good) + 1 }
```

`N_good | 3` 时**不要**再 mod 3。1/3 图案下 `N_good = 32`，再 mod 3 会把 trit 树的工作作废。select-k 用混合后的 `k`。

### 2.5 时序与因果

1 拍组合：CHUNK → 8 LUT 并行 → 4 级 CSA → GF2_11 并行（与树无关）→ 装配。partial-good 加 1 拍 SRAM+select-k。无状态。无 warmup。纯函数。已知量：当前 `A`。

## 3. 为什么有效

先点名翻转的块。`G += δ`。

**`δ = 3`（S = 1536B = 3·2^9）**
- 加数在 `G[1:0]` 为 `11b`。`C0 = G[2:0]` 每步被加 3。`gcd(3, 8) = 1`，`C0` 跑满 0..7，trit 满 `Z_3`。
- 进位进 `C1` 当 `C0 ≥ 5`。`C1` 间歇翻转。
- `C2..C7` 更慢。树的重量 1 输入至少 `C0` 活。

**`δ = 9`（S = 4608B = 9·2^9）**
- `9 = 8+1`：`G[0]` 与 `G[3]` 为 1。`C0` 被加 1（满 8 周期），`C1 = G[5:3]` 被加 1。**C0 与 C1 都活。**
- `r = G mod 9` 在整数意义上冻住（`9 | δ`），但 C0、C1 的 3b 模式不冻。这是本卡相对 `G mod 9` 的全部优势。

**`δ = 24`（S = 12KiB = 3·2^{12}，`δ_blocks = 24`）**
- `24 ≡ 0 (mod 8)`：`G[2:0]` 冻，**C0 冻**。
- `24 >> 3 = 3`：`C1 = G[5:3]` 被加 3，与 `δ = 3` 时的 C0 同构，`C1` 满跑。进位进 **C2**。
- 点名：此步长下活输入是 **C1（总是）、C2（进位）**。C0 死。树仍有变化输入。

**`δ = 3072 = 3·2^{10}`（S = 1.5MiB）**
- `G[9:0]` 冻：C0, C1, C2 冻（C2 到 G[8]），C3 = G[11:9] 被加 `3072[11:9] = 6`（`2^{10}+2^{11}`）。**C3 活**，进位进 C4。
- GF2_11 的 `G[11+i]` 抽头含 `G[11]..G[21]`，C3/C4/C5 区域，2-adic 也不死。

扩展器论点（机制级，不是谱间隙定理）：每个活块的 8→3 映射盖满 `Z_3`。CSA 是满射的 3:2 压缩（任意 3 输入，`s` 跑满 `Z_3` 当固定其它 2 个输入中至少一个自由——不总真：固定 b=c=0，a 跑 `Z_3` 则 s 满）。8 输入里只要 **1 个独立满跑的 trit**，`d0 = Σ mod 3` 满 `Z_3`。因此 `dmc_odd` 在上述四个 δ 上都有一个被点名的活块当熵源。这是 n_DMC 回到 384 的理由：DMC trit 不再等于 `G mod 3`，等于活 3b 块的非线性函数。

`dmc_odd = (d0+d1+d2) mod 3`。`d0` 满则和满，无论 `d1,d2` 是否冻。不依赖 `d2` 取到 2。

Amdahl：`X_rel = 3` 来自 384→128。活块把 trit 拉满则 ×3 占用回来。Little：15360/384=40 vs 120。1 拍树被 128 outstanding 盖住。roofline：带宽墙。

不平衡：ROM 直方图 3,3,2；`d2` 缺 2；8 块不是 expander 的正规定义（没有证明第二特征值）。期望 min/mean **0.9–1.0 若混合成立**，1/3 图案可再相关。不写假百分数。

**未证严：**（1）11×11 接线 `p_mix[i] = G[10−i] ⊕ G[11+i]` 在 GF(2) 上的秩未算，不声称双射。（2）“3 值扩展器”是结构类比，没有邻接谱。（3）多块同时被同一 AP 进位链相关，8 个 trit **不是独立**均匀；`dmc_odd` 满 `Z_3` 在单活块时成立，在多块相关时只是期望，不是定理。

## 4. 评估计划

- 基线: ModMapper %31, Mod192Mapper %192, Mod248Mapper %248, plus a power-of-two-only XOR mapper that is uniform on 2^k strides
- 指标: n_DMC, n_bank, min/mean R/W BW, X_rel, occupancy vs min(384,K)
- 负载: 8GiB shared, outstanding 128, S ∈ {512B, 1KiB, 1536B, 3KiB, 4608B, 12KiB, 1.5MiB, 2MiB} × sequential AP, plus bank partial-good 0%/6%/12% random and 1/3-patterned
- 必须 cycle 级建模的结构: 8 个 3b CHUNK、8×2 trit LUT（直方图 3,3,2）、深度 4 的 Z_3 CSA 树（3 trit→2 trit，保留进位权重）、`dmc_odd=(d0+d1+d2) mod 3`、`r_hash=d0+3·d1`、11×11 GF(2) 接线 `G[10−i]⊕G[11+i]`、GOOD 384×48 1R、48 输入 select-k。评估必须打印每个 S 下 C0..C7 的翻转计数，核对 δ=3→C0、δ=9→C0+C1、δ=24→C1+C2、δ=3072→C3。
- 预期收益与置信度: n_DMC ~128 → 384（×3）在点名块确实翻转且 LUT 满 `Z_3` 时；min/mean ~0.9–1.0。置信度 **中**：单活块 ⇒ `d0` 满是组合事实；多块进位相关和 1/3 图案是未知项。相对 M-1，本卡不依赖 `G mod 9` 预计算，树本身破坏 3-adic 赋值。

## 5. 硬件开销估算

- 逻辑：8 个 8:1 LUT（每份 ~10 GE）+ ~8 个 Z_3 CSA（每份 ~20 GE）+ 11 XOR ≈ **3×10^2–10^3 GE / 核**。7nm **~10^{-4}–10^{-3} mm² / 核**。×120：**~10^{-2}–10^{-1} mm²**。
- SRAM：共享 GOOD_MAP **~10^{-2} mm²**。无每核 ROM 表（8×2 是门）。
- 功耗：每核 **0.1–1 mW** @ 2 GHz。共享 SRAM **1–10 mW**。
- 延迟：**1 拍** 树（深度 4 CSA）+ **0/1 拍** SRAM/select-k。不是 0。
