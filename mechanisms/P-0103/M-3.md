# M-3: Stride-Locked Coset Transversal (SLCT) — 步长锁定陪集横截

- problem: P-0103
- author: Jim Keller
- id: P-0103/M-3

## 1. 根因分析

整数取模把 AP `G0 + ⟨δ⟩` 送进一个真子群。`3 | δ` 时 DMC 的因子 3 与这个子群同构，占用塌成 128。组合哈希（M-1 的 F，M-2 的立方）在 `p_wide` 仍跳时能扭剩余；当 `δ` 大到 `A[24:9]` 的熵也变薄（`S = 1.5MiB`，`δ = 3072`，16b 场只剩 64 个点），组合注入的像可能盖不满 `Z_3`。

本卡打的环：**已知步长之后，对塌缩陪集加一条横截**。横截是 `Z_9` 上的平移 `τ(S)` 加 `Z_128` 上的 DMC 组旋转 `ρ(S)`。`τ` 本身是常数，**不放大单点像**；覆盖来自横截把 `r(G0)+F(p)+τ` 对齐到 `Z_3` / `Z_9` 的完全剩余系，而 `p` 沿幸存 2-adic 子群跑。`S` 在 t=0 未知。禁止完美预测。每个核自己的 FSM，3 次匹配才 LOCK。未锁定流走 M-1 组合备份，不准退回整数取模。

## 2. 机制

### 2.1 结构

1. **STRIDE_FSM** ×120（每核一份，禁止全局预测器）。寄存器：`last_block[24:0]`，`stride[20:0]`（字节，覆盖 1B–2MiB），`lock_cnt[2:0]`，`state ∈ {UNLOCK, CAND, LOCK}`。
2. **KEY_ENC**：把 `|S|` 量化成 8b 键。
3. **TAU_RHO_ROM**：256 项 × 8b。输出 `τ[3:0]`（0..8 合法，9–15 视为 `τ mod 9`）和 `ρ[3:0]`（16 档，实际旋转 `ρ<<3` 落在 `Z_128`）。
4. **MRFI_FB**：完整复制 M-1 组合路径（SPLIT / WIDE / F_BOX / FEISTEL / CRT）。UNLOCK/CAND 只用它。LOCK 也以它为底，再加 `τ, ρ`。
5. **GOOD_MAP + XOR 重试**：与 M-1 相同。384×48b，1R 共享。

### 2.2 数据路径

块地址 `G = A[63:9]`。每核独立。

FSM：

```
δ_obs = (G − last_block) as 21b signed-to-abs 的字节步长
        // 存 stride 用字节：δ_bytes = (G − last) << 9，钳到 21b
case state:
  UNLOCK:
    发行 = MRFI(A)
    if δ_obs != 0:
      stride ← δ_obs; lock_cnt ← 1; state ← CAND
  CAND:
    发行 = MRFI(A)
    if δ_obs == stride and δ_obs != 0:
      lock_cnt ← lock_cnt + 1
      if lock_cnt == 3: state ← LOCK
    else if δ_obs != 0:
      stride ← δ_obs; lock_cnt ← 1          // 重新候选
    // δ_obs==0：同块重复，忽略
  LOCK:
    if δ_obs == stride or δ_obs == 0:
      发行 = MRFI_plus(A, τ, ρ)              // 见下
    else:
      state ← UNLOCK; lock_cnt ← 0; 发行 = MRFI(A)
last_block ← G
```

3 次匹配：第 1 个非零 Δ 进 CAND，再连续 2 个相同非零 Δ 才 LOCK。前 3 拍请求（UNLOCK/CAND）走 MRFI，可能仍塌。128 outstanding 把这 3 拍藏进窗口的 `3/128 ≈ 2%`。

8b 键：

```
v2     = ctz(|S|)                         // 2-adic 赋值，0..21
odd    = |S| >> v2                        // 奇数核
logb   = clamp(floor(log2(|S|)), 0, 31)  // 5b，1B..2MiB
key[7:3] = logb
key[2:1] = odd[2:1]                       // 奇数核的 2b，不是 LSB（LSB 恒 1）
key[0]   = (odd % 3 == 0) ? 1 : 0         // 3 | odd？即 3 | S
```

`3 | stride_blocks` 当且仅当 `3 | (S/512)`。`512 = 2^9`，故 `3 | S` 等价于 `3 | stride_blocks`。`key[0]` 就是这张卡的使能位。

ROM 256×8：

```
{τ[3:0], ρ[3:0]} = ROM256x8[key]
τ_use = (key[0] == 1 and state == LOCK) ? (τ % 9) : 0
ρ_use = (key[0] == 1 and state == LOCK) ? (ρ << 3) : 0     // 0,8,16,...,120
```

MRFI 底（与 M-1 同一方程，必须复制，不许写成“调用哈希”）：

```
p_wide = A[24:9]
idx4   = ⊕ of four 4b nibbles of p_wide
F      = ROM16x4[idx4]                    // 直方图 0..6 各 2 次，7、8 各 1 次
r      = G mod 9
r_feis = (r + F) mod 9
p      = G[10:0]
```

LOCK 且 `3 | S` 时加横截：

```
r'     = (r_feis + τ_use) mod 9
p'     = p
idx    = p' + 2048 · ((2 · (r' − p' mod 9)) mod 9)
DMC0   = idx / 48
bank   = idx % 48
u      = DMC0 / 3                         // 128 个 2-adic DMC 组
t      = DMC0 % 3                         // 已混合的 trit
u'     = (u + ρ_use) mod 128
DMC    = t + 3 · u'
u_dmc = DMC / 3; die = u_dmc[6]; local = (DMC % 3) + 3·u_dmc[5:0]; HA = local/2; pipe = local%2
        // 192 DMC/die。ρ 加在 u 上之后再拆，die 位是旋转后的 u'[6]
```

横截在干什么。塌缩像是 `G0 + ⟨δ⟩`。`r(G)` 在 `9 | δ` 时等于常数 `r(G0)`；在 `3 | δ` 但 `9 ∤ δ` 时跑 3 点陪集。`p` 沿幸存 2-adic 子群 `G0 + ⟨δ⟩` 投影到 `Z_{2048}`。`F(p_wide)` 沿这条轨道给出一个像集 `Im_F`。

选 `τ` 使得 `{ r(G0) + f + τ | f ∈ Im_F }`：

- 若 `|Im_F| = 9`，集合已是 `Z_9` 的完全剩余系，`τ` 只做相位，让直方图对齐 ROM 量化槽，避免 16 档 `ρ` 与 `F` 的拍频叠峰。
- 若 `|Im_F| = 3` 且 `Im_F` 已是 `Z_3` 的完全剩余系（三个不同 `mod 3`），`τ` 把它们搬到指定的 DMC trit 相位；`ρ` 把 128 组转开，打散 2 幂热点。
- 若 `|Im_F| = 1`（`p_wide` 也冻），`τ` 是常数平移，**像仍是 1 点**。ROM 救不了单点。此时 n_DMC 仍塌。8GiB / 1.5MiB ≈ 5461 步，`p_wide` 以 3072 步进，64 点，不是单点。2MiB 步长 `δ = 4096 = 2^{12}`，无因子 3，`key[0]=0`，横截关闭，走纯 MRFI。

ROM 内容（机制约定，不是运行时学习）：对每个 `key`，预计算该量化槽代表步长 `S_rep = 2^{logb} · (1 + 2·key[2:1])`，取 `S_rep` 最近的 `3·2^k` 或 `9·2^k`。令 `Im_F` 为 `p_wide` 沿该 AP 走 256 步的 F 像。选 `τ ∈ 0..8` 最大化 `|{(r0+f+τ) mod 3}|`，并列时最大化 `|{(r0+f+τ) mod 9}|`。`ρ` 选使 128 组访问的 min/mean 最大的 4b 档。离线算死，运行只查表。

### 2.3 容量 / 端口 / 位宽

| 结构 | 容量 | 位宽 | 端口 | 副本 |
| --- | --- | --- | --- | --- |
| STRIDE_FSM | 25+21+3+2 ≈ 51b 状态 | 见字段 | 每核 1 套，每请求 1 读 1 写 | ×120 |
| KEY_ENC | 组合 ctz + 5b 优先编码 | 21b → 8b | 组合 | ×120 |
| TAU_RHO_ROM | 256 项 | 8b | 1R | ×120（256B，可做 LUT）或 ×1 共享 1R |
| MRFI_FB | 同 M-1 | 同 M-1 | 组合 | ×120 |
| GOOD_MAP | 384 × 48b | 48b | 1R 共享 | ×1 |

120 × 256B = 30 kB 若每核一份 ROM，7nm 可接受。共享 256×8 的 1R 会把 LOCK 路径串成 1 查询/周期，不配 120 核。**每核一份 256×8 LUT。**

### 2.4 Partial-good

与 M-1 相同：`mask = GOOD_MAP[DMC]`，`bank ⊕= live5` 最多两次，`mod 48` 折回。禁止 `+1`。DMC 在 `ρ` 旋转之后冻结，重试不改 DMC。`live5 = p_wide[4:0]`。

### 2.5 时序与因果

- t=0：state=UNLOCK，`S` 未知。第 1 个请求走 MRFI。无完美知识。
- 连续 3 个匹配非零 Δ 之后进入 LOCK。warmup = 3 请求。因果合法：只看已经发生的 `G` 差分。
- LOCK 路径：拍 0 组合 MRFI+τ+ρ；拍 1 GOOD_MAP。仍是 1–2 拍。
- 失配立即 UNLOCK。无滞后消费过期 `τ`（失配当拍就切 MRFI）。
- FSM 写 `last_block` 在发行当拍。不存在用未来 `S` 的组合环。
- 模型必须实现 120 个独立 FSM。全局一个预测器是错误模型。

## 3. 为什么有效

子群像：整数取模下 `|im| = N / gcd(δ, N)`。`3 | δ` ⇒ `gcd(δ, 384) ≥ 3` ⇒ 像最多 128 个 DMC。MRFI 已用 `F(p_wide)` 把奇数坐标拉出子群。SLCT 在 LOCK 后加一条**明确依赖 `S` 的横截**，目标是让 `{r(G0)+F(p)+τ}` 成为 `Z_3` 的完全剩余系（DMC）和尽可能成为 `Z_9` 的完全剩余系（bank）。

为什么 `τ` 能对齐而不能放大：平移是 `Z_9` 的自同构。它把已有像集搬到另一个位置。盖满 `Z_3` 的充要条件是 `Im_F` 自己已经命中 3 个不同的 `mod 3` 类；`τ` 只选相位。这是横截，不是扩域。ROM 的工作是在 256 个量化槽里把相位选对，避免 `F` 的像和 128 组的 2 幂拍频共振。

Amdahl：`X_rel = 3` 来自 384→128。LOCK 后若 `Im_F` 盖 3 个 trit，n_DMC 回 384，这项变 1。UNLOCK 的 3 拍仍可能 ×3；Little：15360 outstanding，3 拍 / 128 槽 ≈ 2% 的窗口。稳态被 98% 的 LOCK 流主导。roofline 仍是带宽墙，2 拍 mapper 被 outstanding 盖住。

`S = 512B / 1KiB`（纯 2 幂）：`key[0]=0`，横截关闭，退化为 MRFI，不破坏 2 幂均匀性。`S = 1536B / 3KiB / 1.5MiB`：`key[0]=1`，横截开。`S = 4608B`：`9 | S`，`r` 冻，覆盖全靠 `F`+`τ`。

min/mean：LOCK 稳态若 trit 满 3 类，期望 0.9–1.0。前 3 拍塌缩会在 min 上留尖刺；128 outstanding 把尖刺摊掉。1/3 图案 fusedown 仍能再相关。

**未证严：** ROM 对每个 8b 槽选出的 `τ` 使 `Im_F+τ` 盖满 `Z_3`——这依赖离线对代表步长的 256 步采样，不是定理。量化把连续 `S` 收成 256 桶，相邻 `3·2^k` 可能共享槽而 `Im_F` 不同。若某槽 `|Im_F mod 3| < 3`，该槽 LOCK 后仍缺一类 DMC。不把 ROM 内容写成已证双射。

## 4. 评估计划

- 基线: ModMapper %31, Mod192Mapper %192, Mod248Mapper %248, plus a power-of-two-only XOR mapper that is uniform on 2^k strides
- 指标: n_DMC, n_bank, min/mean R/W BW, X_rel, occupancy vs min(384,K)
- 负载: 8GiB shared, outstanding 128, S ∈ {512B, 1KiB, 1536B, 3KiB, 4608B, 12KiB, 1.5MiB, 2MiB} × sequential AP, plus bank partial-good 0%/6%/12% random and 1/3-patterned
- 必须 cycle 级建模的结构: 120 份 STRIDE_FSM（UNLOCK/CAND/LOCK，3 次匹配，失配解锁）、KEY_ENC、256×8 TAU_RHO_ROM、完整 MRFI 备份数据路径（含 ROM16x4 与 CRT）、ρ 对 128 组的旋转、GOOD_MAP 1R、XOR 重试。warmup 的前 3 请求必须进 n_DMC 统计，禁止假定 t=0 已知 S。
- 预期收益与置信度: LOCK 稳态 `S = 3·2^k` 上 n_DMC ~128 → 384（×3）；min/mean ~0.9–1.0。区间。置信度 **中**：Little 藏 warmup 是硬的；ROM 量化与 1/3 图案是软的。相对纯 MRFI，本卡只在大步长 `Im_F` 变瘦时多出横截；小步长两者应接近。

## 5. 硬件开销估算

- FSM：每核 ~50b 寄存器 + ~2×10^2 GE 比较。×120：6 kb 状态，可忽略面积。
- TAU_RHO_ROM：每核 256×8 = 256B。×120 = 30 kB。7nm SRAM/RF **~10^{-2} mm²** 量级。或 256B 做组合 LUT，每核 **~10^{-4} mm²**，×120 **~10^{-2} mm²**。
- MRFI 逻辑：同 M-1，×120，**~10^{-2}–10^{-1} mm²**。
- GOOD_MAP 共享 **~10^{-2} mm²**。
- 功耗：每核 FSM+LUT **0.1–1 mW**，MRFI **0.1–1 mW**。共享 SRAM **1–10 mW**。
- 延迟：UNLOCK/LOCK 都是 **1 拍组合 + 0/1 拍 SRAM**。FSM 状态更新不在关键组合链上（用上一拍 state）。
