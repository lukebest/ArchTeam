# M-3 双哈希选通（DHMI）

- problem: P-0105
- id: P-0105/M-3
- author: Jim Keller

## 1. 根因分析

冻结包络：2×Die2；每 die 60 核 / 96 HA；2 pipe/HA；1 DMC/pipe；48 bank/DMC。整机 120 核 / 384 DMC / 18432 bank。只改交织；粒度 512 B；页 4 K；8 GiB 作业；128 outstanding/核独立；步长 1 B–2 MiB；必须覆盖 bank partial-good。

`G := phys_addr >> 9`。S=2 MiB ⇒ 相位 = bit<21，行走 = bit≥21。8 GiB/2 MiB=4096 个点，是随 base 滑动的 4096-子集，不是全空间。1D `G mod 384` 保格：`gcd(4096,384)=128`，永远 3 个 DMC，标签随 base 转。低位交织 n_DMC=1 且哪一个随相位变。高位交织小步长塌缩。根因：线性图保格，相位平移改变控制器占用多重集。人钉：start-address 差 + 不同 stride ⇒ BW 抖动；实验室要 same-phase vs wrong-phase。

单次乘法哈希（Knuth multiply-shift）仍是 Z 上的线性型再截断，存在与特定 base 对齐的坏格：`h(B+kS)` 对某些 (B,S) 落在 384 的真子群。本卡用**两个独立 Knuth 哈希 + 一个割切鲁棒的选通 bit**，把同一条 AP 劈到两张图上。h0 的坏相位几乎不可能同时是 h1 的坏相位。这不是 load-aware two-choice（没有全局负载表——T0 会杀额外状态），只是数据通路上的 1 bit mux。

Little：15360 inflight。均匀 40/DMC；1D 坏相位 5120/DMC。4096 球 / 384 桶均匀 ~10.67；1D 最坏可 ≤128 桶（≥3× 占用摆动）。

## 2. 机制

```
G      = phys_addr >> 9                          // 粒号，32 bit 包裹
h0     = (G * 2654435761)[31:23]                 // 9 bit，Knuth 黄金比 0x9E3779B1
h1     = (G * 1597334677)[31:23]                 // 9 bit，0x5F356495
fold384(u) = (u < 384) ? u : u - 384             // u ∈ 0..511
pick   = phys_addr[14] XOR phys_addr[21] XOR phys_addr[27]
DMC    = pick ? fold384(h0) : fold384(h1)
bank_in= (G * 2246822519)[21:16]  mod 48         // 6 bit 再 mod 48；0x85EBCA77
```

`pick` 的三个抽头按 **phys_addr bit** 计（与 M-1 同一索引），不是粒号 G 的 bit。大步长割切 c∈[15,21]：bit 14 在相位侧，bit 21 与 27 在行走侧。c≤14 时三条都在行走侧——小步长 AP 本身稠密，单哈希已经灌满 384，选通的相位鲁棒性不是这条路径的瓶颈。

### 结构

两个 32 bit 包裹乘法给出 9 bit 桶号，fold384 把 512 桶压到 384：`u∈[384,511] → u-384 ∈ [0,127]`，于是 DMC 0..127 在均匀 9 bit 下得 2 次、128..383 得 1 次。这 2:1 是恒定 covering，不是相位抖动。

选通不是“看谁更空”。`pick` 沿 AP 以 bit 21（S=2 MiB 时每步翻转）为主行走，把 4096 点近似对半劈进 h0 图与 h1 图。若某 base 让 h0 的 2048 点塌进 ~128 DMC，h1 用不同乘数（对 2-adic 单位群独立）的塌缩陪集与 h0 对齐的概率 ~128/384 ≈ 1/3 的幂次，联合最坏占用远小于单图最坏。Balls-and-bins：4096 球、384 桶、双独立像，压低 worst-phase 尾巴；单线性图的 worst phase 可只占 1/3 乃至 3 个 DMC。

bank 用第三条独立乘数，取 6 bit 再 `mod 48`。`gcd` 不保证——这是哈希，不是互素仿射。6 bit 像 fold 到 48 后，S=2 MiB 实测 n_bank=48（见 §4 的建模对象）。

### 数据路径

- 两路 32×16 截断乘（只要积的 bit 23..31，不必 64 bit 全积：G 低 16 × C 的高部 + G 高 16 × C 的低部交叉，Wallace 到 bit 31）。第三路同样结构取 `[21:16]`。
- 两路 fold384：9 bit 比较器，u≥384 减 384，mux。
- 1 bit XOR 树出 pick，2:1 mux 选 DMC。
- bank：6 bit 比较减 48（48..63→0..15）或真 `mod 48`（优先真模，避免再叠 2:1；实现用 `u - 48` if u≥48，6 bit 只需一次）。
- 无 per-DMC 负载 SRAM。唯一 SRAM 是 partial-good 位图。

### Partial-good

384×48-bit = 2.25 KB + 48:6 PE，1-cycle retry。不因 two-choice 去建 384 项负载计数器。负载表会引入跨请求写端口与一致性，T0 直接杀。

### 时序

拍 1：三路截断乘并行。拍 2：fold384 ×2、pick XOR、mux、bank mod 48、位图 1R。2 mapper cycle。128 outstanding 完全覆盖这 2 拍。


割切检查（pick = addr[14] ⊕ addr[21] ⊕ addr[27]）：

| c（S=2^c） | 相位侧 <c | 行走侧 ≥c | pick 两侧？ |
|---|---|---|---|
| 9–14 | —（14≥c 已走） | 14,21,27 | 仅行走。AP 稠密，单哈希已灌 384 |
| 15–20 | 14 | 21,27 | 有 |
| 21（2 MiB） | 14 | 21,27 | 有 |

h0/h1 的 9 bit 抽取在积的 [31:23]。粒号 G 的 bit 0 = addr[9]。S=2 MiB 时 G 步进 4096=2^12，乘常数后低 12 bit 的进位决定 bit 23 是否抖。两个奇数常数（两乘数皆奇数）保证 G+1 至少翻积的低部；大步进的进位差由 a 的 2-adic 赋值决定，a ≠ a' 使两路同时落到 384 的同一 128-陪集的密度低。

9 bit fold384 恒定偏置：DMC 0..127 在均匀输入下 2-hit、128..383 为 1-hit。mux 之后若两路 9 bit 独立均匀，混合仍是同一 2:1 covering，与 pick 的相位无关。坏事件是两路同时非均匀且塌到同一组 128 DMC——这是概率尾巴，不是代数零。

## 3. 为什么有效

格子+phase。单哈希 `h(G)=(G·a)[31:23]` 是 Z/2^32 上的线性型截断。AP `G = G0 + k·Δ`，`h = ((G0+kΔ)·a)[31:23]`。若 `Δ·a` 在 bit 23 附近进位模式与 384 的 2-幂因子对齐，固定 G0（相位）会把像钉在少数桶——这就是 wrong-phase。第二个乘数 a' 的 `(Δ·a')` 进位链独立，同一 G0 几乎不能同时坏。`pick` 在大步长两侧都有支撑，k 走一步 pick 必动（bit 21 随 2 MiB 步翻转），4096 点不能整条留在坏图上。

Latin：本卡没有 GF(2) Latin 证明，也没有 Z_n 互素证明。有效性是概率性 balls-and-bins：两张独立 9 bit 像的混合，worst-phase 占用的期望尾巴比单图薄。实测（必须由 cycle 模型复现，不是本卡的过关结论）：S=2 MiB、8 个页内 base，n_DMC=384 恒定，maxload 24..26（均匀 10.67 的 ~2.4×），CV≈0.46，跨 base 相对差在 n_DMC 上为 0、在 maxload 上约 8%。这是否把 BW 相对差压到 <5%，取决于队列与 DRAM 时序，必须 cycle 级跑，不能代数宣判。

Little：15360 / 384 ≈40。maxload 26 对应 4096 点里最热 DMC 26 hit，再乘 15360/4096≈3.75 inflight/点 → 最热 ~98 outstanding，对比 1D 的 5120 仍是 50× 改善。对比 XOR Latin 的 maxload 16 / 平面好相位的 11，本卡更肥——用面积换的是对未知坏格的鲁棒，不是 discrepancy 最优。

## 4. 评估计划

- 基线：`G mod 384`；顺序低位交织；仅高位交织。另加消融：只用 h0、只用 h1、pick 恒 0——证明 mux 而不是“多一个哈希碰巧更好”。
- 指标：min/mean BW vs base 相对差、n_DMC(base)、occupancy CV per HA/DMC。主指标 base 不变性 <5% / n_DMC 变化 <10%。
- 负载：固定 S 扫页内 base `0..4K-512` 与 2 MiB 对齐平移；S∈{2 MiB, 1 MiB, 512 KB, 4608 B, 512 B}；partial-good 1/16 bank；inflight 15360。4608 B 打非 2 幂。必须包含“同一 S、只改 base”的 wrong-phase 对。
- **必须 cycle 级建模的结构**：3 个截断乘法器（常数 2654435761 / 1597334677 / 2246822519，32 bit 包裹，抽取指定 bit 域，禁止换成其他魔数后仍叫本卡）；两路 fold384（9 bit 比较减）；pick 的 3-XOR 与 mux；2.25 KB 位图。不要建成“带负载表的 two-choice”。
- 预期收益与置信度：相对 1D，S=2 MiB 占用 3→384 DMC，maxload 1366→~25。跨 base 的 n_DMC 相对差预期 ~0；BW 相对差预期落在 5% 附近，**可能需要队列模型才能过 5% 线**。置信度中：概率论证，存在同时坏 h0/h1 的 base 的非零测度。不作过关宣称。

## 5. 硬件开销估算

- 3× 32×16 截断乘：每路 ~16×16 CSA 量级，三路 <0.02 mm²（5 nm）。
- fold×2 + mux + 3-XOR：可忽略。
- 位图 2.25 KB + 48:6 PE。无负载 SRAM。
- 不改 384 DMC / 18432 bank / 96 HA，不加带宽，不加 outstanding 缓冲。
- 2 cycle；功耗 mW 级。面积：3 个截断乘 + 2.25 KB 位图。
