# M-3: 每 DMC 活 bank 列表译码 LUT

- problem: P-0106
- author: 保守架构师
- style: conservative / implementable

## 1. 根因分析

固件在测试/修复时已经知道 repair map。与其每请求现场 popcount（M-1/M-2），不如把「第 i 个活槽 → 物理 bank」做成 **列修复风格 LUT**——DRAM 工厂列修表的同族结构，保守、可扫描、可对照 BIST 日志。

约束仍是：不跨 DMC；映射在活集上可逆；不能打到退役 bank。本卡是显式 SRAM 列表，与 M-2 的组合 kth-one 成对、可独立评估。

## 2. 机制

### 结构

每 DMC 一张 48 项 × 6b LUT：`L[i] =` 第 i 个活物理 bank，`i∈[0, n_live)`。`i≥n_live` 的项写 `6'h3F`（非法哨兵），译码若落到哨兵则错误路径。

- `n_live` 6b CSR ×384。
- 索引：`slot = H(G) mod n_live`，`H` 为 6-bit XOR fold（`H=G[5:0] ⊕ G[11:6] ⊕ G[17:12] ⊕ {0,0,G[23:18]}` 的低 6）。
- `bank = L[slot]`。
- 上游只选 DMC；LUT 不改变 DMC。

工厂编程：BIST 列出活 bank 升序（或按物理测试序）填 `L[0..n_live-1]`。与列修 LUT 一样，启动写一次，运行 1R。

### 容量 / 端口 / 位宽

| 结构 | 容量 | 端口 | 位宽 |
|------|------|------|------|
| live_list SRAM | 384×48×6b = 110592b ≈13.5KB | 译码 **1R**；repair **1W** | addr = 9b DMC + 6b slot / data 6b |
| n_live CSR | 384×6b = 2304b | 1R 译码 / 1W repair | 6b |
| XOR fold H | 0 | 组合 | in 24b G / out 6b |
| `mod n_live` | 0 | 1 cycle | 6b ÷ 6b |

13.5KB 可做成 384 银行 × 48×6 或单阵列 18432×6b。1R 在地址译码。不要 2R。不要 CAM。

### 数据路径与状态机

无运行时 FSM。每请求：

1. 上游 `dmc`。
2. `h = XOR_fold6(G)`，1R `n = n_live[dmc]`。
3. `slot = h % n`（1 cycle；可与 n 的 1R 同拍若 n 用 flop）。
4. 1R：`bank = LUT[{dmc,slot}]`。
5. 若 `bank>47` 或（可选）旁路 mask 检查失败 → ERROR。

repair 态：扫描器写 LUT 与 `n_live`，fence 后回 RUN。

**逆**：物理 bank → 在该 DMC 的 `L` 里找唯一 `slot`（离线可建 48×6 逆表；硬件不需要逆，除非做一致性检查）。`h ≡ slot (mod n)` 给出规范原像。活集双射：`L[0..n)` 必须是 `{0..47}` 的无重复子集。

## 3. 为什么有效

`L` 是 `Z_n → L_set` 的显式双射（编程约束：无重复、无死 bank）。`H(G) mod n` 把地址均匀（就 XOR fold 的能力而言）洒在 slot 上。死命中 0，因为死 bank 根本不在 `L[0..n)`。

对比 M-1 前缀树：功能等价（若 `L` 按物理编号升序填，就是 kth-one 的固化）。差别是面积换延迟确定性：SRAM 1R 时序闭包比 48b 前缀树更常规，且固件可打乱 `L` 顺序做 3-adic 规避（把物理 bank 的 3 残类打散到连续 slot）——升序填则与 M-1 相同。

Little：同 M-1，`λ_d ≤ n·μ_b`。面积账见 §5，是本卡相对 popcount 树的主要代价。

## 4. 评估计划

### 基线

M-1 popcount；无 live-set 库 mapper；LUT 故意含死 bank 的负例（应被哨兵抓住）。

### 必须 cycle 级建模的结构

- 13.5KB LUT：1R 译码、1W repair，地址 `{dmc,slot}`。
- 384×6b `n_live`。
- 6b XOR fold 与 `mod n`。
- 哨兵/ERROR。
- 编程时间（填 384×48 的 cycle）。

### 指标与负载

同 M-1：0/6.25/12.5/25%，均匀与 clustered；死命中=0；可逆；min/mean vs 0.85。另报：相对 M-1 前缀树的面积与译码周期。编程代价：`384×n_avg` 次写，25% 退役约 384×36=13824 写，若 1 写/cycle ≈ 14k cycle @boot，可接受。

### 预期收益区间与置信度

功能与 M-1 对齐（升序填时占用曲线应重合，置信高）。打乱 `L` 可能改善 3-adic，BW `+0～15%`，置信低。不宣称 T0 通过。

## 5. 硬件开销估算

面积：13.5KB SRAM 1R1W，约 `0.01mm²` 量级 @7nm（或 flop 110592×6GE≈660kGE，不推荐 flop）。CSR 2304b 用 flop。对比 M-1：多约 11KB 列表，少去每请求前缀树（若 M-1 用共享树则树本身不贵，本卡贵在表）。功耗：1R 6b，`<0.2mW` 动态。延迟：1 cycle SRAM + 1 cycle `mod n`，共 1–2 cycle。
