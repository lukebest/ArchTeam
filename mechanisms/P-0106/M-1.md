# M-1: 每 DMC 48-bit live mask + popcount 压缩

- problem: P-0106
- author: 保守架构师
- style: conservative / implementable

## 1. 根因分析

活桶 `N'<18432`。退役 6.25/12.5/25% 时 `N'≈17280/16128/13824`。约束：**不能跨 DMC 借 bank**。全局 18432 项 remap 是错误粒度，且会把地址送到别的 DMC。

只禁桶不重映射：死桶原像叠到活邻居，额外失衡。本卡在 **每个 DMC 内部** 用 48-bit live mask 做前缀 popcount 压缩：地址算出的 DMC 不变，bank-in-DMC 只落到该 DMC 的活槽。`n_live` 可按 DMC 不同；局部 `s_crit = W_dmc / n_live`，`W_dmc = 8GiB/384 = 2^33/384 ≈ 21.33MiB`。

禁止 `core_id` 进 map。本卡保证死 bank 命中率 = 0，并在活集上可逆。

## 2. 机制

### 结构

1. **384 份 48-bit live mask** `M_d[47:0]`：bit=1 表示该物理 bank 可服务。总量 `384×48=18432b=2304B=2.25KB`。
2. **上游 interleave**（任意现有 mapper）只负责选出 `dmc∈[0,384)` 与一个原始 `r0∈[0,48)`。本卡不规定上游，评估可用 XOR fold：`dmc = G[8:0] % 384` 的结构化切开，`r0 = G[13:9] ⊕ G[18:14]` 再 `%48`。
3. **压缩**：`n_live = popcount(M_d)`。`r = r0 % n_live`（`n_live=0` 为配置非法，走错误路径）。`bank = kth_one(M_d, r)`：第 `r` 个置位（0-based）的位置。实现为 48 位前缀 popcount：`pref[i]=popcount(M_d[i:0])`，`bank = min{i: pref[i]=r+1}`。
4. 地址永不离开该 DMC。无 18432 项全局表。

负对照「有 mask 无压缩」：`bank=r0`，若 `M_d[r0]=0` 则改送到最近活邻居——这就是 stacking，评估必须包含。

### 容量 / 端口 / 位宽

| 结构 | 容量 | 端口 | 位宽 |
|------|------|------|------|
| live mask | 384×48b = 2.25KB | 译码 **1R**；repair 1W | addr 9b（DMC）/ data 48b |
| n_live | 可存 384×6b，或读 mask 时现场 popcount | 1R 或组合 | 6b（0..48） |
| 前缀 popcount 网 | 每 DMC 一套组合逻辑（不存表） | 译码 1 次 | 48b 入 / 6b 出（bank） |
| `% n_live` | 6b×6b 余数 | 1 cycle | `r0` 6b，`n_live` 6b |

mask 建议 flop file 或 384×48 SRAM 1R1W。前缀网：6 级加法树（48→24→12→6→3→2→1）现场算 48 个前缀，1 cycle。不要 48-iter 扫描。

### 数据路径与状态机

无运行时 FSM（repair 时写 mask）。每请求：

1. 上游给出 `(dmc, r0)`。
2. 1R：`M = MASK[dmc]`（48b）。
3. `n = popcount(M)`（并行树，与步骤 4 可叠）。
4. `r = r0 % n`（6b 比较减法循环最多 1 次：`r0<48`、`n≤48`，`r0-n` 一次即可若 `r0≥n`，最坏 `r0=47,n=25` 需一次；若 `r0≥2n` 再减。实现用 6b 整数余数，1 cycle）。
5. 前缀树：`bank = kth_one(M,r)`。
6. 发出 `(dmc, bank)`。断言 `M[bank]=1`。

repair：扫描/BIST 写 mask，须 fence（无飞行请求）。`n_live` 变化后 `% n` 的定义跟着变，飞行中改 mask 禁止。

## 3. 为什么有效

令 `L_d = {i: M_d[i]=1}`，`|L_d|=n_d`。映射 `ψ: Z_{n_d} → L_d`，`ψ(r)=kth_one` 是双射。`r = r0 mod n_d` 把上游 48 槽均匀压到 `n_d` 活槽（均匀程度取决于 `r0` 的分布）。逆：`r = rank(bank) = popcount(M_d[bank-1:0])`，再求满足 `r0 ≡ r (mod n_d)` 的规范 `r0`（例如 `r0=r`）。故在活集上可逆。

死命中：像只落在 `L_d`，命中率 0。

对比 stacking：死槽原像并到 `r0±1`，热度按退役图案叠加。压缩后每个活槽的原像大小是 `⌊48/n⌋` 或 `⌈48/n⌉`（若 `r0` 均匀），不再把死槽整块叠到一个邻居。

局部临界步长：`s_crit,d = W_dmc/n_d ≈ 21.33MiB / n_d`。`n_d=48` 时 455.11KiB（与全局相同）；`n_d=36`（25% 退役且均匀）时 ≈607KiB。占用账必须用 `n_d` 不是 18432。

Little：每 DMC 活 bank 减少，`λ_d ≤ n_d·μ_b` 且 `≤ μ_d`。25% 均匀退役，bank 维剩 75%，若原已是 DMC 界则 BW 几乎不掉；若原是 bank 界，预期掉到 ~0.75。min/mean vs 0.85 是评估尺子。

## 4. 评估计划

### 基线

满好（mask 全 1）；「只禁不压」stacking；无 live-set 的 OriginalMapper/ModMapper/IPoly（会打到死桶）。

### 必须 cycle 级建模的结构

- 384×48b mask，译码 1R。
- 48b popcount 与前缀 kth-one（1 cycle 树）。
- 6b `r0 % n_live`。
- 断言 `M[bank]=1`。
- 退役图案：均匀，以及 clustered-in-DMC（某些 DMC `n_live` 很低）。

### 指标与负载

退役率 0/6.25/12.5/25%。死 bank 命中率必须 =0。活集可逆：decode 再 encode 回规范 `r`。min/mean BW vs 0.85。负对照 stacking 的 BW 与最大 bank 热度。stride 含 2 幂与含 3 因子（为 M-5 对照留下缺口，本卡不重绑 α）。

### 预期收益区间与置信度

死命中 0（功能，高置信）。均匀 25%：min/mean 相对满好 `0.70～0.95`（DMC 界时靠近 1）。clustered：最坏 DMC 的 `n_live` 决定短板，BW 可能 <0.85——这是诚实区间，不是宣称一定过线。不宣称 T0 通过。

## 5. 硬件开销估算

面积：2.25KB mask flop ≈ `18432×6GE≈110kGE`，或 2.25KB SRAM（约 0.002mm² @7nm）更合理；前缀树每实例约 `0.5kGE`，若 384 份全展开太大，应 **1 份共享树 + mask 1R**（推荐）：树 `~0.5kGE` + 2.25KB 1R。功耗：每请求 48b 读 + 树，`0.2～0.5mW`。延迟：1R + 1 cycle 树，总共 1–2 cycle 译码。
