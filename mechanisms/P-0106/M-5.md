# M-5: 修复时重绑定 XOR/仿射参数

- problem: P-0106
- author: 保守架构师
- style: conservative / implementable

## 1. 根因分析

丢掉 N 或 48 的奇数因子会改变 `gcd(S_g, n_live)`，3-adic 必撞集合变，并行度一起掉。只在满好多项式上盖一层 mask **不够**：多项式必须按该 DMC 的 `n_live` 重绑。

例：满好 `bank ≡ G (mod 48)`，`48=16×3`，`S_g=2^k`（k≥4）时 `gcd=16`，每 DMC 只有 3 个碰撞类。退役后 `n=40=8×5`（丢掉 3），若仍 `mod 48` 再跳死槽，碰撞类仍按 48 的 3-adic 走。应改成 `mod 40` 且 `α` 与 40 互素，`gcd(α·2^k,40)=8`，类数 5。

本卡新结构是 **每 DMC 仿射三元组 `(α,β,n_live)`**。live 译码用 mask 的 48 线 kth-one（复用 M-1 风格，不依赖 M-3 SRAM），以保持独立可评估。禁止跨 DMC。禁止 `core_id`。

## 2. 机制

### 结构

repair 时对每个 DMC：

1. 由 live mask 得 `n = popcount(M)`。
2. 选 `α ∈ (Z/nZ)*`，即 `gcd(α,n)=1`，`α∈[1,47]`。策略：在文档步长集 `{512B, 3×512B, 9×512B, 512KiB, 1MiB, 2MiB}` 上最小化 `gcd(α·S_g, n)` 的最大值（优先保证 2 幂大步长，其次含因子 3 的 `S_g`）。`n` 丢掉 3 时，选 `α % 3 ≠ 0` 且与 `n` 互素（自动满足）。
3. `β`：默认 0；可选 `β = dmc[5:0]` 做 DMC 间错位，避免同 slot 对齐。
4. 存储 `(α,β,n)`。运行：`slot = (α·g + β) mod n`，`g=XOR_fold6(G)`，`bank = kth_one(M, slot)`。

与 M-2 的关系：M-2 定义了「α 互素 + kth-one」这条路径；本卡评估焦点是 **repair 时按 n_live 与 3-adic 文档步长重算 α**，并给出 gcd 表。结构上多出的是固件/硬件的 **rebind 计算与 CSR 布局**，译码器本身是 6b×6b 仿射。

### 容量 / 端口 / 位宽

| 结构 | 容量 | 端口 | 位宽 |
|------|------|------|------|
| 仿射 CSR | 384×(6b α + 6b β + 6b n) = 6912b = 864B | repair 1W / 译码 1R | 各 6b |
| live mask（复用 M-1） | 384×48b = 2.25KB | 1R | 48b |
| 6b×6b 乘加 | 组合 | 1 cycle | `α·g+β` → 12b 再 `mod n` |
| kth-one | 共享前缀树 | 1 cycle | 48b→6b |

无 13.5KB LUT。`g` 取 6b 折，不当成 24b×6b 大乘。

### 数据路径与状态机

**RUN**：与 M-2 相同的 2 cycle 译码（乘余 + kth-one）。

**REPAIR 重绑（离线/固件，可硬件辅助）**：

1. fence + drain。
2. 写 mask。
3. `n=popcount(M)`；若 `n=0` 标 DMC 不可用。
4. 对候选 `α∈{1,5,7,11,13,17,19,23,25,31,35,37,41,43,47}` 且 `gcd(α,n)=1`，计算 `score(α)=max_{S∈Doc} gcd(α·S_g, n)`，取 score 最小的 α（并列取最小 α）。
5. 写 `(α,β,n)`，release。

硬件不必实现步骤 4 的搜索（48 次 gcd 在 CPU 上可忽略）；仿真器要按该算法填 CSR，禁止手工随便写 α=1 当「已重绑」。

## 3. 为什么有效

仿射 `g ↦ αg+β (mod n)` 在 `α∈(Z/nZ)*` 上双射，再接 kth-one 仍双射到活集。死命中 0。

gcd 代数（文档步长）：`S=2^m` 时 `S_g=2^{m-9}`，`gcd(α·S_g, n)=gcd(S_g, n)`。上界占用每 DMC `n / gcd(S_g, n)`。对比不重绑、仍 `mod 48`：占用每 DMC `≤ 48/gcd(S_g,48)=3`（大 2 幂），再被 mask 砍掉死类，可能只剩 1～2 个活类。

含因子 3 的 stride：`S_g=3·2^k`。若 `3|n` 且 `3|α` 则 gcd 变大、更塌；重绑禁止 `3|α`。若 `3∤n`（丢掉奇数因子），`3` 不再提供分母，应用 `n` 的 2-adic 与 5、7 等剩余因子算 gcd。这正是本题「丢掉奇数因子会改变与 δ 的 gcd」。

Little：每 DMC 有效并行类从 ~3 拉到 `n/gcd(2^k,n)`。25% 均匀 `n=36`，`gcd(2^k,36)=4`，类数 9，相对不重绑的 3 是 ×3。roofline 再被 pipe 截。

## 4. 评估计划

### 基线

满好多项式 + 只 mask 不重绑（α=1, mod 48，死槽 stacking 或跳死）；M-2 但 α 固定为 1 不随 n 改；无 live-set 库 mapper。

### 必须 cycle 级建模的结构

- 384×(α,β,n) 864B CSR。
- 6b×6b 仿射 + `mod n`。
- mask + kth-one（M-1 线译码）。
- **gcd 表生成器**（评估脚本）：对每个退役率、每个文档 S，打印 `gcd` 与每 DMC 类数。
- repair 重绑算法（按 §2 选 α）。

### 指标与负载

专门打问题中的 3-adic / 奇数因子：退役 6.25/12.5/25%，均匀与「按 3 残类偏退役」（刻意丢掉或保留 3 因子）。占用与 BW：有重绑 vs 无重绑。死命中=0；可逆。min/mean vs 0.85。附 gcd 表。

### 预期收益区间与置信度

2 幂大步长 + `n` 仍含 16 的因子时，重绑相对 `mod 48` 的类数增益 `×1.5～×3`。3 残类偏退役（`n` 丢掉 3）：无重绑可能 BW≪0.85，有重绑回到 `0.7～0.95`。置信度中（代数清楚，交通是否撞 DMC 界不确定）。不宣称 T0 通过。

## 5. 硬件开销估算

面积：864B CSR flop ≈ `6912×6GE≈41kGE`；2.25KB mask 同 M-1；6b 乘加 `<0.3kGE`。无 13.5KB LUT。功耗：1R 18b+48b + 乘，`0.3～0.6mW`。延迟：2 cycle 译码。repair 选 α 在固件，`<10k` cycle 可忽略。
