# M-5: DMC 占用监视触发窗切换

- problem: P-0102
- author: 保守架构师
- style: conservative / implementable

## 1. 根因分析

base/stride 可在运行中换；boot 时写死的窗仍会饥饿。P-0102 的证伪场景正是「某一时刻 S≥1MiB，占用集中到 1 个或少数 HA/DMC，min/mean BW≪0.85」。需要闭环，但必须是保守闭环：长采样周期、不进每请求关键路径、**切换前 drain**（复用 P-0101 M-4 栅栏）。

本卡监视的是 DMC 发行计数，不是 bank 全表。阈值用 `max/mean > 8` 或窗口内 min/mean BW 代理 <0.85。禁止 `core_id` 进 bank map。不在流量下切窗。

## 2. 机制

### 结构

1. **384×16b 饱和计数器**：每个 DMC 一次 issue +1，饱和到 `0xFFFF`。总量 384×16=6144b=768B。
2. **采样周期 Q**：18b CSR。每 Q 次**全局** DMC issue（或每 Q 个完成）锁存一次快照，算 `max`、`mean=sum/384`，然后清零或右移（v1 清零）。
3. **比较树**：`max > 8·mean`（即 max/mean>8）或 `proxy_bw < 0.85`。`proxy_bw` v1 用 `active_dmc/384`，`active` 定义为计数 > `mean/2` 的 DMC 数。
4. **A/B 窗**：两套 `m*` 或两套 14×24 矩阵（复用 P-0102 M-1 的滑动窗：A 为当前，B 为备份，例如 A=`m*=9` 低窗，B=`m*=21` 高窗）。1b `SWITCH` 选择 A/B。
5. **触发**：比较为真 → 置 `NEED_SWITCH`，进入与 P-0101 M-4 相同的 drain；QUIESCE 后翻转 `SWITCH`（或加载 B 的 `m*`），再放行。同一作业内默认只允许一次自动翻转，避免抖振（`FLIP_ONCE` 锁）。

不在 issue 组合路径上做除法：计数器 +1 是旁路；比较在采样边界、多周期。

### 容量 / 端口 / 位宽

| 结构 | 容量 | 端口 | 位宽 |
|------|------|------|------|
| DMC 计数器 | 384×16b = 768B | 1W（issue+1 饱和）+ 1R（采样扫描） | addr 9b / data 16b |
| Q CSR | 18b | 1W 软件 | 1..2^18，默认 65536 |
| 全局 issue 计数 | 18b | +1 / 到 Q 清零 | 18b |
| max/sum 归约 | 流水 9 级树 | 采样态 1R 扫 384 或维护 running max/sum | sum 26b（384×65535<2^24） |
| SWITCH / NEED_SWITCH / FLIP_ONCE | 3b | 控制 | 1b×3 |
| 窗 A/B | 2×5b `m*` 或 2 张矩阵 | 译码 1R | 与 M-1 同 |
| drain 逻辑 | 同 P-0101 M-4：14b outstanding + 5 态 | — | — |

计数器实现：384 入口 flop file 或 1W1R SRAM。每 issue 要 +1，故需按 DMC 并行：384 个独立 16b 饱和计数（推荐 flop，避免 SRAM 写口争用）。768B flop ≈ 6kbit。

### 数据路径与状态机

**Issue 旁路（每请求）**：译码得 `dmc` 后 `cnt[dmc] += 1`（饱和）；`giss++`；不反馈进索引。索引只看当前 `SWITCH` 选中的 A 或 B 窗（M-1 滑动）。

**采样 FSM**：

| 态 | 动作 |
|----|------|
| ACCUM | `giss < Q`，只累加 |
| SNAP | `giss==Q`：锁存 max/sum，多周期扫 384（或用 running 统计则 1 拍），算 `max>8*mean` |
| ARM | 条件真且 `FLIP_ONCE=0`：`NEED_SWITCH=1`，进入 DRAIN（P-0101 M-4） |
| DRAIN/QUIESCE/INC | 与 M-4 相同，但 INC 改成 `SWITCH ← ~SWITCH`，`FLIP_ONCE=1` |
| RESUME | 清计数，回 ACCUM |

硬约束：SWITCH 只在 outstanding=0 时翻转。阈值比较不在 issue 关键路径。

## 3. 为什么有效

饥饿的充要现象是少数 DMC 吃掉几乎全部 issue。均匀时 `max/mean≈1`；9 个 DMC 热、其余 0 时 `mean=Q/384`，`max≈Q/9`，`max/mean ≈ 384/9≈42.7>8`。阈值 8 对应「最热 DMC 比平均热 8 倍」，约 ≤48 个 DMC 在干活（均匀热集），远小于 384，作为保守触发。

闭环：检测到低窗饥饿 → drain → 切到含 `[21,33)` 的 B 窗 → 占用从 1 桶回到 K 量级。Little：检测窗口长 `Q` 个 issue，Q=65536 时，120 核 ×128 outstanding 饱和下约数个 drain-depth 的时间，不是 per-request。

假阳性：顺序流若暂时偏科某个 die，也可能 `max/mean>8`。`FLIP_ONCE` + 大 Q 压假阳性；评估必须报顺序流误切率。

不打破 K：B 窗仍是可逆抽取，快照占用 ≤K。

## 4. 评估计划

### 基线

固定低窗（A=`m*=9`）永不切；手动 boot 就用高窗（无监视）。

### 必须 cycle 级建模的结构

- 384×16b 饱和计数（1W+1R 语义）。
- 18b Q 与全局 issue 计数。
- max/mean 比较树。
- SWITCH 与 A/B 窗（滑动 `m*`）。
- P-0101 M-4 同类 drain（outstanding、发行门）。
- FLIP_ONCE。

### 指标与负载

从饥饿窗启动，注入 `S=2MiB`：应看到 detect → drain → switch，之后占用恢复、BW 回升。顺序 `S=512B`：假阳性率（误切次数 / 采样次数）。报检测延迟（issue 数）、drain cycle、切换后 min/mean BW。不要在切换前的那一个 epoch 里报占用 >K。

### 预期收益区间与置信度

饥饿注入：切换后占用从 `≪K` 到 `~K`，BW 从 ≪0.85 到 0.85 讨论区。检测延迟 ≈Q（默认 64K issue）。顺序流假阳性目标 `<5%` 采样（Q 大且 FLIP_ONCE）。置信度中低（阈值与交通相位敏感）。不宣称 T0 通过。

## 5. 硬件开销估算

面积：384×16b flop ≈ 6kbit ≈ `384×16×6GE≈37kGE`（或 768B SRAM + 每 DMC 旁路 +1，SRAM 方案面积小但要 384 口或银行化）；比较树 `<2kGE`；drain 同 M-4。功耗：每 issue 一个 16b +1，`0.5～2mW`。延迟：索引路径 +0 cycle（监视旁路）；采样比较多周期；切换引入一次 drain 的停顿。
