# M-3: 双索引异或合并

- problem: P-0102
- author: 保守架构师
- style: conservative / implementable

## 1. 根因分析

单窗口是单点故障：窗一旦被 `S=2^m` 冻在外面，I=0。I-Poly 固定 `[9,29)` 在 2MiB 上丢掉 `[29,33)`；再窄的 `[9,24]` 只剩 3 个自由位。

本卡同时算两个哈希再 XOR 合并：低窗死了还有高窗，高窗对顺序流几乎常数，低窗仍动。这不是滑动（M-1）也不是逐位折叠（M-2），而是两条完整索引的合并。禁止 `core_id`。占用 ≤K。

## 2. 机制

### 结构

1. `idx_lo = H_lo(addr[28:9])`：11-bit XOR hash，输入 20b（与库 I-Poly 窗同宽）。`H_lo` 为 11×20 的 0/1 矩阵，复位为单位窗（`idx_lo[i]=addr[9+i]`）。
2. `idx_hi = H_hi(addr[32:21])`：12-bit XOR hash，输入恰为 `S=2MiB` 自由位。`H_hi` 为 12×12，复位为单位阵。
3. 合并：`idx[11:0] = {1'b0, idx_lo[10:0]} ⊕ idx_hi[11:0]`（零扩展较短的 `idx_lo`）。
4. 拼装：`u=idx[10:0]`，`c=(idx[11]+pop3(idx[2:0]))%9`，`flat=c·2048+u`。

大步长：`idx_lo` 常数，`idx_hi` 携带集合。顺序：两者都动，合并仍满秩。

### 容量 / 端口 / 位宽

| 结构 | 容量 | 端口 | 位宽 |
|------|------|------|------|
| H_lo 矩阵 | 11×20 = 220 bit | boot 1W；译码组合 | in 20b / out 11b |
| H_hi 矩阵 | 12×12 = 144 bit | boot 1W；译码组合 | in 12b / out 12b |
| 合并 XOR | 12 XOR2 | 组合 | 12b |
| 合计配置 | 364 bit（评估可裁到 ~200 bit：H_lo 改 11×8 抽列） | — | — |

v1 若要贴「~200 config bits」：H_lo 每行只使能 8 个可编程源（11×8=88）+ H_hi 单位阵硬线（0）+ 12 个可选对角扰码（12）+ H_hi 每行 2 个可编程源（12×10=120）≈ 220 bit。仿真允许满 364b 或精简 200b，须在报告里写死哪一种。

0 SRAM。1 cycle 寄存合并结果。

### 数据路径与状态机

无 FSM。每请求并行算 `idx_lo`、`idx_hi`，再 12b XOR，再拼装。深度：20 输入 XOR 树 ~5 门 + 1 级合并。建议 1 cycle 寄存 `idx`。

消融开关（评估必需，3 个 1b CSR）：

- `USE_LO`：`idx_hi` 置 0。
- `USE_HI`：`idx_lo` 置 0。
- `USE_BOTH`：默认。

飞行中不改矩阵；CSR 消融只在空闲。

## 3. 为什么有效

`idx = zext(H_lo(ℓ)) ⊕ H_hi(h)`。

- `S=2MiB`：`ℓ=addr[28:9]` 中 `[20:9]` 冻结、`[28:21]` 仍变 8b，故 **lo-only 并不完全为 0**（与纯 `[9,21)` 不同），但丢掉 `[32:29]`。`H_hi` 吃满 12 自由位。merged 占用 → K。lo-only 占用 ≤256（若只计与库窗对齐的 8 个自由位）或更少。hi-only 占用 → K，但顺序流上 `h` 几乎常数，占用塌到陪集。
- `S=512B`：`ℓ` 满变，lo-only 接近 2^11 桶；merged 至少同样好。

这就是消融要证明的：lo-only 在 2MiB 塌，merged 不塌。

Little：lo-only 在 2MiB 上有效 DMC 可能只有数个，`BW≤few·μ_d` ≪0.85；merged 按 K 点/最多 384 DMC。Amdahl 段是「高位未进索引」。

## 4. 评估计划

### 基线

lo-only；hi-only；merged；库 I-Poly `[9,29)`（近似宽 lo）。

### 必须 cycle 级建模的结构

- 两个 XOR hash（11b 与 12b）及配置矩阵。
- 12b 零扩展 XOR 合并。
- 3 个消融 CSR。
- 拼装与占用探针。

### 指标与负载

消融表：`S∈{512B,1MiB,2MiB}` × {lo,hi,merged}。证明 lo-only 在 2MiB 塌缩（占用 ≪K，BW≪0.85），merged 不塌（占用≈K）。hi-only 在 512B 应差于 merged。min/mean BW。不要报占用 >K。

### 预期收益区间与置信度

2MiB + merged：占用 `0.9K～K`，BW 回 0.85 讨论区。2MiB + lo-only：占用 `8～256`，BW ≪0.85。512B + merged：接近满映射。置信度中高。不宣称 T0 通过。

## 5. 硬件开销估算

面积：~200–364b 配置 + 两棵 XOR 树 ≈ `2～3kGE`。0 SRAM。功耗：每请求 `<0.2mW` @1GHz。延迟：1 cycle 寄存。
