# M-3: 层次正交放置

- problem: P-0101
- author: 保守架构师
- style: conservative / implementable

## 1. 根因分析

带宽经常先撞 DMC/pipe，而不是 18432 bank。`S=2MiB` 时 `K=4096` **足够覆盖全部 384 个 DMC**（`min(K,384)/384=1`），但 `(G mod N)` 把 AP 叠到 9 个 flat，再 `/48` 后常常只有 **9 个 DMC**。9 个 bank「有占用」仍可能让 375 个 DMC 空转，pipe roofline 直接按 `9/384≈2.3%` 封顶。

根因：单层 `mod N` 不区分「先铺 DMC、再铺 bank」。本卡两级放置：最高熵区分位**注入**进 DMC 索引；bank-in-DMC 用剩余位。成功标准是 DMC 占用 ≈1.0 且无 HA 偏科，**不是** bank 占用 >K/N（那会证伪本题）。禁止 `core_id` 进 map。

## 2. 机制

### 结构

两级组合映射，可选一张 384 项 2-bit 斜表。

**Stage A — DMC（384=128×3）**

- 7-bit 抽取：`p[6:0] = addr[32:26]`（`S=2MiB` 区分位的高 7 位，15.6% 的 2MiB-AP 步长下这些位全变；`K=4096` 覆盖 `2^7=128` 有余）。
- 3-way 编码：`t ∈ {0,1,2} = ENC3(addr[25:24])`（再 2 个区分位；`ENC3` 为 4→3 满射，例如 `{00,01,10,11}→{0,1,2,0}`）。
- `dmc0 = t·128 + p` ∈ [0,384)。
- 可选 **384×2b skew 表** `SK[dmc0]`：输出 `s∈{0,1,2,3}`，`dmc = (dmc0 + s·3) mod 384`，用来把成对 HA（同 die 相邻 pipe）打散。复位 `SK=0`（恒等）。

**Stage B — bank-in-DMC（48=16×3）**

- `b4[3:0] = addr[23:21] ⊕ addr[14:11]`（前 3 个仍是 2MiB 区分位，保证同 DMC 内最多 8 个区分值；XOR 低位服务顺序流）。
- `b3 ∈ {0,1,2} = ENC3(addr[20:19])`（`S=2MiB` 时冻结，只选 16 点里的 3 路陪集）。
- `bank = b3·16 + (b4 % 16)`，再 clip 到 0..47（`b3≤2` 时已 <48）。

目标：`S=2MiB` 时 Stage A 输入含 9 个区分位（7+2），`128×3=384` 可被 AP 的 4096 点盖满 → DMC 占用 = 384/384=1。bank 占用仍 ≤K/N≈22.2%。

### 容量 / 端口 / 位宽

| 结构 | 容量 | 端口 | 位宽 |
|------|------|------|------|
| 7b 抽取 + 3-way | 0 存储 | 组合 | in 7b+2b / out 9b DMC |
| ENC3 | 4×2 硬线 | 组合 | in 2b / out 2b（0..2） |
| SK 斜表（可选） | 384×2b = 768b = 96B | boot 1W；译码 1R | addr 9b / data 2b |
| bank-in-DMC | 0 | 组合 | out 6b（0..47） |

SK 用 96B 1R 寄存器堆或综合 flop file，不走共享 SRAM 银行。无 `core_id` 端口。

### 数据路径与状态机

无状态机（SK 只在 boot 写）。每请求：

1. `p=addr[32:26]`，`t=ENC3(addr[25:24])`，`dmc0=t·128+p`。
2. 若 SK 使能：1R `s=SK[dmc0]`，`dmc=(dmc0+3s) mod 384`（`3s∈{0,3,6,9}`，减 384 至多一次）。
3. 并行算 `bank`（Stage B）。
4. `die=dmc/192`，`ha_in_die=(dmc/2)%96`，`pipe=dmc%2`。

1 周期：步骤 1–4 组合 + 可选 SK 1R。SK 关闭则 0 存储读。

## 3. 为什么有效

占用分层：

- 集合代数：`|π_DMC(AP)| ≤ min(K,384)`。`m=21` 时区分位 12 个，Stage A 用了高 9 个且 7b 为接线、3-way 满射 ⇒ `|π_DMC|=384`，DMC 占用 = `min(K,384)/384=1`。
- bank 层：每 DMC 48 槽，K 点铺在 384 DMC 上，每 DMC 约 `K/384=10.67` 个点，`10.67/48≈22.2%=K/N`，不超上界。
- 对比 `mod-N`：9 个 flat → ≤9 DMC → DMC 占用 ≤9/384。若每 DMC 峰值 `μ_d`，Little/roofline：`BW ≤ 9μ_d` vs `BW ≤ 384μ_d`，比值 42.7。这是本卡相对 M-1 的差异：M-1 饱和的是 bank 陪集基数 K，不保证 4096 点不挤在少数 DMC。

Amdahl：设非内存部分占比 `(1−f)`，内存部分受 DMC 占用线性缩放，`S=2MiB` 上 `f` 接近 1 的扫描核，加速接近 DMC 占用比。HA 偏科：192 HA × 2 pipe，DMC 均匀则每 HA 2 个 DMC 都热；SK 把 `+3` 斜移避免成对 HA 总吃同一 3-way 残类。

## 4. 评估计划

### 基线

`(G mod N)`；M-1（区分位饱和但未优先铺 DMC）；低位 DMC 索引 `addr[17:9] % 384`（大步长应塌缩）。

### 必须 cycle 级建模的结构

- 7b 抽取、ENC3、`t·128+p`。
- 可选 384×2b SK（1R、boot 1W）。
- Stage B 的 6b bank 接线/XOR。
- 按 die/HA/DMC/bank **四层分别**计数的占用探针。
- 每 DMC 单发行口；128 outstanding/core。

### 指标与负载

占用按 die / HA / DMC / bank 拆开；min/mean BW；与 M-1 对照。成功：**DMC 占用 ≈1.0** 且单 HA 请求份额 ≤ `2/384` 的 ~1.5×（无 HA hogging）。**失败标准不是** bank 占用 >K/N——那是禁区。负载同信封：`S∈{512B,512KiB,1MiB,2MiB}`，随机 base。`S=512KiB` 时 K=16384>384，DMC 占用仍应 ≈1.0。

### 预期收益区间与置信度

`S=2MiB`：DMC 占用 `0.95～1.00`；bank 占用 `0.18～0.222`（≤K/N）。相对 `mod-N` 的 BW：`×20～×42`（若真是 DMC 界）。相对 M-1：若 M-1 已把点铺开，增益可能只有 `×1.0～×2`；若 M-1 的 `/48` 把 4096 点挤进 ~86 个 DMC（4096/48），本卡仍有 `×3～×4.5`。置信度中。不宣称 T0 通过。

## 5. 硬件开销估算

面积：组合抽取 `<0.2kGE`；可选 SK 96B flop file ≈ `384×2×6GE≈4.6kGE` 或 96B SRAM（约 0.001mm² 量级 @7nm）。功耗：SK 1R 每请求，`<0.2pJ`。延迟：无 SK 为纯组合；有 SK 为 1 cycle 读 + 模加。
