# M-4: 栅栏 epoch 陪集旋转

- problem: P-0101
- author: 保守架构师
- style: conservative / implementable

## 1. 根因分析

静态可逆映射把一次扫描永久钉在 **K 个 bank 的一个陪集**上。长作业反复扫同一 8GiB 工作集、同一大步长，会反复打同一批热 bank / 热 DMC。占用代数锁死：**单次快照占用 ≤K**，任何换索引函数都不能在同一瞬间造出第 K+1 个互异点。

能做的是：在 **全局排空** 之后旋转冻结位对索引的贡献，换一个陪集。快照占用仍 ≤K；E 个 epoch 的并集占用 ≤ `min(N, E·K)`。`S=2MiB`、`K=4096` 时 `E=5` 才有机会在时间上盖满 `N=18432`（`4×4096=16384<N`，`5×4096=20480>N`）。诚实声明：这不打破单 epoch 内的 K 界。禁止在飞行请求下改 map。禁止 `core_id` 进 bank map。

## 2. 机制

### 结构

1. **机宽 EPOCH CSR**：8 bit，所有 die/HA/DMC 广播同一值。只在栅栏完成时加一。
2. **冻结位贡献**：bank/DMC 索引的冻结段（相对当前主导 `S=2MiB` 即 `addr[20:9]` 的低 8 位）与 `EPOCH` XOR：`f'[7:0] = addr[16:9] ⊕ EPOCH`。区分位段（`addr[32:21]`）**不**与 EPOCH XOR，以免破坏 M-1/M-2 的 K 饱和抽取；EPOCH 只旋转陪集。
3. **索引**：复用「12b 区分 + 9-way 陪集」拼装（与 M-1 同类，但是 9-way/`flat` 高段吃 `f'` 而不是生冻结位）：`c = ENC9(f'[3:0])`，`v=addr[32:21]`，`flat=(c·4096+v) mod 18432`。
4. **drain FSM**：全局 fence。每个 DMC 一个 `inflight` 计数，或一条全局 `outstanding` 计数。软件/固件写 `EPOCH_REQ` 后停止新请求，等计数到 0，才 `EPOCH←EPOCH+1`，再放行。

### 容量 / 端口 / 位宽

| 结构 | 容量 | 端口 | 位宽 |
|------|------|------|------|
| EPOCH CSR | 8b，机宽 1 份 | 1W（仅 QUIESCE→INC） / 广播读 | 8b |
| EPOCH_REQ / ARM | 2b | 1W 软件 | 控制 |
| 全局 outstanding | 14b（`120×128=15360<2^14`） | +1 发行 / −1 完成，1 加 1 减 | 14b |
| 每 DMC inflight（可选冗余） | 384×10b = 480B | 每 DMC 1 加 1 减 | 10b（单 DMC 最坏 ≤15360，实用 10b 饱和） |
| 冻结 XOR | 8 XOR2 | 组合 | 8b |
| ENC9 + 拼装 | 同 M-1 | 组合 | 15b flat |

无大 SRAM。EPOCH 不是 per-core、不是 per-thread，避免一致性分叉。

### 数据路径与状态机

**请求路径（RUN）**：`f'=addr[16:9]⊕EPOCH` → ENC9 → `flat` → `(dmc,bank)`。与飞行中的 EPOCH 一致。

**栅栏 FSM（5 态）**：

| 态 | 条件 | 动作 |
|----|------|------|
| RUN | `EPOCH_REQ=0` | 正常收发 |
| DRAIN_REQ | 软件写 `EPOCH_REQ=1` | 关闭 core 发行门（不再接受新 miss） |
| QUIESCE | 发行门关 | 等待 `global_outstanding==0`（且可选所有 DMC inflight==0） |
| EPOCH_INC | 计数为 0 | `EPOCH ← EPOCH+1`（8b 回绕）；广播同步 1 拍 |
| RELEASE | INC 完成 | 开发行门，清 `EPOCH_REQ`，回 RUN |

**硬约束**：`EPOCH` 只在 `global_outstanding==0` 时改写。仿真器必须拒绝「飞行中改 EPOCH」。不按请求、不按 core 换陪集。

排空代价：若 15360 个 in-flight、平均服务 `T` cycle，drain ≈ `T`（已发行的尾巴），外加关门到最后一拍的对齐。无额外数据搬移。

## 3. 为什么有效

快照：固定 EPOCH 时，本图与静态 M-1 同类，`|{flat}|≤K`。并集：epoch `e` 的陪集是 `C(e)={ (ENC9(f⊕e)·4096+v) mod N }`。若 ENC9 对 EPOCH 低 4 位近似平衡，相邻 epoch 的 `c` 变化，`C(e)` 与 `C(e+1)` 交小。

`|⋃_{e=0}^{E-1} C(e)| ≤ min(N, E·K)`。数值：

| E | E·K (S=2MiB) | 并集上界 |
|---|----------------|----------|
| 1 | 4096 | 4096 |
| 4 | 16384 | 16384 |
| 5 | 20480 | 18432 |

长时间重复扫描若在扫描间插入栅栏，热 bank 集合会换，bank DRAM 的 `t_RC` 热点被摊到另一陪集。Little：单 epoch 仍 `λ≤K·μ_b`；跨 epoch 的**时间平均**可接近 `N·μ_b` 的 bank 维，但仍受 384 DMC 截断。Amdahl：栅栏本身是串行段，`T_drain / T_scan` 必须小，否则旋转收益被吃掉。

## 4. 评估计划

### 基线

静态 M-1（EPOCH 恒 0，从不 drain）；`G mod N` 静态。

### 必须 cycle 级建模的结构

- 8b EPOCH CSR 及广播时序（INC 后 1 拍全机可见）。
- 14b 全局 outstanding（或 384×10b per-DMC）。
- 5 态 drain FSM 与 core 发行门。
- 8b XOR 进 ENC9 的路径。
- 飞行请求完成事件（否则 QUIESCE 不可模拟）。

### 指标与负载

重复 `S=2MiB` 全空间扫描（同一 job 扫 ≥8 遍）：有旋转 vs 无旋转的 BW；每次 drain 的周期数；并集占用（epoch 计数器扫过的 bank 集合大小）。诚实：单 epoch 占用 ≤K，不得写成「旋转后单拍占用 >K」。另报 `T_drain / T_scan`。partial-good：旋转不得把索引甩出 48 槽/384 DMC。

### 预期收益区间与置信度

单次 2MiB 扫描：与静态 M-1 几乎同（0～5%），因为栅栏在扫描之间。多遍扫描：若热 bank 的 `t_FAW/t_RC` 是瓶颈，时间平均 BW 预期 `+10%～+40%`；若已是 DMC 打满（见 M-3），旋转收益 ≈0。drain 成本：`O(T_tail)`，15360 条尾巴在饱和时约一个 bank 服务深度，估计 `2e2～2e4` cycle，取决于当时占用。置信度中低（对调度敏感）。不宣称 T0 通过。

## 5. 硬件开销估算

面积：8b CSR + 14b 加/减计数 + 5 态 FSM `<0.5kGE`；可选 384×10b inflight ≈ 480B flop/`~15kGE`。冻结 XOR 8 门可忽略。功耗：计数器每发行/完成翻转，`<0.5mW`。延迟：RUN 路径 +0 cycle（XOR 进已有 ENC9）；栅栏是控制面，不在命中路径加级数，但关门期间吞吐为 0。
