# M-14: 邻节点饥饿气泡中继

- problem: P-0198
- author: 保守架构师
- style: conservative / implementable

## 1. 根因分析

无缓冲环上空槽是残差：`I ≤ 1−O`。推理 decode 的 KV 小包在某个 NI 连续 `inject-fail` 时，该笔就是这一步的 straggler：`T_step ≥ T_now + W_starve + 剩余跳`。基线与多数 work-conserving 注入规则下，**上游** 节点只要自己有就绪 flit，就会填掉每一个到达的空槽。空槽存在，但到不了已经饿着的那个 KV 源。尾部被「空槽被非饥饿节点吃掉」拉长，平均注入成功率仍可以看起来不差。

这与「空槽≡注入机会 / 偷气泡」相反：问题不是没人敢注，而是 **不该注的人先注了**。也不是静态日历卖掉所有空波（那是 TDM），只在下游声明饥饿时让出 **一次** 空槽。

不是源端 outstanding 限速。`--cc-scheme srcfc` 与 M-5 CRRF 黑盒是对照。

## 2. 机制

### 结构

每个 NI、每个通道、每个方向一份。Snp 方向硬线 `RELAY_EN=0`（Snp 不捐、也不因本卡多等）。

1. **饥饿计数 `ST[3:0]`**：本方向 staging 就绪且本拍未注入则 `ST = sat15(ST+1)`；成功注入则 `ST=0`。只数本节点，不出环。
2. **上游 1 bit `hungry`**：当 `ST ≥ H`（CSR `H[3:0]`，复位 8）时，向 **本方向的上游邻居**（空槽来的方向）送 `hungry=1`。1-cycle 线，不是总线。
3. **中继规则**（上游邻居，当拍）：
   - 本拍 `slot_occupied=1`：过路优先，不动作（没有空槽可让）。
   - 本拍槽空且本地无就绪：空槽本来就会前送，不动作。
   - 本拍槽空且本地有就绪且 `hungry=1` 且本节点 `ST < ST_nbr_approx`：`donate=1`，**跳过这一次注入**，空槽前送。`ST_nbr_approx` 用 1 bit 编码：邻居 `hungry=1` 视为至少 `H`，本节点用自己的 `ST` 比 `H`；相等则不捐（两边一样饿，保持 work-conserving）。
   - 冷却：每个 NI 每方向每 `S` 拍至多捐 1 次（`S[3:0]` 复位 4），避免把自己捐饿。
4. **不改 outstanding，不关窗，不建队列**。被跳过的本地头留在既有 staging。

没有空槽时本卡为零操作。不创造带宽。

### 容量 / 端口 / 位宽

| 结构 | 容量 | 端口 | 位宽 |
|------|------|------|------|
| `ST` | 4 bit / NI / 通道 / 方向 | 每拍 +1 或清零 | 4b |
| `H`, `S` CSR | 4b + 4b / die（可全局） | 1R1W | 复位 8、4 |
| `hungry` | 1 bit 线 / 邻接 | 上游 1 出、本节点 1 入 | 1b，1-cycle |
| `RELAY_EN` | 1 bit / 通道 | 1R1W | Snp=0 |
| 冷却 | 4 bit / NI / 方向 | 每拍 +1 | 4b |
| donate 与门 | 0 | 组合 | 见上 |

14×4×2×4b `ST` = 448 bit。无 SRAM，无 CAM，无跨环饥饿总线。

### 数据路径与状态机

无多状态 FSM。每拍每方向：

1. 更新 `ST`（与 highway 并行）。
2. 输出 `hungry = RELAY_EN AND (ST≥H)`（寄 1 拍到上游）。
3. 注入：`inject = stg_valid AND ~slot_occupied AND NOT donate`。
4. `donate = RELAY_EN AND hungry_in AND stg_valid AND (ST<H) AND cooldown_ok AND ~slot_occupied`。
5. 过路：不进本逻辑。

时序：4b 比较 + 1 AND，目标同拍注入决策；`hungry` 入是上一拍邻居值，已规定 1-cycle。

## 3. 为什么有效

第一性原理：straggler 的等待是一段 **看不见空槽** 的时间。空槽在环上以 1 hop/cycle 移动。上游捐一次，空槽沿方向走到饥饿节点的时间是两节点距离（通常 1 hop，因为线只接到紧邻上游）。于是 `W_starve` 在「存在非饥饿上游且存在空槽」时被钉到大约 `S + 1` 拍的粒度，而不是被上游连续注入无限推迟。`T_step` 里由注入饥饿主导的那一项被截断。

主收益必须是饥饿节点当前 epoch KV 的完成时间 / `T_step`，不是全环 `p_inj`。捐空槽会降低上游自己的瞬时注入率；若 `T_step` 不降，说明捐错了人，卡失败。

推理（主）：decode KV 源在环上稀疏、预取或小集合源更「有东西就注」，空槽被吃掉的图景常见。失效：所有 NI 同时 `ST≥H`（没人捐，退化成基线）；或环上长期无空槽（无物可中继）。

训练大块集合（次要，一句话）：大块源自己长期就绪，`ST` 不易单独突出，中继很少触发，预期近似中性。

## 4. 评估计划

### 基线

1. 流控 OFF，work-conserving 注入（有空且有就绪就注）。
2. `srcfc` 等对照。本卡开/关 × 对照。
3. M-5 CRRF 黑盒（`sims/P-0198/M-5/sweep.py --mode smoke --seed 20260903`；soc_sim 无开关则评估方提供）。
4. 消融：
   - R0：`RELAY_EN=0`（off）。
   - R1：`H=8, S=4`（复位全卡）。
   - R2：`H=4, S=2`（更积极）。
   - R3：`H=15`（几乎不触发）。
   HARD：R1 须在诚实 cycle 下推理 `T_step` 优于 R0。R1≈R0 则禁写因果。R2 若把上游也捐饿导致 `T_step` 变差，记过捐，不得靠 R2 凑过线。

### 必须 cycle 级建模的结构

- 4b `ST`、1b `hungry`、donate 与门、冷却。
- 过路优先不变。
- Snp `RELAY_EN=0`。
- **不要** 建全局饥饿向量、token bucket、静态日历。

### 仿真器改动（独立分支，不动仿真仓 main；RTL 不改）

1. `tests/soc_sim` 加 `--cc-scheme starve-relay`。
2. NI 模块加 `ST` 与注入与门的 `donate` 项。
3. 每条环向邻接加 1b `hungry` 端口（拓扑文件 / `ni` 邻接表）。
4. 为什么改结构：基线 NI 没有「因下游饥饿而跳过空槽注入」的输入；不加 1b 邻接端口则中继在模型里无法发生。

### 指标与负载

主指标：推理 `T_step`、饥饿节点 KV 的注入等待 p99、完成数、collapse。负载写死：多 die decode KV + 少量同环预取/小集合，使「有的节点饿、有的节点有东西可注」成立。纯均匀全对称源是 reduced-bbox，可跑但不得当主表。0.85 是推理 pass bar。`ST` 分布、捐次数是 proxy。

### 预期收益区间与证伪

相对 R0，非对称推理信封：`T_step` 预期 **6%–18%**，且饥饿 KV 的 `W_starve` p99 必须下降。全对称重载：预期 **0%–5%**。Snp 预期 = R0。

证伪：R1 的 `T_step` 不低于 R0，或只见上游 `p_inj` 下降而尾不动 → 失败。不贴 T2。不宣称 T0 通过。

## 5. 硬件开销估算

假设同前。面积：每方向 4b 计数 + 4b 比较 + 1b 线，估计全片 **<3 kGE**。功耗：每拍 4b 加，时钟门控到 `stg_valid`。延迟：注入决策 0 拍；`hungry` 1 拍。不加槽、不加缓冲。

## 6. 与已知工作的区别（为何不是功能等价）

- **不是** Cambridge / empty-slot「谁遇空槽谁填」：本卡在空槽到达且本地就绪时 **可能不填**。
- **不是** Æthereal / Nostrum TDM：许可不是周期位图，只在 `hungry` 时捐 1 次。
- **不是** srcfc / credit / ECN：不改 outstanding，不在包上打标，无速率环。
- **不是** Age+Class：不在多候选里打分；捐的是空槽本身给邻居，不是本地赢家。
- **不是** 最短 CW/CCW。
- **不是** 上轮静态日历：日历无反馈；本卡有 1b 邻居状态，且默认 work-conserving。
