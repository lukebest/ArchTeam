# M-20: Decode-epoch 最长弧先发

- problem: P-0198
- author: 保守架构师
- style: conservative / implementable

## 1. 根因分析

推理 decode 一步是屏障：`T_step = max_i C_i`。第 `i` 笔 KV 的完成至少包含 `t_issue(i) + hops(i) + t_mem(i) + t_resp(i)`。已冻基线把方向选成最短弧，`hops(i)` 对给定 src/dst 是常数。若 AIC 按 FCFS / 地址序先发 **近 dest** 的 KV，所有长弧请求的 `t_issue` 被挤到步末，它们的占用再在步末叠在同一弧上，`max_i C_i` 出现晚高峰。这是 makespan 调度问题，不是「环还不够空」或「注入率还不够高」。

根因作用点在 **源端发行序**（以及对称的 bottom Dat 响应挑选），不在环上仲裁，不在 RBRG，不改路由。Lee 式「每拍按距离重打分」会滑回已知距离仲裁；本卡把 `hops` 做成发行时的一次排序键，发出之后环上仍走基线过路优先。

不是 srcfc。`--cc-scheme srcfc` 与 M-5 CRRF 黑盒是对照。

## 2. 机制

### 结构

两处同一规则，一处关掉则消融。

1. **请求侧（top AIC → Req 注入）**：在既有 outstanding 表里，只看 `EP==CUR` 且已就绪、尚未注入的请求头。最多取出 **4** 个候选（表口 4R 或 4 个队头），比较 `hops`（由已冻最短 CW/CCW 算出，4b，`N≤16`）。`argmax hops` 获得本拍发行/注入权。打平选 txnid 较小。`EP≠CUR` 的预取默认不进这 4 槽，除非当前步候选不足 4（CSR `FILL=1` 时用预取补齐，但键仍是 hops，且 `CUR` 候选永远优先——先过滤 epoch，再比 hops）。
2. **响应侧（bottom Dat NI）**：HBM/内存完成的 Dat 响应头同样按 `EP` 过滤，再 `argmax hops`（响应走回请求源的弧长）。只在 bottom 的 Dat 注入口实例化，不在每个 top 复制一份数据缓冲。候选仍来自既有完成表，不新建 Dat FIFO。
3. **`hops` 计算**：5b 减法 + `N` 校正，或 16×4b LUT，与已冻方向硬件相同，本卡只 **读** 这个值当键，不改 `DIR`。
4. **4 候选上限**：比较树 3 个 4b 比较器。不是把 512 深 outstanding 做成 512 输入堆——那是面积爆炸，也不是本卡。

Snp 不实例化。Req 完成/Rsp 不改序。

### 容量 / 端口 / 位宽

| 结构 | 容量 | 端口 | 位宽 |
|------|------|------|------|
| 候选窗 | 4 个 header 指针 / AIC / 通道 | 4R 到既有表 | 指针宽度按平台；不存 payload |
| `hops` | 4 bit / 候选（组合或随头写） | 1R | 4b |
| `EP` 过滤 | 复用 outstanding 3b 标签（若未实现 M-17，本卡自带同样 3b `CUR`） | 1R | 3b |
| 比较树 | 3×4b 比较 | 1 次/拍 | 胜者 2b |
| `LPT_EN` | 1 bit 请求侧 + 1 bit 响应侧 | 1R1W | 复位皆 1 |
| `FILL` | 1 bit | 1R1W | 复位 0（当前步不足时不填预取） |

无织物存储。4 指针不是 flit 队列：payload 仍在 AIC/内存侧原处，只是挑选哪一个头去既有 1-flit staging。

### 数据路径与状态机

无多状态 FSM。每拍请求侧（响应侧对称）：

1. 从 outstanding/完成表取最多 4 个 `EP==CUR && ready` 头；不足且 `FILL=1` 才补其它 epoch。
2. 对每个候选 `hops = DIST(src,dst,N)`（响应侧 src/dst 对调）。
3. `winner = argmax hops`；打平 txnid。
4. 胜者进入既有 staging，等 highway 空（过路优先不变）。
5. 无候选：本拍不发行。

时序：LUT/减法与 2 级 4b 比较，目标 1 周期，与 AIC 发行口对齐。环上关键路径不经过比较树。

## 3. 为什么有效

第一性原理（LPT / list scheduling 对 `max` 目标）：在一组屏障作业里先开工最长者，降低 `max` 完成的上界。这里的「长度」是已经确定的环暴露 `hops`（加内存项在评估里当噪声，不预测）。先发长弧 KV，它们的 `t_issue` 前移，`C_long` 左移；短弧即使晚发，`hops` 小，仍容易在长弧之前完成。步末不再堆叠一组长弧占用，尾部弧争用下降——这是 `T_step` 直接项。

不是提高 `p_inj`：同一拍仍最多注 1 个。平均完成甚至可能变差（短请求被推迟），只要 `max` 下降就达到本卡目的。若均值下降而 `T_step` 不降，不得写收益。

推理（主）：一步内多 dest KV（不同 die / 不同 bottom 附着）hops 分布宽，LPT 有东西可排。失效：所有 KV 同 hops（对称贴边）；或一步只有 1 个就绪候选（比较树退化）。

训练大块集合（次要，一句话）：大块 hops 单一、拍数由长度主导，LPT 对首拍的影响可忽略，预期中性。

## 4. 评估计划

### 基线

1. 流控 OFF；AIC / bottom 发行 = FCFS 或平台默认地址序。
2. `srcfc` 等对照。本卡开/关 × 对照。
3. M-5 CRRF 黑盒（`sims/P-0198/M-5/sweep.py --mode smoke --seed 20260903`；soc_sim 无开关则评估方提供）。
4. 消融：
   - L0：`LPT_EN=0`（off，FCFS）。
   - L1：只请求侧。
   - L2：只响应侧。
   - L3：两侧（全卡）。
   - L4：最短弧先发（SPT，反卡）：若 L4 的 `T_step` 优于 L3，本卡 makespan 假说被证伪。
   HARD：L3（或可分的 L1/L2）须在诚实 cycle 下推理 `T_step` 优于 L0。L3≈L0 禁写因果。不得用「平均 KV 延迟」代替 `T_step`。

### 必须 cycle 级建模的结构

- 4 候选窗、4b hops、epoch 过滤、比较树。
- 请求侧与响应侧可独立关。
- **不要** 在环上按 hops 重仲裁、不要改 `DIR`、不要建 512 输入排序器。

### 仿真器改动（独立分支，不动仿真仓 main；RTL 不改）

1. `tests/soc_sim` 加 `--cc-scheme lpt-issue`。
2. AIC 发行 / 注入挑选模块：FCFS 改为 4-wide max-hops（`aic` / `injector` / outstanding 模型按仓内文件名落地）。
3. bottom Dat 响应注入同样改挑选。
4. 为什么改结构：基线发行序在流量发生器或 FIFO 头，不改挑选口则 LPT 只能写成测试台排序（那是非法臂）。必须把比较树放进 AIC/bottom NI 模型。

### 指标与负载

主指标：推理 `T_step`、步内 p99、完成数、collapse。负载写死：每 decode 步每 die ≥4 个不同 hops 的 KV dest（否则比较树退化，属 reduced-bbox）。可加 1 次小集合（集合内部不强制 LPT）。训练大块只附一列。0.85 是推理 pass bar。hops 直方图、平均完成是 proxy。

### 预期收益区间与证伪

相对 L0，hops 分布宽的推理步：`T_step` 预期 **8%–20%**。L1 与 L2 单独预期小于 L3。L4（SPT）预期 `T_step` **不优于** L0（若优于，假说反了）。Snp 预期 = L0。均值完成允许变差 **0%–8%**。

证伪：L3 的 `T_step` 不低于 L0，或只见平均 hop/延迟改善而 `max` 不动 → 失败。L4 优于 L3 → 失败。不贴 T2。不宣称 T0 通过。

## 5. 硬件开销估算

假设同前。面积：每 AIC 3 个 4b 比较 + 4:1 头指针 mux，14 die × Req；bottom ×2 × Dat 再一份。估计 **<5 kGE**。不增加 outstanding SRAM 容量（只加 4b hops 列或组合重算）。延迟：发行口 1 拍，highway 过路 +0。Snp +0。

## 6. 与已知工作的区别（为何不是功能等价）

- **不是** Lee 等 MICRO 2010 距离仲裁：那是 **每拍网络口** 按距离加权；本卡是 **发行一次** 排序，环上不再用 hops 做仲裁。
- **不是** Age+Class / QNoC：键是 hops 与 epoch 过滤，无年龄、无静态业务类权重。
- **不是** 最短 CW/CCW 发明：方向已冻，本卡只读 hops。
- **不是** TDM / 偷气泡 / srcfc：不卖空波，不改 outstanding 上限。
- **不是** 测试台把 trace 按 hops 排好：比较树在 AIC/bottom 硬件模型里，FCFS 臂必须能复现未排序到达。

## 7. 自检

1. HARD = L3 vs L0，诚实 cycle `T_step` 须优于 FCFS；不贴 T2。结论：写入。
2. 主收益是屏障 `max`，明确允许均值不降。结论：写入。
3. §6 非功能等价。结论：写入。
4. Snp 不实例化，不作卖点。结论：写入。
5. 平均 hop / gather T/off 不是 card-claim。结论：写入。
6. 单候选 / 同 hops 臂不得写因果；0.85 是 bar；dest 分布写死。结论：写入。
7. 不加缓冲/带宽；4 指针不是 payload 队列；无完美预测（hops 是已知几何，不是预测完成时刻）。结论：写入。
