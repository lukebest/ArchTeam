- problem: P-0198
- id: P-0198/M-5r2

- 船长约束：不加线、不改 RTL；只许在既有 Snp 环宽度上把 1 个 Dat beat 缝成 k 个 Snp 槽；再失败则 CRRF 线关闭

## 0. 诚实前置（读完 T1 再写）

M-5r1 T1（`reviews/P-0198/M-5r1/tier1_synthesis.md`，PR #95）致命两点：Snp flit 无 Data，ghost Dat 不是「借 1 槽」；Dat 已有 **2** 子环、Snp **1** 环，`1+duty_dat` 少算一条环。Dr.Archi 在 r1 harness 上 drain-off / header-only 与全机制数字相同——epoch/bind **零贡献**。

本卡 **删掉 epoch / bind / Drain 世代机**。剩下的只有：在 Snp 物理环的既有宽度上，把一个 Dat beat 拆成 k 个 fragment 缝合；本征 Snp 严格优先；每节点 ghost 密度帽。这就是 T1 说的 header-only + 密度帽。不化妆成新的重绑织物。

**预判（不强迫过线）**：诚实位宽下 64 B 的 k∈[6,9]，128 B 的 k∈[12,18]。相对 Dat×2 基线，多出来的容量 ≤ 1/k 条环。环受限推理 makespan `T/T_off ≥ 2/(2+1/k)`：k=8 → 0.941，k=9 → 0.947，最坏 k=18 → **0.973**，再扣密度帽 → **r≈1**。上周淘汰规则 2：推理 makespan 不缩短即淘汰。Snp ≤1.4 若靠把帽收很紧，Dat 侧更接近 1。两条杀线很难同时真满足。CRRF 线很大概率在本卡关闭。

## 1. 位宽：从 AMBA CHI 推出 k

### 1.1 规范与表号

主钉 **AMBA CHI Issue E.b，ARM IHI 0050E.b**（Non-Confidential ID081621）第 13 章 Link layer / §13.9 Flit packet definitions：

| 对象 | 表 / 节 | 用到的事实 |
|------|---------|------------|
| Snoop flit 字段表 | **Table 13-8** Snoop flit format（p.13-413） | SNP **无 Data / BE / DataID / TgtID**。字段：QoS(4)、SrcID(7–11)、TxnID(12)、FwdNID(7–11)、FwdTxnID(12)、Opcode(5)、Addr SAW=41–49、NS(1)、DoNotGoToSD(1)、RetToSrc(1)、TraceTag(1)、MPAM(0 或 11)。合计 **S = 51+SAW+M … 59+SAW+M** |
| SNP 通道管脚 | **Table 13-4** SNP channel interface signals | `SNPFLIT[(S-1):0]` 与单独的 `SNPFLITV`（valid 不在 flit 内） |
| Data flit | **Table 13-9** Data flit fields（p.13-414/13-415） | DW ∈ **{128, 256, 512} bit** = {16, 32, 64} B。BE = DW/8；可选 DataCheck=DW/8、Poison=DW/64。合计 D ≈ 221–233 / 370–382 / 668–680 +Y+DC+P |
| 事务 Size | **Table 13-18** Size encodings（p.13-427） | `0b110` = 64 B；**`0b111` Reserved**。Issue E **不定义 128 B / 1024 b Data** |
| NodeID / 地址 | Table 13-8 注释 | NodeID **7–11 b**；`SAW = Req_Addr_Width − 3` ∈ [41, 49] |

互证：

- ARM 公开 Channel Interface overview（`developer.arm.com/documentation/ihi0050/latest`，Issue E.r1 页）把典型 SNP 写成 **88 b**、DAT 例（4 B DataCheck）201+20=221 b。88 b 比 Table 13-8 下限 92 b 窄 4 b，列入保守针。
- **IHI0050F Issue F** §13.6 Flit widths；DataWidth 编码 000–100 = 4 B–64 B（F 本 Table 13-17）。仍无 128 B Data。MPAM 在 F 勘误 ARM-AES-0077 **D678** 对 Table 13-8 写 0 或 12；本卡 E.b 用 0/11，F 的 +1 b 不改变 k 整数。

128 B beat（1024 b Data）**不是** Issue E/F 合法宽度，只因平台 `gen_config.py:529` 记录 top 64 B vs bottom 128 B 冲突而扫；KILL 取扫过的 **最坏 k**。船长若后补 `chi_interface`，只在下列 k 区间内取点，**不改卡**。

### 1.2 W_snp、必须留下的字段、U

SNP 无 TgtID（Table 13-8）。环上弹出仍要目的地；highway 还要 valid / 通道区分 / i-tag / e-tag。这些位 **不得改写成 payload**：

| 字段 | 宽 | 理由 |
|------|----|------|
| valid | 1 | Table 13-4 的 `SNPFLITV`；槽占用。从 W_snp 扣（保守：valid 已是独立管脚，扣它只让 U 更小） |
| channel disc | 2 | 本征 Snp vs ghost fragment，header 权威 |
| dest（弹出） | N（7–11） | SNP 表无 TgtID，环 eject 必须另带 |
| i-tag + e-tag | 1+1 | 平台每 highway 一活标；**只许本征 Snp 发起 i-tag** |
| QoS（保守针） | 4 | Table 13-8 QoS；ghost 不得改写本征优先级。主针不扣，`conserv-U68` 扣 |

`S_keep = 1+2+N+2 = N+5`（主针）。保守针再扣 QoS4 → `N+9`。`U = W_snp − S_keep`。

Table 13-8 求和 + 公开 88 b 针：

| 针 | 出处 | N | SAW | MPAM | W_snp | S_keep | **U** |
|----|------|---|-----|------|-------|--------|-------|
| E.b-narrow | Table 13-8 下限 | 7 | 41 | 0 | **92** | 12 | **80** |
| E.b-mid | Table 13-8 | 11 | 45 | 0 | **104** | 16 | **88** |
| E.b-wide | Table 13-8 上限 | 11 | 49 | 11 | **119** | 16 | **103** |
| overview-88 | 公开 overview | 7 | — | — | **88** | 12 | **76** |
| conserv-U68 | overview 88、dest N=11 + QoS4 留下 | 11 | — | — | **88** | 20 | **68** |

**U ∈ [68, 103]**。KILL 用 **最小 U=68**。

### 1.3 D 与 k

每个 fragment 自带重组头（计入 D，不偷 U）：`H_frag=32`（src≤11 + TxnID 12 + frag_id 4 + last 1 + 对齐）。Dat beat 的 Data 加 BE（部分写必须；读 CompData 的 BE 全 1，仍按规范宽度计）：

| beat | Data | BE | D = Data+BE+H_frag | Issue E 合法？ |
|------|------|----|--------------------|----------------|
| 16 B | 128 | 16 | 176 | 是（Table 13-9 DW=128） |
| 32 B | 256 | 32 | 320 | 是（DW=256） |
| 64 B | 512 | 64 | **608** | 是（DW=512；平台默认 `kBeatBytes=64`） |
| 128 B | 1024 | 128 | **1184** | **否**（仅灵敏度；Table 13-18 无此 Size） |

数据-only、不计 BE：D_64=544、D_128=1056（列入区间下限，不作乐观主列）。

`k = ⌈D / U⌉`（主列含 BE）：

| beat | U=68（最坏） | U=76 | U=80 | U=88 | U=103 |
|------|--------------|------|------|------|-------|
| 16 B | 3 | 3 | 3 | 2 | 2 |
| 32 B | 5 | 5 | 4 | 4 | 4 |
| 64 B | **9** | **8** | 8 | 7 | 6 |
| 128 B | **18** | **16** | 15 | 14 | 12 |

**64 B 区间 k∈[6, 9]**（Issue E 合法；平台默认并列 k=8 / 最坏合法 k=9）。
**128 B 区间 k∈[12, 18]**（非法宽度灵敏度）。
**KILL 判定 k = 18（最坏）**。禁止 k=1 主列。规范允许的 Data 宽度是 16/32/64 B（E Table 13-9）以及 F 的 4–64 B；128 B 只因平台冲突而扫。

代数（`models/P-0198/M-5r2/width.py`，UNSIGNED）：

```
C_dat_off = 2
C_snp_off = 1
C_dat_on  = 2 + (1/k) · f_cap     # f_cap≤1，密度帽再削
C_dat_on  < 3                      # 不加第三条 Dat 宽环
T_dat / T_off ≥ 2 / (2 + 1/k)     # 环受限下界；k=8 → 0.941；k=9 → 0.947；k=18 → 0.973
```

最坏 k=18 的环受限下界是 `2/(2+1/18)=36/37≈0.973`，比 64 B 最坏还更接近 1。再扣帽，推理 makespan **看不到 0.85**。

### 1.4 环计数（基线）

平台（已核 `bufferless-ring-noc@63163cad`，`src/TMultiRing.cpp:223-231` / `gen_config.py:308`）：Req **1**、Rsp **2**、Snp **1**、Dat **2**。通道是分开的 `TNetwork` 树，**不共享导线**。每向每 CS 一个 `NetworkFlit*` 槽（`include/TCsHighWay.h:136`）。环周长 = CS_NUM（top 21；bottom H 24/25；bottom V 33/37/38）。

禁止再写 `1+duty_dat`。加宽 Snp 到 Dat 宽 = 加线，本卡禁止；对照「Dat 2→3」支配本卡，不采用。

## 2. 机制（无 epoch）

### 2.1 结构

| 结构 | 容量 | 说明 |
|------|------|------|
| Snp 环 highway | 每向每 CS 1 槽，宽 = 既有 SNP 线 | 本征 Snp **或** ghost fragment；过路赢（`TCsHighWay.cpp:1041-1117`） |
| k 缝合器 / Dat NI | 每拍最多向 Snp 环送 1 个 fragment；**1 深 Dat 宽寄存器** | 1 Dat beat → k 个 fragment；不要求 k 槽连续（不连续靠重组）。只在 **本拍两条 Dat 子环都注入失败** 时溢出到 ghost（不抢更快的本征 Dat） |
| 每节点 ghost 帽 | `G_node`：该节点在 Snp 环上在途 fragment ≤ k（= 1 个 beat） | **硬帽**；含 orbit。多租户再按 src 均分，默认单租户 |
| 目的重组 CAM | 每 Snp NI：`N_src` 项（默认 = 源点数），每项 D bit + 位图 k + 超时计数 | 满：该 dest 不再接收新 fragment，fragment **留环** |
| 1 深转道 holding | 每节点 1 个 **Dat 宽** 寄存器（D bit） | 仅重组完成 → 交给 Dat 消费者；满则 CAM 占住 ready 项，后续片留环。**禁止源端副本** |
| i-tag | 复用平台每 highway 1 活标（`TCsHighWay.cpp:894-950,1094-1103`，阈值默认 64×2） | **ghost 不得在 Snp 环上发 i-tag**；本征 Snp 可发；ghost 必须让出 reserved 槽 |

**没有**：Rebind FSM、epoch_tag、SYNC Drain、`epoch_committed`、4×4 绑定表。header `channel disc` 是唯一身份。

### 2.2 同拍规则

1. 过路 flit 赢（零和）。
2. 槽空且本征 `Snp pending` → 注入 Snp。
3. 槽空且无 Snp pending 且本节点 `inflight_ghost < G_node` 且槽未被 i-tag 预留给他人 → 注入 1 个 ghost fragment（仅当该拍 Dat×2 已满）。
4. ghost **禁止** `tryItagProcess` / `sender_tagged`。
5. 禁止为 Snp 丢在收到 fragment（那是第三槽或队列）。

### 2.3 重组、超时、满

- 键：`(src, txn_id)`。项宽 D，位图 k。项数 `N_src`（减箱 = 源点数；soc_sim 钉与 top 源数同量级，禁止无限 CAM）。
- 满：新 fragment 不弹出，`looped_times++`，计入源节点 `G_node`（源不得再注入，直到该 beat 完成或超时释放）。
- 超时 `T_partial`：钉 `2 · 2 · C_ring`（两圈）。top CS_NUM=21 → 84 拍量级；减箱 N=12 → 48 拍。超时：**丢该 beat 的已收 fragment**（计 `partial_drop`），源靠 CHI 事务层重试——**本卡不在源 NI 留 Dat 副本**。丢 beat 必须进报表；若 completions 暗掉 = 机制失败。
- 收齐 k 片 → 组一拍 Dat，进 1 深 holding；Dat 入口满则 holding 占满，CAM 继续占 ready 项，后续片留环。重组 CAM 与 Dat 入口 credit **解耦**。
- fragment 自身 `hops > 2·2·C_ring` → 丢片（`frag_drop`），同样无源端副本。

### 2.4 NACK / 不弹出：数据从哪来

无 epoch，不再有 bind 失配。仍有「不能交给 Dat 消费者」：

- **在环上**：NACK / CAM 满 / 未到 dest 的 fragment **带着自己那 1/k 的数据绕环**。数据来源是 **该 Snp 槽里的 payload**，不是源端拷贝。
- **缝合器**：源 NI 在序列化这一个 beat 时持有 1 深 Dat 宽寄存器（§5 已计）。k 片全部离开缝合器之后，源端 **立即释放**，不再留副本。
- **原地转道**：当前 CS 把已齐的 beat 从 CAM 搬进 1 深 holding，下一拍交给 Dat 消费者。数据来自 holding 里的那一份。
- holding 满：后续 ghost **留 Snp 环**，禁止丢、禁止加第二深、禁止回源再取。
- e-tag：挂在 **Snp NI 本向**（`TReserveState`，默认 1 reserved、`etagReserveCycle=10`）。ghost 用同一套 reserved 位弹出到重组口，不抢 Dat NI 的 e-tag。ghost 不得自己打 i-tag。

### 2.5 跨通道循环依赖

CHI 分通道是为了 Snp 不依赖 Dat。缝合后可能的环：Dat 入口满 → 事务等 Snp → Snp 上不了环（orbit ghost）→ ghost 出不了（Dat 入口满）。

结构性保底（不是 i-tag 阈值）：

1. `G_node ≤ k` 且 orbit 计入帽 → 单源无法用列车填满下游。
2. 本征 Snp 弹出走 Snp NI，**不**进 Dat 入口。
3. 每段空槽在「无 Snp pending」时才给 ghost；有 Snp pending 则该空槽是 Snp 保底。

i-tag 只保证终会注入，不保证 ≤1.4；帽才是 1.4 的候选界。

### 2.6 15:1 推理混合（钉死，作者不得事后改）

推理（decode KV/P2P + 推理集合）是主负载。训练不单独过关。

**15:1 = 并发提供的 Dat beat : Snp flit = 15:1**，不是 epoch duty，也不是平台 catalog 里「7680 B:512 B 尺寸比、两次 run 顺序执行」。

| 成分 | 比例 | 图案 | Snp 源位置 |
|------|------|------|------------|
| Dat A | 提供 Dat beat 的 **75%** | kv_decode 型扇入（多源 → 单 sink，代理 gather / decode KV） | — |
| Dat B | 提供 Dat beat 的 **25%** | weight_reread 型均匀 P2P | — |
| Snp | 每 15 个 Dat beat 插入 1 个本征 Snp | 目录嗅探，单 flit，无 Data | **必须在热 ghost 路径下游**（扇入 sink 的最后一跳：减箱节点 1 与 N−1） |

事务粒 512 B。64 B beat → 8 Dat beat/txn；128 B → 4 beat/txn。Snp 另扫 λ∈{0.05, 1/16, 饱和}；主 KILL 列用 15:1。soc_sim 默认 TrafficGen **不发 Snp**，评估必须新写发生器（§6）。

## 3. 为什么（不）有效

相对无 CC（Dat×2、Snp×1、额外 FC 关）：Snp 环空槽在帽下可运 1/k 的 Dat。k≥8 时环受限加速 ≤6%。密度帽再削。推理 KV 扇入还受 dest eject 限制——r1 的 0.569 是双环无限 eject + 假 k=1 伪影，本卡禁止。

相对源端 FC：FC 不增加 Dat 槽；本卡理论上 +1/k 槽，k 大时与「几乎没加」不可分。

相对 M-5 / M-5r1：排他窗已删（那是 Snp 17× 的真因）。r1 的 epoch 已证伪。本卡不假装还在做通道–环重绑。

**header-only / drain-off 判决（明文）**：本卡 **就是** header-only。没有 Drain 可关。T1 已测 r1 与 header-only 等价。r2 的 `header-only` / `drain-off` 臂必须与 `stitch` **逐数字相同**（构造上同一条路径）。若有人把 r2 再画成 CRRF 世代机，那是撒谎。

## 4. 评估计划

- 信封：DV200 12+2；ost 读 512 / 写 256；禁完美预测 / 无限带宽。
- 主列：推理 makespan 与尾（kv_decode + P2P + 推理集合）。训练不单独过关。
- 基线：stitch-off（= 无 ghost = 无 CC）；源端 FC（只削 Dat ost）；**禁止** k=1 主列。
- 消融：`cap-off`；`itag-ghost-on`（非法，必须比合法臂更糟或持平）；`k1-cheat` 只对照并标 `FAKE_WIDTH`；**drain-off / header-only = 本卡本身**（必须同表印出恒等）。
- **KILL（不变）**：15:1 下 `T_snp/T_snp(stitch-off) ≤ 1.4` 且 `<1.5625`，**snp_path 与推理混合各自**满足；不平均；不用 Dat 抵扣。另：推理 Dat makespan **r≈1（无缩短）即淘汰**（上周规则 2）。最坏 k=18 判定；k=8/9（64 B）只并列。
- `snp_path` 无 Dat ⇒ 比值 **构造为 1**——必须标注，不得当「机制赢了」。
- p99 / 多种子；按 Snp 源位置分列。只涨 `p_inj` 不算。

## 6. 已知限制（平台，不得假装不知道）

1. **假 k=1**：`tests/esl_wrapper/compat/chi_common.h:92-118` 四通道共用 `CHIFlitFields`，无 Data/BE/DataID。真实 CHI ABI 在缺席的 `chi_interface` IP。库内任何 flit 占 1 槽 = 静默 Snp=Dat 宽。本卡主列禁止用这个假 k。
