# M-8: CHI 信道亲和与集合相位钉扎

- problem: P-0198
- author: 保守架构师
- style: conservative / implementable

## 1. 根因分析

冻结信封：CHI 四通道 `Req/Rsp/Snp/Dat` **各自独立成环**，每环每方向每拍仍只有 1 个 highway 槽。事务类型到物理环的映射若只按 CHI 通道字面（读请求走 Req、数据走 Dat），则两种 LLM 形态会在 **同一争用域** 里叠加：

- 形态 (1) 点对点 / 近均匀：权值重读、KV 扫描、激活分片读写——大量短事务打满 Req/Rsp，Dat 随完成返回。
- 形态 (2) 集合：broadcast / gather / reduce / allgather / allreduce / alltoall——扇入扇出的大 payload 突发打在 Dat（及完成所需的 Req/Rsp），并在 RBRG 端口与形态 (1) 汇合。

四环在拓扑上正交，但默认映射 **没有** 把两种形态钉到不同的环/相位资源上。集合 Dat 突发与 P2P Req 饱和仍通过共享 endpoint 与 RBRG 口耦合：一个环上的过路占满会经 RBRG 把 `inject-fail` 传播到另一环，拉伸全局 makespan。基线已显示形态不可互换：均匀读峰值后崩到 2.8–3.4 TB/s，写平台约 5.5 TB/s；broadcast（8192 B、OQ 4096）可维持约 117.76 B/ns，其它集合在公开扫描下大量 `collapsed=true`。把两类压成一条均匀流，或只报均匀读峰值 goodput，等于取消问题。

本卡是 **路由/亲和与集合相位钉扎**，不是源端速率、token bucket、ECN、窗口或 tag 策略。平台 `--cc-scheme srcfc|ecn|tagwin|…` 是对照，不是本机制。

## 2. 机制

### 结构

在每个 die 的 CHI 口与 RBRG 口各加一张可编程亲和表，把 `TrafficClass` 译到「用哪条 CHI 环、在哪个集合相位允许出 RBRG」。默认表复现今日字面映射，使 off 臂可复现基线。

1. **TrafficClass 编码 `TC[3:0]`**（16 类，软件/流量发生器给出；也可由 CHI opcode 硬线映到复位表）：

   | `TC` | 复位含义（可改 CSR） |
   |------|----------------------|
   | 0 | P2P 权值重读 |
   | 1 | P2P KV 扫描 |
   | 2 | P2P 激活分片读 |
   | 3 | P2P 激活分片写 |
   | 4 | 均匀读（基线对照类） |
   | 5 | 均匀写 |
   | 6 | broadcast |
   | 7 | gather |
   | 8 | reduce |
   | 9 | allgather |
   | 10 | allreduce |
   | 11 | alltoall |
   | 12–15 | 保留 / 实验 |

2. **亲和表 `AFF[16]`**：每 die 一份，16 项 × 4 bit = 64 bit CSR。每项字段：
   - `ch[1:0]`：目标 CHI 环 `{Req=0, Rsp=1, Snp=2, Dat=3}`。复位：P2P 读类 → Req，P2P 写数据 / 集合 payload → Dat，完成/响应类 → Rsp，Snp 保持 Snp（本问题缓存一致性出范围，Snp 环仍建模但负载应接近空）。
   - `ep[1:0]`：集合相位钉 `{0..3}`，见下。P2P 类复位 `ep=0`（任意相位可过 RBRG）。

   推荐可编程钉扎（评估默认 on 表，不是唯一解）：allreduce / reduce-scatter 类 payload → `Dat` 且 `ep=1`；alltoall → `Dat` 且 `ep=2`；broadcast / allgather 扇出 → `Dat` 且 `ep=3`；权值/KV/激活 P2P → `Req`/`Rsp` 且 `ep=0`。软件仍可把某类改回默认字面映射做消融。

3. **集合相位 CSR `CPHASE[2:0]`**：每 die 一份，3 bit，每拍或每完成一个集合 epoch 由控制面 `+1 mod 8`（复位每 `E_COL=8` 个环拍自增 1，CSR `E_COL_SEL` 1b：0→每 8 拍，1→每 16 拍）。`phase_now = CPHASE[1:0]`（低 2b 为当前钉，最高 1b 预留扩展）。本卡 **不** 用 `CPHASE` 做窗口限速；它只决定「当前允许哪组 `ep` 使用 RBRG 口」。

4. **RBRG 口使能掩码 `RBEN[7:0]`**：每桥一份，8 bit。bit `i` 对应「相位 `i mod 4` 的偶数/奇数半拍槽」或更简单：`RBEN[3:0]` 对应 `ep=0..3` 是否允许本桥本拍 grant，`RBEN[7:4]` 复制给另一方向。复位 `8'hFF`（全开）。钉扎生效时，软件把 `RBEN` 写成与 `CPHASE` 同步的独热/双热：例如 `ep==phase_now` 的 bit=1，避免 alltoall 波与 allreduce 收尾在同一 RBRG 口重叠。

5. **译码 mux**：`ch = AFF[TC].ch` 替代既有 CHI 通道选择（1 个 16:1 的 2b mux）。`rbrug_ok = RBEN[{dir, AFF[TC].ep}]`（`dir` 1b 拼成 3b 索引，或用 `RBEN[AFF[TC].ep]` 两向共用）。`rbrug_ok=0` 时桥侧 CTRL stall（见 M-9 的 Hold 语义可复用，但本卡只提供使能位；若未实例化 M-9，则 stall 停在既有 NI credit/staging，**仍禁止** 织物多 flit 队列）。

本卡不改 highway 槽数，不在源端扣 token。

### 容量 / 端口 / 位宽

| 结构 | 容量 | 端口 | 位宽 |
|------|------|------|------|
| `TC` 标签 | 每待注入 header 4 bit（伴随既有 staging） | 1R/拍 | 4b |
| `AFF` CSR | 16×4b = 64 bit / die | 1R 组合 + 1W CSR | 每项 `ch` 2b + `ep` 2b |
| `CPHASE` | 3 bit / die | 1W 自增 / 1R | 3b；有效钉 2b |
| `E_COL_SEL` | 1 bit / die | 1R1W | 0→8 拍，1→16 拍 |
| `RBEN` | 8 bit / RBRG 口 | 1R/拍 + 1W CSR | 8b 掩码 |
| 通道 mux | 0 | 16:1 | 2b `ch` |
| 口使能 | 0 | 组合 | 1b `rbrug_ok` |

14 die × 64b `AFF` = 896 bit CSR；RBRG 口按 2 bottom × 每 bottom 最多 4 个通道桥估算 ≤ 8 份 `RBEN` = 64 bit。无 SRAM，无按 flit 的 CAM。占用指标只定义一种：`O_ch,d(t)∈{0,1}` 为通道 `ch` 方向 `d` 的 highway 槽占用，跨卡不得另发明第二套「当量占用」。

### 数据路径与状态机

每拍待注入 / 待过桥：

1. 取 `TC`（流量发生器或 opcode 表 `OPMAP`：CHI opcode 7b → `TC` 4b，16 项复位 ROM，可 CSR 覆盖）。
2. `{ch, ep} = AFF[TC]`。
3. 本地注入投递到环 `ch` 的既有 highway 口（其余环看不到这次请求）。
4. `CPHASE` 按 `E_COL` 自增；`rbrug_ok = RBEN[ep] AND (ep == phase_now OR AFF 的 P2P `ep=0` 旁路)`。P2P 旁路位 `P2P_BYPASS` 1b CSR，复位 1：`ep=0` 的类任何相位都可过桥，避免把形态 (1) 误钉死。
5. `rbrug_ok=0`：桥 CTRL stall，header 留在 NI/桥控制级；在途过路 flit 不受影响。
6. 无额外状态机。`CPHASE` 是自由运行计数器，**禁止** 用全局集体完成预言或无限带宽假设来推相位。

时序：`AFF` 16:1 × 4b 与 opcode 译码并行，目标同拍选出 `ch`；过桥使能可寄 1 拍（与 header 对齐）。

## 3. 为什么有效

四条 highway 是正交的零和资源。默认映射把两种形态的突发叠在同一 `(ch, 方向)` 的单槽上，等效于把两个到达过程塞进 `μ=1 slot/cycle` 的同一服务台。亲和把形态 (1) 的控制/短事务与形态 (2) 的 payload 尽量分到不同 `ch`，使 `O_Req` 与 `O_Dat` 不再同步饱和。

相位钉扎进一步把 **同通道内** 的集合波错开：alltoall 与 allreduce 收尾若共享 RBRG 口，桥上单槽变成第二处零和。`CPHASE`+`RBEN` 把该口的 grant 按 `ep` 切片，污染半径停在一个相位（`8` 或 `16` 拍），而不是一次 collapse 灌进所有环。

Amdahl：仅当 makespan 中「跨形态同槽争用 + 同口集合重叠」占比为 `f_x` 时，本卡加速上界 `1/(1−f_x)`。若评估只跑单一形态，`f_x≈0`，不得宣称收益。Little：集合屏障 `T ≥ L_straggler / λ_bridge`；钉扎提高的是 straggler 在桥上的有效 `λ`，不是平均利用率。

本卡不增加槽数、不加织物队列。轻载下错误的独热 `RBEN` 会让 P2P 空等相位——因此必须保留 `P2P_BYPASS`，并在评估中报「只开亲和、关闭相位钉」与「两者都开」。

## 4. 评估计划

### 基线

1. 公开基线：12+2、512 B、AIC RO 512 / WO 256、流控 OFF；通道映射 = 平台默认字面 CHI。
2. 对照：`--cc-scheme srcfc`、`ecn`、`tagwin` 等。本卡开/关 × 各对照。亲和表不是窗口/tag 限速。
3. 消融：
   - B0：`AFF` 恒等默认，`RBEN=0xFF`，`P2P_BYPASS=1`（off）。
   - B1：只改 `AFF.ch`（通道亲和），相位全开。
   - B2：B1 + `CPHASE`/`RBEN` 钉扎。
   - B3：B2 但 `P2P_BYPASS=0`（应观察 P2P 回归）。
   若 B1/B2 与 B0 的每类 makespan 不可分，禁止写因果（约束 1）。不得用两类平均加速比过 0.85 冒充每类过线。

### 必须 cycle 级建模的结构

- 每 die 64b `AFF`、3b `CPHASE`、1b `E_COL_SEL`、1b `P2P_BYPASS`。
- 每 RBRG 口 8b `RBEN` 与 1b stall。
- opcode/`TC` → `{ch,ep}` mux，接入既有 CHI 通道选择。
- **必须同时注入形态 (1) 与形态 (2)**（并发工作集，不是两次单类回放拼报表）。
- **不要** 建源端 token/ECN/tag 机作为本卡部件；不要为亲和加织物队列。

### 指标与负载

Full envelope：12+2 DV200、CHI 四环、有限链路延迟、有限 outstanding。并发负载例（须在报告中写死配比，禁止事后用未声明 `p_mix`）：50% 事务数为 P2P（权值/KV/激活或均匀读+写各半），50% 为集合全集轮转；另报纯 P2P、纯各集合作为分解，但 **过线判定只看并发信封 + 每类 endpoint**。

Endpoints：每类 makespan、完成 txn 数、collapse 标志。0.85 是每类 pass bar，不是 measured mean。Proxy：各环 `O_ch,d` 时间平均、RBRG stall 拍数、inject-fail。单环注入成功或均匀读峰值 goodput ≠ endpoint。

读写不对称与集合扇入/扇出必须都出现在并发信封里。Reduced-bbox（单环、top 子集、只均匀读、完美预测、无限 BW）≠ full envelope。

### 预期收益区间与置信度

并发信封下，集合类 makespan 相对 B0 预期 **8%–30%**（B2 相对 B0），且仅当 B1 或 B2 已与 B0 可分；P2P 类预期 **0%–15%**，B3 允许 P2P 变差，变差 >10% 则不得推荐关掉 bypass。不预期单独把均匀读崩塌区拉回 5761 B/ns。只跑单类时预期接近 0%——那是 reduced-bbox，不能冒充本卡收益。

置信度中偏低：正交环隔离在结构上成立，RBRG 耦合占比未知。不宣称 T0 通过。

## 5. 硬件开销估算

面积：每 die 64b SRAM-less CSR + 16:1 mux + 3b 计数器，14 die + 每桥 8b，估计 **<2.5 kGE**，0 SRAM。功耗：每注入一次表读 `<0.02 pJ/bit×4`。延迟：通道选择 0 拍或 +1 拍对齐；过路路径不经过 `AFF`。不增加 highway 槽、不加缓冲。
