- Domain tag: in-memory computing / on-chip training / FeFET
- One-line hardware fact (from p.1–3 only): eNVM crossbar training accelerator (FeFET-calibrated) with peripheral reuse for forward/backward dataflow reverse, plus a training rule that steers weights toward conductance-stable regions under NL/asymmetry/C2C/D2D.
- Reading scope: **PDF pages 1–3 only** (through non-ideal weight-update motivation). Methods/eval unread by design.

## 四视角独立批评

### 微架构

Visible structures by p.3: eNVM array doing MVM (forward) and MTVM (backward) with DAC/ADC; need **dataflow reverse** hardware so the same array serves W and Wᵀ (p.3); two update styles named — in-situ outer-product pulses vs explicit ΔW then write (p.3). FeFET CuInP₂S₆/MoS₂ heterostructure is fabricated and curve-fit (p.2). What is missing on p.1–3: array size, ADC precision, how "single set of peripheral circuits" actually muxes directions, endurance budget. Mechanism vs algorithm: much of the claimed accuracy gain is attributed to NAT (algorithm), not a new bitcell.

### 负载

Benchmarks named only as VGG6 / VGG11 / ResNet18 in the outline (p.2); CIFAR10 + VGG8 appear as prior-art citation context (p.3). No LLM, no large embedding tables. On-chip training here means classical CNN training under device physics — fine for IMC literature, narrow for "AI training" marketing.

### 仿真方法学

Claims: under severe asymmetry, **+15.1%** accuracy vs baselines; **~33.58×** energy efficiency vs GPU peak (abstract/p.2). Table I compares prior IMC training papers on whether they model NL/D2D/C2C and weight-distribution linearity (p.2). Device model is experimental FeFET I–V fit (p.2). No GPU SKU, no array dimension, no Monte Carlo count on p.1–3. Eqs. (5)–(7) give the NL LTP/LTD model (p.3) — good, falsifiable.

### 工业可行性

On-chip training on eNVM still fights endurance, verify-write energy, and fab-specific FeFET stacks. Intro admits process-optimized linear devices ([28],[29]) are fab-locked (p.2). A product path needs: pulse-verify protocol, retention under temperature, and whether "steer to stable region" shrinks usable conductance dynamic range enough to hurt model capacity. Not answered in first three pages.

## Master Class

1. **The Real Abstract** — Train on eNVM crossbars despite nonlinear/asymmetric conductance and C2C/D2D noise by (a) building a FeFET-calibrated accelerator that reverses dataflow for backprop, and (b) an update policy that keeps weights out of the worst conductance regions. Headline +15.1% accuracy / 33.58× vs GPU peak efficiency (p.1–2).

2. **The Rashomon Synthesis** — Microarch wants the reverse-dataflow peripheral; algorithm people want NAT; tools want the FeFET model card; industry wants endurance. Shared premise: ignoring NL/asymmetry makes published IMC training numbers unreproducible (p.1–2).

3. **The Magic Trick** — Stop fighting non-ideality with ever-more-linear devices; move weights to where the device is already well-behaved.

4. **The Skeleton in the Closet** — Accuracy wins may be mostly algorithmic (NAT); hardware novelty on p.1–3 is thin beyond FeFET model + bidirectional peripherals; GPU efficiency comparison baseline unspecified in the opening.

5. **可提取的问题线索**（仅 p.1–3，有数字，无机制名）

1. 冯·诺依曼机算存分离使训练中权重/激活频繁搬运，带来显著延迟与能耗（memory wall）。(p.1)
2. 理想权重更新要求电导变化与目标增量近似线性；实际新兴非易失单元的电导调制呈高非线性与不对称，使同幅更新落到偏离目标的电导态，拉低训练精度。(p.1)
3. 大规模阵列写入存在 cycle-to-cycle 与 device-to-device 波动，误差在阵列上累积，破坏权重更新精度与收敛稳定性。(p.1)
4. 仅靠“更线性的器件工艺”缓解非理想性会绑定特定先进制程与材料，可移植性差。(p.2)
5. 把非理想模型塞进噪声感知训练、靠网络鲁棒性被动容忍的做法，强烈依赖器件线性度；线性度变差时易出现收敛困难与精度崩溃。(p.2)
6. LTP/LTD 中电导常在脉冲初期快速变化、随后饱和，偏离与脉冲数成正比的理想直线（可用参数 A 刻画非线性强弱）。(p.3)
7. 在阵列内用同一物理阵列加速反传时，需要的是权重矩阵的转置数据通路；与前向相比，反传要求额外的硬件支持来反转数据流方向。(p.3)
