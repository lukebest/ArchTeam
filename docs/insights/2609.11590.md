# 2609.11590: CHERI-D Reincarnate — efficient multicore CHERI temporal memory safety through allocation reincarnation (draft) (first-3-pages note)

- arXiv: [2609.11590](https://arxiv.org/abs/2609.11590) · PDF: [arxiv.org/pdf/2609.11590](https://arxiv.org/pdf/2609.11590)
- Venue: arXiv preprint (cs.AR / cross-list as applicable) — marked draft version
- Domain tag: capability temporal safety / multicore metadata coherence
- One-line hardware fact (from p.1–3 only): architectural extension that reincarnates allocation slots under new IDs (quarantine IDs, not memory), extends ID protection toward large objects (modes to 1 GiB), and keeps private ObjID buffers coherent across cores via reverse-map/filter tied to coherence/L1 events. Claimed overheads 1.7% SPEC INT / 0.7% SQLite / 0.3% PARSEC.
- Reading scope: **PDF pages 1–3 only**. Methods/eval unread by design where they begin after p.3.

## 四视角独立批评

### 微架构

Capability fields on p.3: 8-bit ID, 3-bit IDMODE, 6-bit IDLOC; ID 0 reserved for immortal allocator caps. Reincarnate the slot when the current ID exhausts; quarantine exhausted IDs for later sweep/reclaim. Eight ID modes (Table 1) from <63 B region-relative through 128 MiB–1 GiB top-relative. Multicore: private virtually addressed ObjID buffers synchronized by reverse-map/filter on existing coherence invalidations and L1 replacements; no fence instruction promised.

### 负载

Long-running allocation-intensive heaps. Named suites on p.2: SPEC CPU2006 INT, SQLite, PARSEC, NIST Juliet, MSET. SQLite is the scan-frequency anecdote: Cornucopia Reloaded baseline 267 memory sweeps vs none claimed for the proposal. Prior ID schemes evaluated single-core only.

### 仿真方法学

HW/SW co-design: CHERI-Toooba FPGA softcore, QEMU, LLVM/Clang, CheriBSD, MRS, jemalloc. Comparison frame is Cornucopia Reloaded (quarantine+sweep) plus Picasso / CHERI-D. Sweep counts and %-overheads appear as intro claims; FPGA/QEMU methodology after p.3 unread.

### 工业可行性

CHERI-only ISA/software stack; user-space heap only (kernel/stack left future). Needs capability-encoding bits and allocator/MRS cooperation. FPGA softcore ≠ product core; draft paper. Centralized ID tables (Picasso) are the rejected alternative on metadata locality.

## Master Class

1. **The Real Abstract** — Exhausting an identity need not exhaust the memory: quarantine IDs, reincarnate the slot, and keep per-core ObjID caches coherent off existing snoop/L1 events.

2. **The Rashomon Synthesis** — Temporal safety wants dangling capabilities dead now; allocators want immediate reuse and no quarantine tax; multicore wants a VA metadata buffer that still tracks PA coherence.

3. **The Magic Trick** — ID reincarnation (quarantine IDs, not pages) plus reverse-map/filter so private ObjID buffers follow coherence/L1 events without a central table.

4. **The Skeleton in the Closet** — 267 is the baseline sweep count, not a new measurement of the proposal; 1 GiB modes and IDLOC encodings start on p.3; kernel/stack out of scope; draft.

5. **可提取的问题线索**（仅 p.1–3，有数字，无机制名）

1. 能力可被自由复制，对象释放后仍可能可达，时间安全比空间安全更难；已部署的基于隔离区+地址空间扫描回收的方案会推迟重用，并拖累分配器优化、内存占用与缓存效率，叠加扫描成本后系统开销可难以接受。(p.1)
2. 有限位宽、与分配槽静态绑定的代际标识在标识耗尽时会被迫把整块内存放入隔离区；先前方案主要覆盖小于约 4 KiB 的对象，而大对象不成比例地贡献隔离浪费并主导不少应用。(p.1)
3. 既有时间安全方案多在单核评估；多核下私有、按虚地址组织的对象标识缓冲难与物理一致性事件同步。(p.1–2)
4. 在 SQLite 一类分配密集负载上，基于隔离+扫描的基线可产生数百次内存扫描（文中对照为 267 次），说明长时间运行下扫描频率与隔离占用是一阶痛点。(p.2)
5. 需要把时间元数据与被保护内存共址以保局部性，又要避免集中式元数据结构，同时把标识耗尽与内存隔离解耦，使常见路径可立即重用底层内存。(p.1–2)
