## 四视角独立批评

### 微架构

CV SoC 前端（传感器+ISP）与后端（CPU/GPU/NPU）可跨帧流水，但单帧仍受传感→处理串行交接约束。先验全帧投机要像素合成与额外推理引擎；纯运动外推则关键帧仍堵在满后端路径。前三页结构主张：投机与外推全部落在运动域——ISP 内嵌轻量单元，用二阶自回归在已有块运动向量上预测未来 MV；调度上把运动外推当默认、满后端推理周期性异步做漂移校正；可选前端降采样省传感能量。反向工程：MV 预测器面积/延迟、关键区域校验阈值、与现有 ISP ME 流水的插入点——未读完。

### 负载

安全关键 AD 常需端到端 **<100 ms**，XR **<50 ms**；移动端能量紧、传感器分辨率/帧率上升。作者定义 Slack / Balanced / Overload 三区：Slack 时前端主导时延与能耗；Balanced 时后端优化直接兑现；Overload（如高精度检测 **30 FPS**）下有界“只留最新”队列频繁丢帧。尾时延取队列深度 1、单处理单元下的 P99。负载审稿人还要：真实 AD/XR 轨迹 vs 目标检测代理、运动可预测性分布、相机曝光与 ISP 配置——前三页以体制分类与先验对照为主。

### 仿真方法学

Abstract：目标检测上最高约 66.8% 尾时延下降、约 46% 能耗节省，精度代价小——unpaid。前三页方法元素：对照 Baseline / Motion Extrapolation（Euphrates 类）/ Prior Speculation（PVF 类）的时序图（Fig.2）；帧时延与信息传播时延二分；P99 尾时延定义。完整数据集、能耗模型与面积开销 unread。勿把 abstract 百分比当作已付清。

### 工业可行性

命题是“在商品 CV SoC 上用 ISP 侧轻量扩展替代像素域投机与专用推理引擎”。工业墙：ISP 供应商是否开放 ME 旁路与寄存器；二阶预测在剧烈运动/遮挡下的安全认证；漂移校正周期与功能安全（ASIL）的关系；相对 Euphrates/PVF 的软件栈改动量。前三页强调复用既有 ME、无额外 NPU，产品叙事清晰，但硅面积、驱动与认证路径未给。

## Master Class

1. **The Real Abstract** — Mobile CV needs sub-100 ms (AD) / sub-50 ms (XR) e2e latency under tight energy. Pipelined SoCs still serialize per-frame sensing→processing; full-frame speculation is expensive to miss, and motion extrapolation still stalls on key-frame full backends.

2. **The Rashomon Synthesis** — Speculative-vision people predict pixels; motion-extrapolation people warp prior outputs; ISP people already emit block MVs. Leftover: speculate *in the motion domain* before frame arrival, and keep full inference off the critical path as drift correction.

3. **The Magic Trick** — Predict future MVs with a light ISP extension on existing ME; default to motion extrapolation; run full backend periodically/async for drift; optionally scale frontend sampling when motion is stable.

4. **The Skeleton in the Closet** — 66.8% / 46% unpaid; object-detection proxy for broader CV; predictor HW cost and safety validation unread on p.1–3.

5. **可提取的问题线索**（仅 p.1–3，有数字，无机制名）

1. 连续视觉（CV）在 AD / AR·VR·XR 等场景要求严格端到端时延：AD 常需 **<100 ms**，XR 常需 **<50 ms**；同时移动端能量预算紧，高分辨率高帧率传感器进一步加压。(p.1)
2. 现代 CV SoC 虽可在不同帧上流水前端（传感器+ISP）与后端（CPU/NPU），但**单帧**时延仍受传感→处理串行交接约束，捕获与处理整体仍呈串行主导。(p.1)
3. 全像素域投机（预测未来整帧再跑后端）：需要整帧像素合成与额外算力（NPU/GPU），误预测强制在真实帧上重跑，抬高能耗与复杂度；为省电关闭前端时还会出现无新鲜传感器数据的空窗。(p.1)
4. 仅用 ISP 运动向量外推感知结果：能量与平均时延更好，但关键帧仍付满后端时延；丢帧时外推结果可能延迟或中断。(p.1)
5. 现成 ISP 已在 **8×8** 或 **16×16** 像素块粒度生成运动向量——信号已在前端产生，但基线流水线并未把它变成“帧到达前”的投机原语。(p.1–2)
6. 帧时延=传感开始→语义处理完成；信息传播时延=新场景内容首次到达输出。尾时延取有界“只保留最新、丢弃最旧”、队列深度 **1**、单处理单元设定下的 **P99** 传感→任务完成时间。(p.2–3)
7. Slack 工况：后端在下一帧到达前轻松完成；多数时延与能耗来自前端（曝光、读出、MIPI CSI、ISP），后端优化边际变小。(p.3)
8. Balanced 工况：后端完成时刻紧贴下一帧到达，后端优化可直接转化为可感知的时延与能效收益。(p.3)
9. Overload 工况：后端远超帧间隔，有界流控不断覆盖队列中帧→频繁丢帧、时间分辨率与响应性下降；高精度目标检测 **30 FPS** 等负载常把移动平台推进该区。(p.3)
