## 四视角独立批评

### 微架构

主张不是「再做一个只吃稀疏加的脉冲阵列」，而是承认 SOTA 音频 SNN（如 Spiking-FullSubNet）推理需要**异构算子混合**：尖峰层可走纯加，编码层要矩阵乘，泄漏/门控要逐元素乘，外加 Multi-Frame Deep Filtering 的复数滤波乘加。结构线索（p.1–3）：稀疏感知柔性/异构 PE 阵列（同一物理 Hybrid PE 时分复用到门控 MAC→sigmoid LUT→膜电位更新等阶段）+ 事件驱动权重读路径（地址译码把活跃神经元索引映射到权重地址，参数存储器只向 PE 供应活跃事件所需权重）。反向工程：PE 复用相位边界与流水气泡、BRAM 参数存储相对片外 DRAM 的切分、活跃索引编码宽度与稀疏度塌陷时的吞吐——均在未读节。

### 负载

动机负载是智能手机 / 无线耳机 / 助听器上的**音频去噪**，电池与 SRAM 紧约束。前三页硬数字（Intel N-DNS Challenge 代理口径，Table 1）：ANN 基线如 Microsoft NsNet2 **12.51 µJ**、Fast FullSubNet **0.09 mJ**；SNN 侧 Spiking-FullSubNet-XL（Winner）**965K FP32** 参数、SI-SNR **15.20 dB**、能量代理 **1.48 µJ**；DPSNN **1.08 µJ** / **14.70 dB**。引言强调 ANN 的稠密 MAC + 大内存与耳机类 SoC 不匹配；SOTA SNN 虽稀疏，但仍要求硬件同时支持多种算子才能兑现功耗收益。p.3 指出 FP32 权重约 **4 MB** 对助听器/蓝牙耳机类低功耗 SoC SRAM「不可行」。负载审稿人还要：32 ms 帧率下的实时裕度分布、噪声场景覆盖、稀疏度随语料的方差——完整评测 unread。

### 仿真方法学

前三页方法元素：Intel N-DNS 操作数能量代理（文给 \(P_{\mathrm{proxy}}=\mathrm{SynOps}+10\times\mathrm{NeuronOps}\)；45 nm 模型脚注 4.6 pJ/FP32 MAC、0.9 pJ/AC）；另有 45 nm / 0.9 V 下 INT8 乘 0.20 pJ、INT32 加 0.10 pJ 的定制硅估算口径；FPGA 侧 PYNQ-Z1、100 MHz、RTF 0.727。Abstract 的 52.9 nJ / ≈28× 与 Table 1 一致方向，但**代理能量 ≠ 测得 FPGA 能量**，文亦承认未显式计入操作数精度、LUT 访问、逐通道 requant、访存成本。完整门级/后仿与 iso-accuracy 功耗拆解 unread。勿把 52.9 nJ 当作已付清硅测。

### 工业可行性

命题是「用稀疏感知柔性 PE + 事件取权，把音频 SNN 的异构算子与稀疏性一起吃掉，落在耳机/助听器功耗包络」。工业墙：代理 µJ/nJ 到真芯片漏电与 SRAM 编译的落差；Hybrid PE 时分是否锁死 Spiking-FullSubNet 族拓扑；INT8 QAT + 去 BN / 激活简化后的产品听感与认证路径；PYNQ-Z1 验证相对定制 45 nm 的带宽/存储层次是否可迁移；与既有听感 DSP/ANC 管线的接口。前三页产品叙事清晰（边缘、nJ 级代理），流片与软件栈未给。

## Master Class

1. **The Real Abstract** — Edge audio denoisers must run under battery and tiny-SRAM budgets, but ANN denoisers burn dense MACs and large FP32 footprints, while SOTA SNNs that look “sparse” still need matrix-mul encoding, element-wise leakage/gating, and multi-frame filtering—so add-only neuromorphic arrays cannot actually host the winning models (Spiking-FullSubNet-XL still sits at ~1.48 µJ proxy / ~965K FP32 on Intel N-DNS).

2. **The Rashomon Synthesis** — Algorithm people see spike sparsity and gated-spiking neurons; accelerator people see a homogeneous MAC array that stalls on non-MAC phases; edge-audio people see 32 ms frames and hearing-aid SRAM that cannot hold a 4 MB weight image. Leftover: one flexible PE fabric time-multiplexed across the heterogeneous op mix, plus weight fetch gated by active-neuron events.

3. **The Magic Trick** — Sparsity-aware flexible/heterogeneous PE array (same Hybrid PE time-multiplexed across matrix-mul / pure-add / element-wise mul and Multi-Frame Deep Filtering phases) + event-driven weight-read memory (active-neuron index → weight address; skip inactive DRAM/PE work); HW-friendly SFSN via QAT/activation simplification is the co-design enabler, not the microarchitectural claim.

4. **The Skeleton in the Closet** — 52.9 nJ / ≈28× / RTF 0.727 unpaid as measured silicon energy on p.1–3 (proxy + FPGA latency narrative); full PE schedule, memory hierarchy sizing, and iso-quality listening tests unread; “custom 45 nm” numbers are cost-model estimates, not post-silicon.

5. **可提取的问题线索**（仅 p.1–3，有数字，无机制名）

1. 智能手机、无线耳机与助听器等边缘设备需在**严重电池功耗约束**下运行音频去噪神经网络，用户仍期望长续航。(p.1)
2. 传统 ANN 去噪模型计算与访存沉重：依赖大量**稠密 MAC** 与较大内存资源，难以部署在无线耳机类高约束 SoC 上。(p.1–2)
3. 即便改用高激活稀疏的 SNN，许多 SOTA 模型仍要求硬件同时支持**多种算子混合**才能完整推理——尖峰层可走纯加，但编码层常需**矩阵乘**，泄漏/门控项常需**逐元素乘**，而非「只加即可」。(p.1 Abstract / §1–2)
4. 在 Intel N-DNS Challenge 操作数能量代理口径下，竞赛获胜的 Spiking-FullSubNet-XL 仍达约 **1.48 µJ**/帧量级，参数约 **965K（FP32）**，SI-SNR **15.20 dB**；同表 ANN 基线 Microsoft NsNet2 约 **12.51 µJ**，Fast FullSubNet 约 **0.09 mJ**。(p.2 Table 1)
5. FP32 权重量级约 **4 MB** 时，对助听器 / 蓝牙耳机类低功耗 SoC 的 SRAM 容量而言被作者称为**不可行**量级（同页亦给出量化后 dual 的对照叙事，此处只保留问题侧 4 MB 不可行）。(p.3)
6. 该类音频 SNN 的计算模式高度**异构**（矩阵乘 + 纯加 + 逐元素乘 / Multi-Frame Deep Filtering），与「主要面向同构 MAC」的常规神经网络加速器假设不匹配。(p.3)
7. 去噪需按音频帧推进（文以 **32 ms**/帧为能量叙述单位），边缘部署还隐含**实时**约束；仅降低操作数代理并不足以保证在可行时钟下跟上帧率。(p.1 Abstract)
