# 2609.07175: Enabling High-Bandwidth Flash for Generative Recommendation Serving with Write-Aware KV Cache Policy (first-3-pages note)

- arXiv: [2609.07175](https://arxiv.org/abs/2609.07175) · PDF: [arxiv.org/pdf/2609.07175](https://arxiv.org/pdf/2609.07175)
- Venue: IEEE preprint (cs.AR)
- Domain tag: HBF memory system / GR KV cache
- One-line hardware fact (from p.1–3 only): GR serving device: 1×HBM4 for hot intermediates + 7×HBF stacks for weights & user KV; HBF ≈512 GB/stack, 1.6 TB/s read, 48 GB/s write; policy is admission-controlled LRU-K.
- Reading scope: **PDF pages 1–3 only**. Methods/eval unread by design where they begin after p.3.

## 四视角独立批评

### 微架构

System topology HBM+HBF stacks; LRU-K admission splits miss-write vs miss-no-write. Not a new flash cell—policy+memory hierarchy. Missing: FTL details, GC write amp.

### 负载

Generative recommendation (HSTU-scale, OpenOneRec mentioned); user-level KV reuse across requests.

### 仿真方法学

Analytical roofline for hit/miss latency & lifetime; claims HBF 3.8–4.7× throughput vs HBM-only; LRU-10 lifetime >6 years. Model-heavy; trace assumptions Poisson.

### 工业可行性

Huawei-affiliated preprint; HBF productization + endurance SLA are the gates. Policy change is deployable in software/firmware.

## Master Class

1. **The Real Abstract** — Use HBF capacity/bandwidth for user KV, but stop write-on-miss churn with K-th-request admission so flash lasts years not ~1 year.

2. **The Rashomon Synthesis** — Serving wants hit rate; flash wants writes↓; HBM wants to stay small. Shared: GR KV is huge, read-heavy, but LRU still burns writes.

3. **The Magic Trick** — Admit only users whose K-th touch is hot enough—misses need not write.

4. **The Skeleton in the Closet** — Lifetime math uses Eflash and λ; real FTL/GC may shorten; accuracy of Poisson locality vs production traces unshown in p.1–3.

5. **可提取的问题线索**（仅 p.1–3，有数字，无机制名）

1. HSTU-10B、10K 用户、只留最热 25% 用户时用户级 KV 约需 3.62 TB，远超单靠 HBM 的容量。(p.1)
2. 8K 交互历史、20 ms 延迟目标下 KV 读带宽需求约 403 GB/s，远超典型 CPU 内存带宽。(p.1)
3. HBF 单栈容量可 >10× HBM4（例 512 GB vs 36 GB）且读带宽接近 HBM 级（例 1.6 TB/s），但 SLC 闪存耐久大约仅 100K P/E。(p.1–2)
4. 常规 LRU 把每次 miss 与整份 KV 写入耦合，10K 用户 HSTU-10B 下七栈 HBF 寿命大约仅一年。(p.2)
5. Dhist+inc ≫ Dinc，miss 路径写全量历史+增量会迅速吃掉有限写入耐久。(p.3)
