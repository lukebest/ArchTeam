## 四视角独立批评

### 微架构

弱内存核在 acquire/release/full-fence 上习惯用比内存模型更保守的强制：store-release / full fence 靠 retirement 前排空 older stores（drain），load-acquire / full fence 靠 load queue 标记 hazardous 并在 ordering 指令退休时 squash/replay。结构上：load 走 LQ→cache；store 走 SQ→merge buffer→L1D；merge buffer 按 cache line 索引、每 line 至多一条；RC 的 merge buffer 本不必 FIFO drain，但常规实现仍把可见性约束绑到 ROB-head 退休延迟（merge-buffer 占用与 miss 服务时间）。前三页给出的候选结构：按程序序赋 ordering tag，经 LQ/SQ/merge buffer 携带；store 侧把强制从 retirement drain 挪到 merge-buffer 完成时的 tag 序可见性；load 侧用 tag-aware retirement 谓词区分 safe/unsafe，并把 invalidation hazard 推迟到相关约束真正激活。基线形态声称纯核内、无 ISA 扩展、无一致性协议改动。Table I 总结常规 RC 退休动作。反向工程问题：tag 位宽、merge-buffer 与 ROB 谓词的精确状态机、多核对拍路径——均在未读章节。

### 负载

动机负载是弱内存服务器/客户端上的同步：fence / acquire / release 是共享内存同步积木，核数增大时 fence 成本更敏感。前三页没有给出具体 benchmark 名称或 fence 密度数字；提到 native 四线程工作负载与 instrumented SPEC2017 DBT 代理（x86-on-Arm 类跨 ISA）仅作为 abstract 评测声明，方法未展开。负载审稿人需要：锁/屏障微基准 vs 应用、acquire vs full-fence 比例、store-buffer/merge-buffer 压力分布——前三页均无。

### 仿真方法学

Abstract 声称 geo-mean 归一化执行周期降 7.9%（native 四线程）、SPEC2017 DBT 代理 geo-mean IPC 升 15.9%、每核仅加 262 bytes——全部 unpaid，待未读评估。前三页方法论元素：以 Armv8 RC 子集（RC1–RC6）为操作语义抽象，非完整 Armv8 模型；明确不覆盖该范围外的特征。无模拟器名、无基线核参数、无面积工具链出现在 p.1–3。

### 工业可行性

产品命题是：在已有弱内存 ISA（Armv8 / Power / RISC-V RVWMO 方向语义）上，用核内元数据精确落实方向性约束，而不是把同步一律当 full fence。工业墙：验证成本（RC 语义 ↔ 微结构谓词）、与现有 store buffer / merge buffer / 投机 load 恢复路径的硅改动量、多核一致性交互（文称基线无协议改动，但跨核读值仍靠 RC5/RC6）。262 B/核的面积声明 unpaid。TSO 适用性被预告在未读讨论节。

## Master Class

1. **The Real Abstract** — Weak-memory cores over-enforce fences: drain stalls at retirement and squash/replay of speculative loads. Encode directional RC constraints as per-instruction tags and enforce them at the pipeline stages that actually need them (retirement predicates + merge-buffer completion), not by serializing ROB-head commit.

2. **The Rashomon Synthesis** — Memory-model people already have acquire/release asymmetry; µarch people still implement full-fence-like drains; DBT/cross-ISA people pay extra fence tax. Leftover: precise within-core enforcement that preserves legal RC executions without ISA/protocol changes.

3. **The Magic Trick** — Ordering tags + split enforcement (retirement predicates vs merge-buffer tag-ordered visibility) so required visibility survives without drain-induced ROB stalls.

4. **The Skeleton in the Closet** — Abstract 7.9% / 15.9% / 262 B unpaid; first three pages give almost no quantified conventional overhead; correctness and TSO discussion unread; merge-buffer “one entry per line” assumption may not match all commercial designs.

5. **可提取的问题线索**（仅 p.1–3，有数字，无机制名）

1. 弱内存实现常把排序指令执行得比内存模型要求更保守：在排序指令处出现由排空（drain）引起的退休停顿，并对投机 load 做保守的 squash/replay，压制本合法的执行、降低吞吐。(p.1)
2. 常规微结构忽略 acquire/release 的方向性：full fence 与 store-release 常靠在退休前排空 older stores 来强制，从而卡住提交；load-acquire 则可能在无效化后保守地 squash/replay 投机 load。(p.1)
3. Store 提交后仍留在 store queue，再转入 merge buffer（写缓冲）才写入 cache；路径为 SQ→merge buffer→cache。目标设计中 merge buffer 按 cache line 索引，每条 cache line 至多一个条目。(p.2–3)
4. 因 store 全局可见推迟到 merge-buffer drain，full fence / store-release 等排序约束直接耦合 drain 行为：若正确性要求 po-older stores 先全局可见，则退休延迟成为 merge-buffer 占用与 cache-miss 服务时间的函数。(p.3)
5. 常规 RC 实现用“卡住退休直到所需 po-older merge-buffer 条目排空”来处理 store 侧全局可见性 hazard；load 侧则在 po-older full fence / load-acquire 仍活跃时，对匹配 snoop 的投机 load 做 hazard 跟踪并推迟 squash/replay 到该排序指令退休。(p.3, Table I)
6. Table I：常规 RC 下 load-acquire 不要求 merge-buffer drain 但要求 hazardous-load squash；store-release 相反；full fence 两者皆要——直接对应投机窗口收缩、drain 引起的 store 退休停顿、以及不必要的 load squash/flush。(p.3, Table I)
