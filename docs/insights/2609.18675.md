## 四视角独立批评

### 微架构

Full-HBF: no retained HBM in the package/stack budget; NAND dies stacked on a base die with HBF controller, TSVs, micro-bumps. Hierarchy stack–die–plane–block–page; per-plane array datapath + page buffer; array read/program on ~4 KiB physical pages; erase on blocks; same-plane accesses serialize; heaviest plane sets completion time. Base-die SRAM buffers dynamic KV; prefill and decode are co-located so prefill compute can drain decode KV programs. Three coordinated mechanisms named: (1) HBF-aware KV placement + attention/CTA scheduling for plane balance (placement imbalance vs access imbalance distinguished); (2) window-aware aggregated writeback—program occupies a plane ~75 μs and is non-preemptible; (3) lifetime-guided block packing + deferred reclamation. Logical KV pages (PagedAttention) map independently of physical striping. Hybrid baselines named: H3 cascaded (weights/shared KV in HBF, generated KV in HBM); FlashAccel cascaded/co-located; integrated DRAM+flash stacks. No SRAM size, plane count, or controller microarch on p.1–3.

### 负载

LLM serving with growing weights + KV: long context, multi-turn, concurrency; DeepSeek-V4-Pro cited at ~1.6T params and 1M-token context. Prefill (parallel prompt) vs decode (incremental token + KV reuse). PagedAttention logical pages + chunked CTA/work-tile attention: a CTA’s logical tile becomes scattered physical reads. Named unread eval: four LLMs, four Alibaba Bailian production traces, SWE-bench, varying concurrency. Weight reads still live on HBF and compete with KV.

### 仿真方法学

Abstract/end of intro: “average throughput speedups of up to 1.58× over FlashAccel and 3.30× over H3.” Custom trace-driven sim “models individual read and write operations.” Characterization: DeepSeek-V4-Pro block-level GC write amplification ~30×; raw KV writes claimed inside endurance, mixed-lifetime blocks not. Ablations of read balancing / writeback / lifetime-aware reclamation promised, unread. Treat 1.58× / 3.30× as unpaid until unread plots; 75 μs and 30× are author-stated physical/characterization numbers on p.2.

### 工业可行性

Product move is spend the whole package budget on HBF planes and do KV management in flash, instead of keeping HBM as a KV scratchpad. That is a packaging bet: more planes vs a DRAM cache. Needs a base-die SRAM big enough to absorb decode updates until a program-hiding window, and a scheduler that can jointly place pages and CTAs. 75 μs non-preemptible programs vs short weight/KV compute gaps is the operational risk; 30× WA is the endurance risk. No process, capacity, or SRAM size on p.1–3.

## Master Class

1. **The Real Abstract** — If HBM stays in the package, HBF never gets enough planes to be a real bandwidth device; if HBM leaves, KV’s fine-grained reads, 75 μs programs, and mixed-lifetime erases will waste those planes unless the memory system is built for them.

2. **The Rashomon Synthesis** — Packaging people trade HBM stacks for HBF dies; serving people want paged, request-level KV; flash people stripe planes and erase blocks; attention CTAs pick a subset of pages. Balance at allocation time is not balance at access time, and is not lifetime locality at erase time.

3. **The Magic Trick** — Full-HBF plus base-die SRAM and co-located prefill/decode; place and schedule KV for plane balance; aggregate writes into compute-long windows; pack by lifetime and defer GC so erases do not migrate a 30× tax.

4. **The Skeleton in the Closet** — 1.58× / 3.30× have no config on p.1–3; SRAM capacity is the hidden HBM; 75 μs programs vs “sufficiently long” windows is a hope; lifetime packing fights the same striping that read balance wants; four models / Bailian / SWE-bench unread.

5. **可提取的问题线索**（仅 p.1–3，有数字，无机制名）

1. DeepSeek-V4-Pro 约有 1.6 万亿参数并支持百万 token 上下文；HBM 容量难同时容纳大模型与增长中的 KV，跨更多 GPU 分摊又增加通信与协调开销。(p.1)
2. 在固定封装预算下保留 HBM 会挤占本可用于 HBF 的堆栈/裸片资源，从而限制 HBF 平面数与聚合读带宽，连权重侧可用带宽也被卡住。(p.1–2)
3. 细粒度 KV 读会在放置与访问两层造成平面失衡：请求完成/再激活改变活跃工作集却未必搬页；即便放置均衡，分页注意力与分块 CTA 调度仍可能把读集中到少数平面，迫使额外读波而其他平面空闲。(p.2)
4. 增量 KV 更新要聚合才能吃满平面并行，但单次 program 约占目标平面约 75 μs 且不可抢占；权重与 KV 读交错把计算切成可能藏不住整次 program 的短窗口，推迟写回又会被缓冲压力逼回。(p.2)
5. 对 DeepSeek-V4-Pro 的刻画显示，块级垃圾回收平均写放大约 30×，超出可用耐久裕度；不同寿命的 KV 页若共块，擦除时还要迁移有效页。(p.2)
6. HBF 按堆–裸片–平面–块–页组织，阵列读/program 以约 4 KiB 物理页为单位、擦除以块为单位；同平面访问串行，最重负载平面决定完成时间。(p.3)
