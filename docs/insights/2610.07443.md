## 四视角独立批评

### 微架构

贡献的骨架是一个分析量：利用率 U = [min(M,m)·min(N,n)/(m·n)]·[K/(K+k)]，并把 m、n、k 三维都做成可调。非对称展平（1×1024）意味着每周期要向 1024 列各送不同权重——权重带宽需求增长约 32×，靠 W4A16 只能缓解 4×（相对 16-bit）；片上 SRAM 端口/bank 与全局权重分发网络如何供给是关键，前三页只说"raising weight delivery"。Split-K 的 tick–tock 复用阵列内链路做部分和折叠，代价是转发与累加交替占用链路、可能使有效吞吐减半，需正文核算。内积式混合精度单元在 W8A8 与 W4A16 间切换，PE 面积与关键路径代价未在前三页给出。

### 负载

动机抓住真实服务特征：decode 为 M=1 的 GEMV，权重访存占 decode 内存流量 **>90%**；连续批处理使 GEMM 形状随活跃 token 数波动；PD 分离下静态部署的 prefill/decode 硬件随相比例变化而失衡。风险：(i) TPOT 36.55× 这种量级通常意味着基线（FIGLUT 定点阵列）在 decode 上极度低效，对比口径需要核对带宽是否等量；(ii) 未见 MoE、长上下文注意力（KV 读取主导而非权重）、投机解码等使 M>1 的 decode 变体；(iii) W4A16 在 decode 的精度影响作者自认"degrades accuracy"，却在 decode 端采用。

### 仿真方法学

前三页称用真实服务 trace 评测，未说明是周期级模拟、解析模型还是 RTL；关键在于 HBM/片外带宽是否在 DynaCore 与基线之间等量，以及运行时 MEU 切换（重配置延迟、数据重排）是否计入每批次时延。调度器依赖离线 profiling 的延迟–能耗表，对未见形状的外推误差会影响 TTFT/TPOT 尾部，需看分布而非均值。

### 工业可行性

方向与业界一致（prefill/decode 分离、decode 带宽墙），但工业 NPU 通常直接用不同芯片/不同 SKU 处理两相或靠更大批次填满阵列；可重形阵列需要编译器为每种 MEU 生成映射，验证面成倍增加。1×1024 形状对权重缓冲布局与物理布线（长线、时序收敛）压力大；W4A16/W8A8 双格式还要求模型权重以两份或可在线转换的形式存储，片外容量与加载时延是部署成本。

## Master Class

1. **核心机制一句话** — 把 systolic 阵列执行的最小高效 GEMM 块 m×n×k 三维都做成运行时可调（非对称展平换权重并行、Split-K 用阵列现有链路折叠部分和），配合 prefill W8A8 / decode W4A16 的分相量化与精度无关输出宽度的数据通路，并按批次调度形状。
2. **作者淡化的局限** — 展平后权重分发带宽与 SRAM 端口成本；Split-K 链路复用的吞吐代价；W4A16 精度损失；重配置开销与离线 profile 外推；超大倍数加速对基线带宽口径敏感；未覆盖 KV 主导的长上下文 decode 与 MoE。

## 问题线索（交给问题提炼 Bot；仅 p.1–3，有数字，无机制名）

1. 自回归生成把推理分成两相：prefill 以大规模 GEMM 为主、加速器利用率高；decode 逐 token 生成，每步以并行度与算术强度都很低的 GEMV 为主，造成严重硬件低利用，并成为端到端 LLM 服务的主导瓶颈。(p.1 §1)
2. decode 是访存受限负载，权重访问常占内存流量 **>90%**，激活足迹很小。(p.1 §1)
3. 二维 systolic 阵列在 decode（token 维 **M=1**）时复用崩塌：激活无法跨行复用、权重也无法在阵列内高效共享；在 **S×S** 阵列上空间利用率项塌缩到 **1/S**，大部分 PE 闲置；输出驻留与权重驻留两种数据流均如此。(p.3 §2.3, Fig.2, 式(1))
4. 阵列满利用需同时满足 M≥m、N≥n、K≫k **3** 个条件；其中归约深度 k 不由阵列尺寸单独决定，而取决于操作数如何送入与传播。(p.3 式(1))
5. 连续批处理按活跃 token 数聚合请求，使 GEMM 形状随请求到达与完成持续波动，计算在扁平的访存受限 GEMV 与更大更并行的 GEMM 之间来回切换，硬件利用率不稳定；它并未消除 decode 负载与阵列执行模型之间的结构性失配。(p.2–3 §1/§2.2)
6. prefill 与 decode 同设备共置会因资源争用造成显著时延波动；把两相分到不同设备虽缓解干扰，但相比例随负载持续变化，静态分设硬件导致资源失衡。(p.1 §1；p.3 §2.2)
7. 量化通常对两相用同一配置（如 W8A8 或 W4A16）：双侧 8-bit 量化在 prefill 提升计算效率且保精度，但对受带宽约束的 decode 收益有限；仅权重 4-bit 量化减少 decode 访存，却几乎不加速 prefill 且降低精度。(p.2 §1)
8. 已有可重构阵列只重塑空间维 (m, n) 且对称地切分（例如把 **128×128** 切成 **32×32** 或 **4×4** 方阵），目标是多 DNN 共置/扩展；固定阵列类 LLM 量化/稀疏加速器（**16×32** 到 **192×256** 不等）的执行块都固定、面向 prefill GEMM。(p.3 Table 1, §2.3)
