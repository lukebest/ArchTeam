## 四视角独立批评

### 微架构

主张不是「再做一套 bit-serial PUM 指令」，而是给 subarray 加**受限的水平通信**：既然进位/部分积/前缀都只需相邻或 2 的幂距离的位间交互，那就不必为任意逻辑移位而把数据转成比特切片。结构线索（p.1–2）：(i) migration cell 取代 bitline 上周期位置的普通单元，经 WL0/WL1 两只接入管接到相邻两条 bitline、共享存储节点——是 RowShift/RowBroadcast/RowInvert 的基础；(ii) inversion cell 位于 subarray 末端，由 migration cell 派生，接 BLSA 互补侧；(iii) 原语沿用 Ambit/SIMDRAM 的 AP/AAP、MAJ3、MAJ5（含 MAJ5 求 XOR）；(iv) 同时保留 bit-serial 与 bit-parallel 两种执行。反向工程未读：migration cell 间隔对密度与可移位距离的约束、2 的幂距离移位需要多少次级联单步移位、开放 bitline 架构下 BLSA 由相邻 subarray 共享（BL i 与邻 subarray BL i+1 配对）如何与水平移位交互、多行激活可靠性与刷新/RowHammer 的耦合、对 6F² 密度的面积代价。

### 负载

动机负载是 **主机–PUM 协同执行**：数据要在 CPU/加速器与 DRAM 内计算之间往返，比特切片布局让每次往返都付转置成本。前三页只给出抽象工作负载类（MLPerf 19 个基准、边缘级 host–PUM 协同）；问题侧更应抓住：bit-serial 在大量元素上吞吐好但单元素延迟 O(c·n)，bit-parallel 延迟 O(log n) 但并行度受行宽内操作数数量约束——哪个赢取决于算子位宽、元素数与布局转换频率。前三页未给出布局转换在端到端时间中的占比分布，也未说明 MLPerf 中哪些层真正在 PUM 上跑。

### 仿真方法学

前三页声称有晶体管级版图与 SPICE 验证电路、自研编译器与 MLPerf 评测，但 **未**给出 DRAM 时序参数、多行激活的工艺偏差余量、SIMDRAM 基线是否同样计入转置开销、主机侧建模（CPU 型号、内存通道数）。方法学风险：migration cell 的可行性引用既有 saddle-fin 桥接工作 [16]，若 SPICE 未覆盖温度/工艺角与保持时间，"保持常规阵列组织与密度" 的说法偏乐观；5.9× 是相对 DDR4 bit-serial 基线，若基线的布局转换由主机串行完成而本方案原地完成，收益会混入转置算法差异。

### 工业可行性

命题是「只加两类特殊单元，就让 DRAM PUM 与主机布局兼容」。工业墙：任何改 cell 阵列的方案都触碰 DRAM 厂商最敏感的密度与良率；AP/AAP 多行激活属于规格外命令序列，需要 JEDEC 级接口与控制器支持；新 cell 对 ECC（片上 ECC 按列编码）、RowHammer 缓解、刷新策略的影响未讨论；地址映射与交织会把一个"逻辑字"打散到不同芯片/列，行主序兼容是否在系统级成立存疑。前三页未给出面积百分比。

## Master Class

1. **The Real Abstract** — Charge-sharing DRAM compute is confined to one bitline, so existing PUM stores data bit-sliced and must transpose whenever data crosses between host and memory, even though most arithmetic needs only neighbor-bit communication.

2. **The Rashomon Synthesis** — PUM researchers see massive bitline parallelism and want bit-serial throughput; host/accelerator designers see row-major word layouts they will not give up; DRAM vendors see a dense cell array they will not redesign heavily. Leftover: add sparse, local horizontal links inside the subarray so bit-parallel arithmetic runs in host layout.

3. **The Magic Trick** — Periodic dual-port migration cells bridging adjacent bitlines (paired, different offsets) plus inversion cells at subarray edges; row shift/broadcast/invert primitives; Kogge–Stone prefix add with power-of-two shifts + MAJ AND/OR; multiply via broadcast partial products and single-bit-shift carry-save reduction; compiler picks bit-serial vs bit-parallel layout over the dependence graph.

4. **The Skeleton in the Closet** — 5.9× vs SIMDRAM and 1.8× from joint layout selection unpaid on p.1–3; area/density cost of migration cells not stated; out-of-spec multi-row activation, ECC/RowHammer/refresh interactions and system address interleaving unaddressed in the opening; feasibility leans on prior device work [16].

5. **可提取的问题线索**（仅 p.1–3，有数字，无机制名）

1. 基于电荷共享的 DRAM 存内计算只能在**单条 bitline 内**完成运算；同一行内相邻比特位在电气上相互隔离，没有原生的相邻位通信通路。(p.1 §I)
2. 因缺少水平数据移动，现有 DRAM 存内计算把数据重排成**列向/比特切片**布局（每个比特位占一行），与 CPU/加速器的行主序、字并行布局根本不兼容；每次在主机执行与存内执行之间切换都要付一次昂贵的布局转置。(p.1 Abstract / §I)
3. 比特串行加法是 **O(n)** 深度：每个全加器步要执行固定的 **c** 条行级原语操作，总计 **O(c·n)** 次行操作，以单元素延迟换取整行吞吐；并行前缀加法理论上只需 **O(log n)** 深度。(p.2 §II-C)
4. 进位传播、部分积累加、前缀计算等算术结构大多只需**相邻或近邻比特位**之间的局部通信，但现有方案为了任意逻辑移位的灵活性，长期维持与主机不兼容的布局。(p.1 §I)
5. 已有把比特并行算法跑在比特切片数据上的做法（把操作数比特分散到多个 subarray 并利用 subarray 级并行），物理布局仍是比特切片，与行主序主机数据交互时**仍需转置**。(p.2 §I)
6. 同一程序依赖图中不同算术操作偏好的布局不同，而布局间转换的重组成本必须在结果交给 CPU 或后续比特并行计算前付清。(p.2 §I)
7. 一次行级批量拷贝可在单个 DRAM 时序周期内操作整行（典型 **8 KB**），但该行内各比特位之间仍无法交换数据——行宽并行与位间通信能力之间存在结构性断层。(p.2 §II-B)
