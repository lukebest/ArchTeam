## 四视角独立批评

### 微架构

PPD (1024 slots, 11-bit fingerprint in table), DPB N-bit membership, domain rings + LSG cross-cut. Eliminates host vm.PageTable on remote path. Missing: PPD false-positive handling cost, broadcast storm under migrate storms.

### 负载

relu/aes/conv/minife/GEMM/transpose/im2col/fft/sort/random_access/pagerank/xsbench/bfs/spmv; footprints 9–236 MB (Table II).

### 仿真方法学

Extended timing model; claims 2.5× vs Trans-FW average. Config tables on p.3. Idealized GEMM roofline ignores translation in Fig.1a.

### 工业可行性

Needs wafer-scale packaging (CoWoS/SoW); consistency protocol correctness under migration; CPU still holds full PTE set for cold pages.

## Master Class

1. **The Real Abstract** — Let the GPU mesh locate which die holds a PTE via presence directories/domains so remote VA translation never leaves the wafer.

2. **The Rashomon Synthesis** — UM wants local-like remote; IOMMU wants centrality; NoC wants bounded broadcasts. Shared: translation, not DRAM BW, is the WSG scaling cliff.

3. **The Magic Trick** — Track PTE presence (who has it), not full PTE replicas, then search a small cross-domain set.

4. **The Skeleton in the Closet** — 2.5× is vs Trans-FW only; apps are small footprints vs real UM working sets; PPD/cuckoo false positives not stress-tested in intro.

5. **可提取的问题线索**（仅 p.1–3，有数字，无机制名）

1. 多 GPU 统一内存要接近本地访问，需互连带宽≈本地内存带宽；NVIDIA B200 示例内存 8 TB/s 但互连仅 0.9 TB/s，互连/内存比约 0.225。(p.1)
2. 晶圆级互连单向可达约 7.5 TB/s，互连/内存比可超过 1，但现有 UM 仍把远程虚地址翻译丢给 CPU-IOMMU，请求要走离片路径并争用有限 CPU 侧翻译资源。(p.1)
3. GPU 数量到数十颗时，数千 SM 产生的翻译请求使集中式转发表/IOMMU 成为瓶颈；Trans-FW 的集中 FT 一次只处理一个请求且仍付离片代价。(p.2)
4. 在 N×N GPU 阵列上建单一全局 PTE-PC 域并对每次 PTE 更新全网格广播，更新流量与每 GPU O(N²) 级 presence 元数据不可接受。(p.3)
5. 仿真标定：单 GPU 缩到 MI100 的约 1/4 CU/L2；晶圆链路按 SoW-X 比例；HBM 1.23 TB/s、100-cycle；晶圆链路 1.85 TB/s、38-cycle；Wafer2CPU 180-cycle。(p.3)
