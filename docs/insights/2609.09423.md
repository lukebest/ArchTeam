## 四视角独立批评

### 微架构

Dual key-switch datapaths + runtime method select from performance model; KLSS path keeps intermediates on-chip. FPGA resource/parallelism vs key memory footprint is the knob.

### 负载

CKKS FHE; bootstrapping; secure image classification; multiplicative level/depth varies mid-computation.

### 仿真方法学

FPGA implementation on U280; model-guided comparison of HKS vs KLSS compute+memory. Numbers are end-to-end FPGA, not ASIC.

### 工业可行性

U280/HBM FPGA path is product-near for privacy cloud; KLSS higher precision/key footprint may thrash smaller devices; adaptive mux adds design complexity.

## Master Class

1. **The Real Abstract** — Neither HKS nor KLSS wins for every depth/parameter—switch methods at runtime under an FPGA memory/parallelism model.

2. **The Rashomon Synthesis** — Crypto wants fewer NTTs (KLSS); FPGA wants on-chip residency; deep circuits change which bottleneck binds.

3. **The Magic Trick** — Memory-efficient KLSS datapath + adaptive HKS/KLSS select during one FHE run.

4. **The Skeleton in the Closet** — Key-switching up to ~80% runtime claim is literature-cited; adaptive gains depend on parameter sets chosen vs prior FPGA accelerators.

5. **可提取的问题线索**（仅 p.1–3，有数字，无机制名）

1. 全同态加密相对明文可慢若干数量级；密文常比明文大约两到三个数量级，内存带宽易成瓶颈。(p.1)
2. Key-switching 可占到总运行时间约 80%，因为每次密文乘法与旋转都需要它；bootstrapping 与实用应用含大量乘法/旋转，使其成为主要瓶颈。(p.1)
3. 较新的 KLSS 类方法通过减少 NTT 次数降低计算复杂度，但提高求值密钥内存占用与精度需求，FPGA 上是否总优于传统混合 key-switching 并不事先清楚。(p.1)
4. FPGA 平台上相对延迟高度依赖硬件并行度、安全参数与片上内存容量；内存资源与并行度必须权衡。(p.1)
5. 分析表明：在一次 FHE 计算过程中，支持两种方法并自适应选择，可比静态只用一种获得更低总体延迟（作者动机）。(p.1)
