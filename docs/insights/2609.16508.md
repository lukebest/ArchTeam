## 四视角独立批评

### 微架构

Claimed co-design, not a CNN systolic remap. Search dimensions named on p.2 (Fig. 2): stage count, upscale strategy, color domain, UV processing, kernel design, bit allocation—each scored on PSNR/SSIM/model size and deploy memory/resource/frequency/latency. Selected point (p.2–3): LUT-SR on luminance Y only, U/V upscaled separately; two-stage dual-branch Y path splits 8-bit input into 4-bit MSB / 4-bit LSB; MSB uses four 3-pixel H/D/B/L kernels whose rotations cover a 5×5 RF, LSB uses two 2-pixel H/D kernels for a 3×3 RF; bit decomposition replaces interpolation so the FPGA path claims zero DSPs. p.3 architecture sketch: SRDMA from DDR4 into five circular line buffers; a new 1×4 group plus prior rows builds four 5×5 blocks dispatched to four units; each unit is a Pixel Arithmetic Unit + Memory Unit (16 banks: 8 MSB + 8 LSB); one unit emits 2×2 / cycle, four units a 2×8 block written back over AXI. RGB and YUV accelerator variants are both named. Port/timing closure and full HDMI-subsystem resource tables are after p.3.

### 负载

Edge real-time image/video SR for 4K display enhancement and streaming. Classical interpolation / sparse-coding is cheap but weak on high frequency; DLSR is quality-rich and MAC-heavy. LUT-SR replaces convolution with precomputed queries (single-LUT, multi-LUT, series-parallel, reconstructed-convolution, compact, storage-efficient lineages named as prior). Fundamental trade-off stated: RF coverage vs LUT size vs memory-access cost vs deploy efficiency. Independent RGB-channel processing either drops throughput or replicates tables and blows FPGA/ASIC SRAM. Target: arbitrary input resolution and configurable ×2ⁿ factors. Fig. 1 context: Set5 4× PSNR vs runtime at 1280×720 output, vs interpolation / LUT / sparse-coding / DLSR points.

### 仿真方法学

p.1–3 are intro + related work + framework/architecture sketch. Headline FPGA numbers (95.3 FPS 4K ×2 @ 300 MHz; ≥58.6% fewer LUTs; ≥41.1% fewer FFs; 0 DSP; ≥42% lower power; 10× vs best CPU SR; 1.2× vs prior FPGA SR; 18.4% memory vs SOTA LUT SR; YUV memory “two-thirds” below RGB-domain) appear as claims. Fig. 1 is a PSNR–runtime scatter, not a resource table. Exhaustive DSE is asserted; search/ablation tables and the full ZCU102+HDMI measurement setup are unread. Treat every percentage and FPS figure as author-reported.

### 工业可行性

Product shape is an FPGA video pipeline (ZCU102 + HDMI named), not a foundry ASIC. Zero-DSP LUT inference and YUV (already native to cameras/displays) are the adoption hooks versus MAC-heavy SR NPUs. Configurable ×2ⁿ plus arbitrary input size is the edge-SKU story. SRAM still has to hold the tables; the 18.4% cut is relative to SOTA LUT-SR, not a proof that 4K real-time and power close together on a cheaper device than ZCU102. No ASIC node / area on p.1–3.

## Master Class

1. **The Real Abstract** — Edge 4K SR cannot pay DLSR MAC/power, and existing LUT-SR still misses speed, storage, and cross-scale fit; jointly search the table and the pipeline so lookup is multiplication-free, parallel, and configurable across ×2ⁿ.

2. **The Rashomon Synthesis** — Algorithm people grow RF and PSNR; FPGA people refuse replicated RGB tables and DSPs; video people need arbitrary resolution and several integer scales; prior LUT-SR stays algorithm-centric and never meets the execution pipeline.

3. **The Magic Trick** — Put SR in YUV so only Y pays the tables; cover RF with rotated power-of-two kernels and MSB/LSB bit-split so storage and arithmetic stay shift/add/lookup; stream 5×5 windows through a banked parallel lookup pipeline.

4. **The Skeleton in the Closet** — 95.3 FPS / 18.4% / zero-DSP / 1.2× are unread beyond the abstract; “first configurable LUT-SR” and “first zero-DSP LUT-SR on FPGA” are positioning; §3–4 already dump the network and the four-unit pipeline on p.2–3—easy to over-read as vetted eval.

5. **可提取的问题线索**（仅 p.1–3，有数字，无机制名）

1. 边缘实时超分被深度模型的海量 MAC、时延与功耗卡住，难以在资源受限平台落地。(p.1 / abstract)
2. 用查表代替卷积可去掉 MAC，但既有 LUT 超分仍受速度、存储开销与跨上采样倍率可扩展性三重约束。(p.1)
3. 扩大感受野通常抬高 LUT 复杂度与存储；按 RGB 通道独立处理则吞吐下降或复制多份 LUT，容易击穿 FPGA/ASIC 的 SRAM 预算。(p.1)
4. 感受野覆盖、LUT 规模、访存代价与部署效率之间存在根本权衡；多数 LUT 超分工作仍偏算法中心，与硬件执行流水线未对齐。(p.1–2)
5. 相对既有 LUT 方案，存储仍可再降约 18.4% 量级才谈得上实用；4K 实时与资源/功耗同时达标仍是开放压力。(abstract)
