## 四视角独立批评

### 微架构

边缘 LLM 推理：自回归 decode 逐步满参前向，内存瓶颈、算力闲置；片上装不下完整 target 时，误推测的数据搬运更贵。投机解码引入 draft 生成（M=1 GEMV）、target 并行验证（M=γ+1，介于 GEMV 与 GEMM）、以及一次 prefill（大 M GEMM）。算术强度 AI(M)=M/2 FLOPs/byte（32-bit 权重主导假设），随 M 线性变。固定数据通路难同时吃满三种制度；tiled 互联可调参与 tile 数 T，但增大 T 常降低每 tile 复用、把工作点向左推——对靠近 ridge 的验证核可能推回内存界。前三页结构：多 tile + NoC + 分布式片外带宽 + host 编排；每 tile 双缓冲局部存储、可重构计算引擎、融合后处理、通信单元（含轻量 TLB）与配置寄存器；8×8 PE（64 MAC）、64-bank 权重与 8-bank 输入/部分和/输出。Systolic vs vector-lane 按 M 在 kernel 粒度切换。反向工程：重配置时延、NoC 原语集合、host 决策开销——未读。

### 负载

三相：prefill（M=S）、draft 自回归（每步 M=1）、target 验证（M=γ+1）。典型 draft–target：接受率约 0.8–0.9、γ=4–8 时，每次 target 调用约产出 3–6 个接受 token。模型族点名 Pythia / SmolLM2 / GPT-2（评测声明）。边缘约束：容量有限 → target 无法全常驻 → 放大错误预测代价。负载审稿人还要：序列长度分布、γ 在线是否自适应、draft 相对 target 的算力比——前三页几乎只有公式与典型区间。

### 仿真方法学

20-tile FPGA 原型；tile 级重配置相对最佳固定数据通路至多 2.09×，系统级自适应相对最佳静态映射再至多 1.25×——abstract 数字 unpaid。前三页方法元素：Roofline 定性图（Fig.1）、AI 公式、T=1/2/4/8/12 示意。无频率、工艺、仿真器/RTL 综合流出现在 p.1–3。ICCAD’26 论文身份明确。

### 工业可行性

命题是边缘/移动平台上的可重构 tile 阵列服务投机解码全流水，而非云端大芯片。工业墙：FPGA 原型 → ASIC 的重配置开销与控制面复杂度；host 每 kernel 编排是否可在驱动/运行时承受；多模型族权重布局与片外带宽分区。容量墙（target 无法全常驻）是真实产品约束，但前三页未给具体边缘 SoC 带宽/容量预算。

## Master Class

1. **The Real Abstract** — Speculative decoding adds a verification regime whose arithmetic intensity sits between memory-bound decode and compute-bound prefill and moves with γ and acceptance. Fixed edge accelerators underutilize across phases; need tile-level datapath mode switches and system-level tile/partition/comms adaptation per kernel.

2. **The Rashomon Synthesis** — Spec-decoding people pick γ and draft models; accelerator people specialize systolic vs vector; edge SoC people fight capacity. Leftover: one fabric whose operating point must track a runtime-moving mid-regime without stranding tiles or bandwidth.

3. **The Magic Trick** — Same PE array: systolic for GEMM, vector-lane for GEMV; across tiles, pick T, partitioning, and communication per kernel.

4. **The Skeleton in the Closet** — 2.09× / 1.25× unpaid; reconfiguration latency not on p.1–3; FPGA≠shipping edge NPU; acceptance 0.8–0.9 assumed typical.

5. **可提取的问题线索**（仅 p.1–3，有数字，无机制名）

1. 边缘/移动平台内存带宽与片上容量受限，decode 阶段可用并行度下降，算力资源易闲置；target 模型往往无法完整常驻片上，放大误推测 token 的数据搬运代价。(p.1)
2. 自回归 decode 每步 M=1，矩阵乘退化为 GEMV，算术强度降至约 **0.5 FLOPs/byte**，执行本质上内存受限，追加算力收益有限。(p.2)
3. Prefill 以大 M=S 做 GEMM、算强高、偏计算受限；投机解码的 target 验证以 M=γ+1 并行处理多 token，落在二者之间的中间算强区，且随投机长度 γ 与接受率变化。(p.1–2, Fig.1)
4. 在权重 32-bit、权重流量主导的假设下，AI(M)=M/2 FLOPs/byte，算强随输入行数 M 线性上升、与 K/N 无关——验证阶段的工作点随 γ 滑动。(p.2, Eq.1)
5. 典型 draft–target 组合在接受率约 **0.8–0.9**、γ=**4–8** 时，每次 target 调用约产生 **3–6** 个接受 token，串行前向次数按同因子下降——但硬件仍需同时服务 draft GEMV、验证中等 M、以及 prefill GEMM。(p.2)
6. 将同一 kernel 分到更多 tile（示意 T=1,2,4,8,12）会提高峰值吞吐，但也常因复用下降、输入/权重复制而使有效算强左移；对已靠近 ridge 的验证类 kernel，可能被推回内存受限区，限制可扩展性。(p.3, Fig.1)
