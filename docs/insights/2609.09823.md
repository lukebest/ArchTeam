## 四视角独立批评

### 微架构

Predict-and-audit contract on AttAcc-like HBM-PIM; stack-level merge controller; SCBO tunes 5 knobs under false-drop budget. Not a new GEMV cell—control/sparsity schedule across GPU+PIM.

### 负载

Long-context decode; LongBench/RULER; contexts 8K–64K; batch 8 in sim.

### 仿真方法学

Trace/sim GPU–PIM; task quality near baseline; energy 28–66%↓ dynamic decode vs dense. False-drop ablation −68% with audit feedback.

### 工业可行性

Needs real HBM-PIM productization + false-drop SLO; prediction irreversibility for current token is the risk knob.

## Master Class

1. **The Real Abstract** — Break the serial query→score→mask chain by predicting drops from history so GPU and PIM overlap, while auditing every predicted drop for the next step.

2. **The Rashomon Synthesis** — Sparsity wants skip K traffic; correctness wants not to silently kill blocks; PIM filter that waits on current query still serializes the critical path.

3. **The Magic Trick** — History margins → early survivor mask; PIM audits the omitted complement in parallel; eager next-mask closes the selective-label hole.

4. **The Skeleton in the Closet** — Irreversible wrong drops only bounded statistically; 89.2% verdict stability is workload-trace dependent; sim≠silicon HBM-PIM.

5. **可提取的问题线索**（仅 p.1–3，有数字，无机制名）

1. 自回归解码每步重读增长的 KV；长上下文注意力受 GPU 内存带宽束缚。(p.1)
2. 后 QK 的块选择（如相对最大阈值）虽能跳过 softmax/V/PV，但仍读完每个 K 块；在约 90% 块稀疏时，K 仍约占其剩余逻辑 K+V 流量的 91%。(p.1)
3. 用当前 query 在 PIM 侧做过滤虽可在 GPU 取 K 前形成 mask，但仍依赖当前 query，PIM 阶段仍串在 query→分数→mask→注意力链上。(p.1)
4. 轨迹中约 89.2% 的合格块判决在下一步保持不变；但若只预测不审计，被丢掉的块再也得不到分数，错误丢弃会删掉本可纠正它的证据（选择性标注）。(p.2)
5. 受控消融显示：对每个预测丢弃做并发审计并把结果折回下一步，可使错误丢弃率约降 68%。(p.2)
