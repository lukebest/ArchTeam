## 四视角独立批评

### 微架构

PUD 用 DRAM 阵列模拟特性做体比特布尔/算术：常见 bit-serial SIMD，把 M 个 N-bit 元素竖排放成 M 列 × N 行，使进位可经行拷贝在列内传播。但现代系统原生水平布局（cache line、行缓冲局部性、高吞吐）。前三页结构主张两条：① 在 MC 侧对每次访存请求做确定性比特置换，使水平布局下操作数仍局域在单 subarray（多 mat）内且按比特位分 mat；② 把可独立激活的 mat 变成流水级，bit-dependent 原语按依赖推进、bit-independent 原语跨级重叠。反向工程：置换网络宽度与时序、mat 间互连相对既有细粒度 PUD 的增量、静态 modulo 调度表如何下发——均在未读节。

### 负载

动机不是某单一应用，而是「凡要把水平内存数据送进 bit-serial PUD」的一类：竖排转换在评测中平均把性能与能效相对无转置理想 PUD 各砍约 **3.9× / 3.7×**；竖排对象切成跨多 cache line 的 slice 后，碰一个元素就可能写回整 slice，放大 cache 流量并与 CPU 层次纠缠。前三页点名对比平台含 CPU/GPU 与三家既有 PUD，声称十二真实应用——负载细节与应用列表 unread。负载审稿人还要：转换开销是否随字宽 N、并行度 M、以及混合 CPU+PUD 相位而变；「双布局视图」给软件带来的显式管理成本是否主导。

### 仿真方法学

Abstract 吞吐/能量/面积数字 unpaid。前三页方法元素：把转置开销对照「无转置要求的理想 PUD」给出 **3.9× / 3.7×**；用标准 DRAM 层次数字（chip 数、bank/subarray/mat、×16 prefetch、64 B / 8-beat）铺垫局部性与互连缺口；引用细粒度行访问与既有 mat 级互连作为可组合积木。完整 gem5/DRAM 仿真配置、能模与面积流片假设 unread。勿把 abstract 相对 SIMDRAM/MIMDRAM/Proteus 的倍数当作已付清。

### 工业可行性

命题是「水平布局下直接做 bit-serial PUD，去掉运行时转置与双布局」。工业墙：MC 侧确定性比特置换是否打穿多厂商 DDR/LPDDR 训练与 ECC/CHIPKILL 假设；DRAM 侧 mat 独立激活 + 互连相对量产颗粒的金属/时序增量；软件不再管双布局后，编译器/库如何声明「可 PUD」缓冲区与一致性。前三页强调低面积百分比与开源，产品叙事清晰，但 JEDEC 命令扩展、多 rank 扩展与安全擦除路径未给。

## Master Class

1. **The Real Abstract** — Bit-serial PUD wants operand bits co-located for sense-amp-driven carry; commodity memory wants horizontal cache-line layout. Runtime verticalization costs ~3.9× perf / ~3.7× energy vs an idealized no-transpose PUD and creates a dual-layout software view plus slice-amplified cache writebacks.

2. **The Rashomon Synthesis** — DRAM people see mat/subarray locality and missing column-wise interconnect; PIM people see vertical layout as the default fix; systems people see cache-line/row-buffer throughput. Leftover: keep the horizontal ABI, but place bits so each mat owns one bit-position and can be a pipeline stage.

3. **The Magic Trick** — Deterministic per-request bit permutation at the memory controller for horizontal-yet-PUD-friendly placement; treat mats as pipeline stages with inter-mat carry move; overlap bit-dependent vs bit-independent primitives under a static schedule.

4. **The Skeleton in the Closet** — 11.8×/80.4× and area % unpaid on p.1–3; hierarchical in-DRAM copy that “keeps carry off the critical path” is named but unread; “first pipeline bit-serial PUD without vertical organization” is a priority claim, not a proof obligation for this note.

5. **可提取的问题线索**（仅 p.1–3，有数字，无机制名）

1. 现代系统原生采用水平数据布局以保留 cache line 抽象、行缓冲空间局部性与高内存吞吐；而 bit-serial 体计算常把操作数竖排（M 元素 × N 比特位跨行），两种布局根本不兼容，迫使运行时在水平/竖直格式间反复转换，带来性能、能量与系统集成开销。(p.1)
2. 相对「无转置要求」的理想体计算基线，数据布局转换平均把性能与能效分别降低约 **3.9×** 与 **3.7×**。(p.1–2)
3. 竖直布局常把对象存成跨多条 cache line 的 slice：访问或逐出单个数据元素会触发整 slice 写回，放大 cache 行流量、抬高写回压力，并使体计算执行与 CPU cache 层次行为缠在一起。(p.2)
4. 竖直布局还引入内存的双布局视图：应用需区分水平与竖直组织的对象并协调布局转换，增加显式数据格式管理与协调成本。(p.2)
5. 常规 DRAM 交错把一个 N-bit 数据字的各比特均匀打散到 rank→chip→bank→subarray→mat 层次；体计算由 mat 内 sense amplifier 驱动，操作数比特若不在同一 mat 内集中，就出现数据局部性缺口。(p.1)
6. 体计算本质是按行：sense amplifier 跨已激活行的所有列工作，阵列内没有原生列向互连可在行间按列传播中间值；因此在「一字多列」的水平摆放下，进位类跨比特位依赖很难做，除非对阵列做昂贵改造。(p.1)
7. 模块侧常见 **8–16** 颗 chip 组成 rank；单 chip 常见 **8–16** bank；bank 内约 **64–128** 个 subarray，每 subarray 约 **16–32** 个 mat；mat 内约 **512–1024** 行、列宽约 **2–8 kB** 量级——比特局部性与互连问题落在这一深层次上。(p.3)
8. 一次 64 B cache line 传输：控制器驱 **64** 路 DQ，DDR 每拍 64-bit、**8-beat** burst；×16 chip 每拍收 16-bit，burst 内在 prefetch buffer 累到 **128** bit 再写入 mats——水平 ABI 与片内放置强绑定。(p.3)
9. 跨 subarray 整行搬移的既有命令路径延迟量级为 **3×tRAS + 2×tRP + 2×tRBM**；列级跨 subarray 搬移另需新命令——说明「把进位/中间值挪到算得着的地方」本身就是一等延迟成本。(p.3)
10. 同时三联行激活可在本地 bitline 上做出多数逻辑，但会破坏性改写行内容，因而要把阵列划成数据行 / 常数行 / 计算用行等分区——计算与存储容量、行资源管理互相挤占。(p.3)
