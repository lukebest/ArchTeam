## 四视角独立批评

### 微架构

严重资源受限边缘 FPGA（如 220-DSP 级）上部署 LIC：算术量、外部存储流量、算子间不平衡与批处理都会各自成为瓶颈，单纯缩小大型加速器不够。先验 FPGA LIC 多保留标量量化+学习熵模型，或另建专用 VQ 搜索阵列。前三页结构主张：非对称边–云编解码——边端只做紧凑 INT8 深度可分离分析变换 + 多码本 VQ + 表驱动 rANS（PS），重建放云端；关键硬件事实是 VQ 码字匹配可写成点积，因而直接复用分析变换已实例化的 PW MAC 阵列，无需独立 VQ 计算引擎。配套的是按读/DW/PW/写竞争成本做瓶颈配比的延迟模型。反向工程：DW vs PW 并行度分割、激活缓冲与外部带宽接口、VQ 与 transform 时分复用仲裁——均在未读节。

### 负载

视觉传感在带宽/能量紧的边缘平台上，传原始图像成本高；LIC 近年靠更大变换、hyperprior、自回归上下文与注意力，GPU 取向编解码难落到低成本嵌入式。目标工况：720p（1280×720）、约 **0.1–0.5 bpp**；选定三块 stride-2、通道日程 **16–48–64**，潜在维 **D=64**，**M=4** 子向量、**Dm=16**，参考码本 **K0=256**（未编码上界 **0.5 bpp**）。负载审稿人还要：真实相机流量 vs CLIC 代理、多分辨率/多速率自适应、边端温控与持续帧率——前三页以资源信封与 bpp 目标设定为主。

### 仿真方法学

Abstract：延迟模型相对硅上分析/VQ 预测误差约 **0.26% / 0.05%**；中等速率 preset 约 **0.1398 bpp @ 28.69 dB PSNR**；完整分析–VQ 流水约 **0.1945 kMAC/pixel**、**47.98 FPS**、**42.84 mJ/frame**——unpaid。前三页方法元素：>100 组 RTL 配置验证、无拟合修正项的确定性周期计数；训练前用模型选 **16–48–64**（相对六块参考预测延迟降约 **24.0%**）；码本基数后处理候选 **K∈{256,…,32}**，终配 **(M*,K*,Dm*)=(4,64,16)**。完整 RD 曲线与对照加速器表 unread。勿把 abstract 吞吐/能量当作已付清。

### 工业可行性

命题是“在乘数极度受限的 FPGA 上，用共享 PW 引擎吃掉 VQ，并把重建推到云”。工业墙：边–云接口与码本/概率表版本一致性；rANS 在 PS 上的 CPU 占用；相对厂商 DPU/overlay 的可移植性；码本缩减对画质与安全认证（监控/车载）的影响。前三页强调 220-DSP 级可落地与模型先行选型，产品叙事清晰，但量产板级 BOM、多租户与固件升级路径未给。

## Master Class

1. **The Real Abstract** — LIC on multiplier- and bandwidth-starved FPGAs is limited by memory traffic, operator imbalance, and batching—not MAC count alone. Prior FPGA LIC either keeps learned entropy models / dedicated VQ arrays or targets much larger DSP envelopes; simply shrinking those designs fails the edge budget.

2. **The Rashomon Synthesis** — Codec people want discrete latents via multi-codebook VQ; FPGA LIC people build DW/PW pipelines or dedicated VQ search arrays; NAS/perf-model people know MACs ≠ latency. Leftover: choose a latent so VQ scoring is the same pointwise MAC the transform already owns, and size that shared engine from deterministic read/DW/PW/write cycle costs.

3. **The Magic Trick** — Asymmetric edge–cloud codec; INT8 DW/PW analysis on PL; map VQ codeword scoring as dot products onto the same PW array; table-driven rANS on PS; provision by bottleneck latency model before training/RTL spin.

4. **The Skeleton in the Closet** — Silicon FPS/energy and 0.26%/0.05% model errors unpaid on p.1–3; CLIC mid-rate proxy; DW/PW arbitration and banked memory detail unread; “first for FPGA LIC” is a priority claim, not a proof obligation for this note.

5. **可提取的问题线索**（仅 p.1–3，有数字，无机制名）

1. 资源严重受限的边缘 FPGA 上，LIC 实际速度不只取决于算术量，还取决于存储流量、不同算子间不平衡与硬件批处理方式；在有限乘数与窄外存接口上，简单缩小大型加速器不足以预测延迟。(p.1)
2. GPU 取向 LIC 依赖更大变换、hyperprior、自回归上下文与注意力，其算术、存储、激活流量与熵模型成本使低成本嵌入式部署困难，即便做数值量化后仍难落地。(p.1)
3. 先验 FPGA LIC 多面向明显更大的资源信封；在乘数受限平台上，专用最近邻 VQ 搜索阵列与变换硬件分离，会再占一份稀缺计算资源，平台难以负担。(p.1–2)
4. 深度可分离卷积把运算拆成逐通道滤波与跨通道混合，但在有限外存带宽下两者对硬件的需求不同：**固定乘数预算**如何在 depthwise 流式与 pointwise 计算之间分割，无法单靠 MAC 占比推断。(p.2)
5. 目标约 **0.1–0.5 bpp** 覆盖既有 FPGA LIC 工作点；三块 stride-2 总下采样 **8×**、潜在维 **D=64**；**M=4**、**Dm=16**、参考 **K0=256** 时未编码速率上界为 **0.5 bpp**；下采样 16× 则约 **0.125 bpp**，4× 则约 **2 bpp** 且潜在位置多 4 倍。(p.3)
6. 产品量化平衡：更少子码本会急剧抬高码本规模与每潜在位置搜索代价（例：**M=2** 需 **K=65,536**，每位置乘法约多 **256×**）；更多子码本则把 **Dm** 推向标量量化。(p.3)
7. 720p（**1280×720**）输入下，选定通道日程 **C=(16,48,64)** 的分析变换约 **4,491** 个卷积权重；中间激活重新量化为 INT8，最终 64 通道潜在以无符号 INT8 存放。(p.3)
8. 确定性 RTL 周期计数模型（读 / depthwise / pointwise / 写）在 **>100** 组配置上、相对硅无拟合修正项，前三页称逐块延迟预测误差约 **0.3%** 内且总能指出瓶颈；训练前用于候选张量几何，相对六块参考可砍预测延迟约 **24.0%**。(p.2–3)
9. 码本基数后处理在 **K∈{256,128,96,64,32}** 中按训练 EMA 使用先验截断，终配 **(M,K,Dm)=(4,64,16)**；前三页称可把 VQ 算术与码本存储砍约 **4×** 并缩小定宽潜在表示——完整 RD/硅测 unread。(abstract / p.3)
10. 边端流水还要把学习型 hyperprior / 自回归熵模型推理移出路径：索引用**固定预共享**概率表做表驱动熵编码，重建容量放到云端更大解码器——边端只压缩、不重建。(p.1–2)
