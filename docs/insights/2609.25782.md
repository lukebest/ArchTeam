## 四视角独立批评

### 微架构

Agentic serving 把单查询变成多轮 decode–工具–用户循环，KV 跨会话累积且在工具/用户等待期长期闲置。紧 TBT 需要活跃 KV 在 HBM；暂停池却持续膨胀直至溢出。HBF（HBM 风格接口后的 3D-NAND）单栈读带宽约 1.6 TB/s、容量约 512 GB（vs HBM4 约 48–64 GB），但更高读能、更低写耐久、页粒度读。前三页结构主张：热集留 HBM、冷池落 HBF，形成 GPU 内存层内热–冷分层；HBM base die 用地址路由与双缓冲 staging，经 D2D 吸收换出/resume 预取，使 HBF 不在逐步 decode 读路径上。四条数据通路：①权重+活跃 KV HBM→GPU；②resume 时 HBF→HBM；③新生成 KV 写回 HBM；④压力下最冷 idle KV HBM→HBF。反向工程：base-die 缓冲深度、D2D 带宽、页对齐粒度与控制器面积——未读完。

### 负载

双峰访问是核心负载事实：热集=当前 decode batch 的 KV，每步必读；冷池=暂停会话 KV，仅 resume 读。Fig.3 在 Na=48 时：热集约 3% 容量却约 98% 读流量。足迹：Qwen3-Coder-30B-A3B 约 56.8 GiB BF16 权重、96 KiB KV/token；峰值上下文约 16.7k token≈1.53 GiB KV/会话，稳态常驻约 0.82 GiB；闲置中位约 8 s、均值约 23 s。纯 HBM 轨迹约 165 会话饱和。负载审稿人还要：真实 agent 到达过程 vs 轨迹重放、工具时延分布是否可推广、MoE 专家权重是否必须全留 HBM——前三页已声明为消除路由方差而全留 HBM。

### 仿真方法学

Abstract 声称 14 ms TBT、resume 额外 ≈0.1 ms、每 GPU 24× 并发会话、相对全 KV-from-flash 每 8-GPU 节点读功率降 7.6 kW——unpaid。前三页方法元素：SWE-bench Verified + mini-swe-agent 轨迹、自研 trace-driven + 解析时延/功耗模型、B200 192 GiB HBM3e @ 8 TB/s + 3 TiB SLC HBF（匹配 HBM 带宽、100k P/E、25 µs 读时延）、1.5 MiB KV 块 + LRU。Fig.4 的 resume TTFT 分层对比属评测开头，细节待完整 §IV。勿把 abstract 倍数当作已付清。

### 工业可行性

产品命题是“HBF 作冷层补位、而非替代 HBM”，针对 agentic 闲置会话容量墙。工业墙：封装级 HBM+HBF 是否进入可采购基板路线；写耐久（写-on-evict、不可变 KV）是否覆盖生产写放大；HBF 读能扫参 8–30 pJ/bit vs HBM ≈3.5 pJ/bit 的产品标定；D2D/base-die 对 GPU 驱动与调度器的暴露面。相对 PCIe/NVLink 换出或重算，前三页动机成立，但成本、良率、控制器 IP 未给。

## Master Class

1. **The Real Abstract** — Agentic multi-turn leaves most KV idle yet retained; HBM cannot hold the paused pool at production concurrency without eviction/recompute, while HBF capacity+bandwidth come with read-energy and endurance costs that forbid serving *all* KV from flash. Need a hot–cold split inside the GPU memory tier.

2. **The Rashomon Synthesis** — Serving systems offload KV to host/SSD; HBF packaging people push flash beside the GPU; agent frameworks lengthen idle gaps. Leftover: a secondary tier that is fast enough for resume but must not sit on the per-step decode read path.

3. **The Magic Trick** — Keep the hot decode set in HBM; park the cold paused pool in HBF; move blocks over base-die D2D only on eviction/resume so per-step traffic stays on the GPU–HBM bus.

4. **The Skeleton in the Closet** — Abstract 14 ms / 0.1 ms / 24× / 7.6 kW unpaid; idle gaps synthetically scaled; MoE experts pinned in HBM; HBF read-energy still a sweep parameter.

5. **可提取的问题线索**（仅 p.1–3，有数字，无机制名）

1. Agentic 多轮会话在工具调用/用户输入之间长期闲置，但 KV 仍须跨整段会话保留；有限 GPU 内存迫使 inactive KV 被换出，恢复时要么重算上下文，要么经慢互连回迁。(p.1)
2. 紧 TBT SLO 要求活跃 decode 的 KV 常驻 HBM；活跃读足迹随 batch 增长但仍受 HBM 容量与“加大 decode batch 会降低每请求吞吐”双重约束而保持相对较小。(p.1)
3. 暂停会话的聚合 KV 随 agent 并发持续膨胀，往往在节点尚未达到生产会话目标前就先溢出 HBM，迫使系统冒 SLO 违规、换出或重算代价。(p.1)
4. 单栈 HBF 读带宽约 **1,638 GB/s**（与 HBM4 栈可比），单栈容量约 **512 GB**，对比 HBM4 约 **48–64 GB**——容量密度远高于 HBM，但读写能耗/耐久与页粒度仍制约其能否承载全部 KV 流量。(p.2)
5. HBF 相对 HBM：更高时延、显著更高的每 bit 读能、更低写耐久；耐久预算约 \(T_{life}=C\cdot N_{PE}/(R_W\cdot WAF)\)，写速率越高寿命越短，故写必须保持低频。(p.2, Eq.1)
6. Flash 读为页粒度（约数十 KB）：子页请求仍按整页取数并付能，小随机读会浪费有效带宽并抬高每 bit 读能。(p.2)
7. Agentic KV 呈双峰：小热集（当前 decode batch 的 KV）每步必读；大冷池（暂停会话 KV）仅在 resume 时读——冷池随并发快速溢出 HBM。(p.1–2)
8. 工作负载表征（Na=48）：热集约占常驻容量的 **3%**，却贡献约 **98%** 的读流量（冷侧占容量大头、读流量约 **2%**）。(p.3, Fig.3)
9. 评测设定中的足迹压力：Qwen3-Coder-30B-A3B 约 **56.8 GiB** BF16 权重、每 token 约 **96 KiB** KV；单会话峰值上下文约 **16.7k** token ≈ **1.53 GiB** KV，稳态每常驻 agent 平均约 **0.82 GiB**；闲置间隔中位约 **8 s**、均值约 **23 s**。(p.3)
10. 纯 HBM 设备在该轨迹下约在 **165** 会话处饱和；对比之下冷层容量问题与 resume 恢复时延共同决定可服务会话数，而非仅有主机 DRAM 容量即可。(p.3)
