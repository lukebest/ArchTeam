## 四视角独立批评

### 微架构

主张不是「再做一个大扩散 U-Net FPGA」，而是针对 **VLA 中紧凑但迭代的 Diffusion Action Expert**：感知大 ViT 留在边缘 GPU，把 I/O 受限的多步去噪 MLP 整段钉到 FPGA 片上存储，消除去噪循环的 DRAM 参数重载。结构线索（p.1–3）：(i) 异构划分——Jetson 跑 BlockTransformer / 观测编码，KR260 跑 DAE；(ii) FPGA 顶层控制器 + **MLP ResNet / DDPM / GRNG** 三单元；参数与 schedule 常数常驻 URAM/BRAM；(iii) 双量化策略可互换——per-channel INT8（宽 datapath P=128）vs NF4-g16（URAM 减半 56→28 tiles on Small，P=64）；(iv) GRNG：4 独立 Xorshift128 状态 + Box-Muller，动作维 **Da=28**、扩散步 **T=20**。反向工程未读：Ethernet readout 握手与主机同步、URAM/BRAM bank 冲突、SiLU/LayerNorm 硬化精度、跨设备端到端流水气泡、功耗分区实测 vs TDP 上界。

### 负载

动机负载是 **Physical AI / VLA**（Octo-Small ∼**27M**、Octo-Base ∼**93M**，不含 T5）：边缘机器人要实时动作，但即便压缩后 Octo 在 RTX 4090 上仅约 **17 / 13 it/s**、功耗约 **200 W**，移动/仓储/野外平台吃不下。关键不对称：DAE 参数仅 **∼1.7–1.8M**、却要 **20** 步 MLP 前向 + schedule + 新高斯噪声；边缘 GPU 上 DAE INT8 足迹约 **1.8 MB** 几乎占满名义 **2 MiB** L2，且 L2 不可钉住，宽 SIMT 吃不饱。问题侧：小参数、高迭代、内存绑定的头，放错架构就会拖垮端到端；大视觉骨干仍适合 GPU。明确范围：针对 Octo 族 DAE（三块 MLP ResNet，Dh=256，Df=1024），不声称覆盖大型图像扩散去噪器。

### 仿真方法学

前三页给出平台（Orin Nano + KR260）、FPGA **250 MHz**、以及相对边缘 GPU / RTX 4090 的延迟与能效摘要数字，但 **未**给出测量口径（是否含 T5、PCIe/Ethernet 传输、功耗计位置、TDP 上界 vs 实测）、量化校准集、或与「整模 FPGA」「整模 GPU」的 iso 对照。方法学风险：若把 DAE 从 GPU 卸走后的传输开销理想化，异构叙事会被高估；能效用 it/J 在 TDP 上界（摘要 1.467 vs 0.085）可能偏乐观。Abstract 的 52.5%/∼17× 在未读完整评测前勿当作已付清系统级结论。

### 工业可行性

命题是「用异构划分 + 片上钉死小 DAE，让边缘功率/热包络下的 VLA 实时成为可能」。工业墙：Jetson+Kria 双板互联的产品化（线缆、延迟、驱动栈）；机器人中间件（ROS 等）与 readout token 接口；NF4/INT8 两套比特流的维护成本；DAE 结构一变（更多步、更大隐层）片上存储假设即破；与纯软件量化/蒸馏路线的竞争。前三页场景清楚（移动操作平台），BOM/可靠性/认证未给。

## Master Class

1. **The Real Abstract** — Compact VLA diffusion action heads are tiny in parameters but iterative and memory-bound on edge GPUs (reload + undersized shared L2), so the GPU’s compute width sits idle while end-to-end robot latency and power stay too high for mobile platforms.

2. **The Rashomon Synthesis** — Robot platforms need low-power real-time policy; edge GPUs excel at wide ViT perception but hate skinny iterative MLPs; FPGAs offer pin-able BRAM/URAM but not GPU-class transformer throughput. Leftover: keep perception on GPU, pin the entire DAE (weights, scales, LayerNorm, schedules, RNG) on FPGA fabric with a quantized MLP datapath and on-chip GRNG.

3. **The Magic Trick** — EdgeDAE on Orin Nano + KR260: heterogeneous partition; FPGA MLP ResNet + DDPM + 4-way Xorshift128/Box-Muller GRNG; full on-chip parameter storage; interchangeable INT8 (P=128) vs NF4-g16 (P=64, half URAM) Quantized Linear Units at 250 MHz.

4. **The Skeleton in the Closet** — 52.5% / 38.7% / 2.10× / ∼17× / it/J-at-TDP unpaid as full-system accounting on p.1–3; interconnect and host sync costs unread; works because DAE is ∼1.8M and fits on-chip—larger action heads break the premise; ASP-DAC short-paper length limits depth.

5. **可提取的问题线索**（仅 p.1–3，有数字，无机制名）

1. 边缘 GPU 擅长并行化计算密集的视觉 Transformer，但对 **Diffusion Action Expert** 类模块：多步去噪需反复从 DRAM 装载参数，表现为**内存绑定**，宽计算通路利用率低。(p.1 Abstract / §1)
2. 即便 Octo 等紧凑 VLA 相对早期模型缩小数量级，RTX 4090 上仍约 **17 / 13 it/s**、功耗约 **200 W**，难以进入移动操作、仓储与野外功率/热/成本包络。(p.1)
3. DAE 参数仅约占模型很小比例（约 **1.7–1.8M** vs 总 **27M / 93M**），却因 **T≈20** 步迭代采样成为边缘端到端延迟瓶颈。(p.1–2 / Table 1)
4. 边缘 GPU 上 INT8 DAE 足迹约 **1.8 MB**，接近名义 **2 MiB** L2；共享、不可钉住的 L2 无法保证跨全部去噪步的权重驻留。(p.2–3)
5. 大型图像扩散 FPGA 加速器仍常依赖片外存储器，因其网络比机器人动作头大几个数量级——**小到可全片上、却迭代到成瓶颈**的工作点未被 prioritze。(p.2 Related)
6. 异构划分要求：感知骨干留在 GPU，动作头在 FPGA 上以确定性计算流水运行且**去噪循环中无动态片外取参**；否则 I/O 特性与计算特性错配依旧。(p.1–2)
7. 量化策略影响片上资源与并行度权衡：更高并行的整型通路 vs 更省 URAM 的低比特分组，会改变动作头延迟与可容纳模型规模。(p.1 贡献 / p.3)
8. 端到端需在真实边缘异构平台上证明延迟与能效收益，并显式计入跨器件传输与主机同步；完整测量口径 unread。(p.1 Abstract)
