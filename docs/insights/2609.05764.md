## 四视角独立批评

### 微架构

Visible by p.3: NVM array as write-once KV store; SA comparators with fixed codebook refs; 16-entry dequant LUT + norm multiply; static Hadamard crossbar for rotation; digital attention. Missing: array size, endurance budget, how many SA refs, noise σ sweep details (promised §4).

### 负载

Llama-3.2-3B / Llama-3.1-8B / Qwen2.5-14B; contexts to 32k. Decode-only KV traffic; no prefills/training.

### 仿真方法学

Analog non-idealities on rotation crossbar and storage cells at 'realistic device levels'; energy claims 3.1–3.6× / 8× metadata vs KIVI. No GPU SKU or cycle model on p.1–3.

### 工业可行性

NVM endurance vs write-once KV; fixed-range converters lock format; ICCAD venue leans CAD but payload is memory-interface co-design. Product path needs verify-write policy and retention.

## Master Class

1. **The Real Abstract** — Put long-context KV in dense on-chip NVM with a quantization layout that fits fixed-range converters and tiny per-vector metadata (~3%), not GPU-style 25% group metadata.

2. **The Rashomon Synthesis** — Memory people want density/endurance; algo people want KIVI accuracy; mixed-signal people want fixed refs. Shared premise: GPU quantizers break when KV lives behind dense NVM peripherals.

3. **The Magic Trick** — Make every coordinate share one fixed range so one codebook + fixed SA refs digitize the whole cache.

4. **The Skeleton in the Closet** — Software accuracy still below KIVI/KVQuant; wins claimed at interface energy/capacity. Crossbar+storage noise realism deferred.

5. **可提取的问题线索**（仅 p.1–3，有数字，无机制名）

1. 长上下文自回归解码每步都要读完整 KV cache，体积随序列线性增长，解码变成内存带宽瓶颈而非算术吞吐瓶颈。(p.1)
2. KIVI 类方案给每组坐标挂全精度 scale/zero-point，元数据约占存 KV 的 25%。(p.1)
3. RRAM 单元面积约仅为 SRAM 的 1/23，长上下文 KV 放不进片上 SRAM 时仍可能塞进可接受的 NVM 管芯预算；但写入远贵于读取并消耗耐久，宜写少读多。(p.1–3)
4. NV 阵列是稠密规则地址，压缩稀疏离群结构无法原地驻留；必须保持全精度无噪声的量化元数据要占数字 SRAM，单比特面积约贵 23×。(p.3)
5. 读出外设转换器分辨率与输入量程在流片时固定，若每 token 需要不同量程就要每步重配转换器。(p.3)
6. 把 GPU 风格量化映射到同一 NVM 时，报告的 KV 读能量开销可到约 3.1–3.6×（相对接口匹配格式），且去掉稀疏结构后 KVQuant 检索精度会崩溃。(p.2)
