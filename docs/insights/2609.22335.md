## 四视角独立批评

### 微架构

VLA 两阶段（VLM + action head）可异步流水，但 GPU CTA scheduler 的队头阻塞使大 VLM grid 占满各 SM 的 CTA 槽，尽管 CUDA Core / 带宽仍有空闲，action-head 内核仍被堵在分发器后。前三页给出的具体分发器改动（机制索引用）：(1) 启动描述符增加三个 4-bit 字段编码 CTA 对 Tensor Core / ALU / DRAM 带宽峰值的占用比例（一次离线 profiling）；(2) work distributor 每 SM 增加三个 8-bit 利用率计数，在准入/完成路径按预剖析值更新；(3) 贪婪准入改为两阶段：阶段 1 保证每个有未完成工作的活跃内核至少准入 1 个 CTA（防微内核饿死），阶段 2 按与 SM 剩余能力最匹配的强度向量填满。实现声称基于 Accel-Sim（RTX 4090/5090）+ NVBit trace。这已超过“纯表征”——是明确的 dispatcher/scheduler 机制。未读：面积、时序、与真实 NVIDIA 调度器差异。

### 负载

四模型：CogACT（扩散头 ~300M DiT）、Octo（轻量扩散 ~3M）、π0.5（工业流匹配）、GraspVLA（流匹配 + CoT）。控制频率常要求约 ≥50 Hz；单 GPU/边缘上 VLA 延迟未必达标。表征（p.2）：四模型中位 SM 吞吐仅峰值的 18%–30%；action 阶段最忙时 Tensor Core 仍 <3%；VLM prefill/视觉编码平均 Tensor Core 约 37.4%。两 CUDA stream 朴素并发：VLM 阶段近零减速，但 action chunk 发射速率约为 action 单独跑的一半。Action head 含数百微内核，中位时长仅数微秒（即便 torch.compile 融合后）。挑战：共驻组合微秒级变化；微内核窗口容不下在线 profiling / 抢占。

### 仿真方法学

Accel-Sim + NVBit traces；RTX 4090 与 5090；吞吐增益最高 28%、平均 20.5%——abstract unpaid。前三页无周期模型校准数字、无 RTL。PACT’26 身份明确。仿真可信度取决于 trace 是否覆盖多 stream 真实 launch 序与 CTA 资源记账——未读。

### 工业可行性

命题是改 GPU 硬件 CTA 分发器 + 轻量运行时包装注入标签，不改内核源码（兼容闭源 vendor library）。工业墙：GPU 厂商调度器为机密 IP；4-bit/8-bit 记账精度是否够；离线 profiling 在驱动/模型更新后的维护；与现有 MPS/流优先级/抢占功能的交互。机器人控制 ≥50 Hz 是真实产品约束。前三页未给硅面积或驱动改动行数。

## Master Class

1. **The Real Abstract** — Decoupled VLA phases should overlap on one GPU, but the CTA dispatcher’s head-of-line blocking lets huge VLM grids monopolize SMs while action micro-kernels wait, leaving CUDA Cores idle. Need dispatcher-visible resource tags and a non-greedy admission policy that keeps both phases’ CTAs flowing.

2. **The Rashomon Synthesis** — Robotics people pipeline VLM/action streams; GPU scheduling papers preempt or profile online; vendor libraries are closed-source. Leftover: microsecond action kernels + nondeterministic co-residency make prior schedulers miss, while the hardware dispatcher still admits greedily.

3. **The Magic Trick** — Offline per-kernel TC/ALU/MEM tags + per-SM utilization counters + two-phase CTA admission (anti-starvation then complementary fill).

4. **The Skeleton in the Closet** — 28% / 20.5% unpaid; Accel-Sim≠shipping GPU scheduler; profiling tags assumed stable; only flow-matching/diffusion two-phase VLAs characterized.

5. **可提取的问题线索**（仅 p.1–3，有数字，无机制名）

1. 机器人控制频率常要求接近或高于约 **50 Hz**，而边缘设备与单 GPU 上的 VLA 推理延迟未必满足该闭环需求；吞吐不足时即使用 action chunking，机器人在窗口内也无法响应新观测。(p.1)
2. 四款代表性 VLA 在推理中严重低利用 GPU：全模型中位 SM 吞吐仅峰值的约 **18%–30%**；即便在最忙阶段，action 相位的 Tensor Core 利用率仍低于约 **3%**。(p.2)
3. 视觉编码与 VLM prefill 偏高算强，Tensor Core 平均利用率约 **37.4%**；action expert 以 batch=1 运行且含大量低强度内核——两相位本可在资源维度互补，但朴素并发并未变成吞吐。(p.2)
4. 将两相位分到独立 CUDA stream 时，VLM 相位近乎零减速，但 action head 显著变慢：action chunk 发射速率大约只有 action head 单独运行时的 **一半**，尽管来自 VLM 的干扰可忽略且存储带宽仍有余量。(p.2)
5. 根因指向硬件 thread-block（CTA）分发器的队头阻塞：VLM 启动的巨大 grid 超出 GPU 空间容量，分发器几乎只用 VLM 的 thread block 占满各 SM；即便各 SM 在整个 VLM 执行期 CUDA Core 仍有充足余量，硬件调度仍把两相位串行化。(p.2)
6. Action head 以数百个微内核为主，中位时长仅数微秒（即便经 TorchInductor / torch.compile 等融合之后）；共驻的 VLM 内核在微秒粒度上切换，使静态/提前调度与依赖采样窗口的在线剖析、以及上下文切换开销大于内核本身的抢占式调度都难以套用。(p.2)
