# 2609.06270: Towards Enabling Distance-Based Memory Addressing (first-3-pages note)

- Domain tag: ANNS / near-array distance memory
- One-line hardware fact (from p.1–3 only): Distance-Addressable Memory: 1T-1R array + near-array processor computes approximate per-datapoint distances to emit partially ordered responses for post-process pruning/rerank.
- Reading scope: **PDF pages 1–3 only**. Methods/eval unread by design where they begin after p.3.

## 四视角独立批评

### 微架构

NAP + 1T-1R; distance-as-address pruning after scan. Missing on p.1–3: array dims, how top-k partial order is physically sorted, ADC/bitline precision.

### 负载

Million/billion-scale embedding vectors; ChatGPT-like / retrieval / recsys / web search cited. Metrics: recall-k@k, QPS, energy.

### 仿真方法学

Claims 52.7× throughput / 97× latency vs compression baseline on Xeon E5-2680; +50% area vs RRAM chip; 4.15× energy. Simulation-based—methodology not on p.1–3.

### 工业可行性

BEOL RRAM story; area +50% vs baseline RRAM; need to prove rank quality under device noise for production ANNS.

## Master Class

1. **The Real Abstract** — Make memory emit distance-ordered candidates so pruning is post-processing on a parallel in-memory scan, not indirection-heavy index walk.

2. **The Rashomon Synthesis** — Algo wants recall; memory wants sequential/parallel scan; PIM wants no pointer chasing. Shared: curse of dimensionality forces huge touches.

3. **The Magic Trick** — Turn 'closest' into an addressable property of the array response.

4. **The Skeleton in the Closet** — 52.7×/97× vs one CPU compression baseline; approximate distance quality vs exact under noise not in first pages.

5. **可提取的问题线索**（仅 p.1–3，有数字，无机制名）

1. 高维精确 k-NN 在 D≥100 时几乎只能暴力，每查询 O(N×D)，大数据集上算力与带宽都不可接受。(p.1–2)
2. 无论图索引还是压缩索引，为保高召回常需访问向量集的很大比例，ANNS 呈带宽受限；压缩索引在其高吞吐配置上 recall-k@k 常 ≤0.6。(p.1, p.3)
3. 图索引为高召回要加深遍历，多次间接访存使带宽效率差；索引构建与邻接存储开销大，可扩展性差。(p.1, p.3)
4. 传统索引在剪枝时依赖内存间接，与 PIM 的 SIMD 式计算模型不契合。(p.1)
5. 现有索引对分布外查询、索引新鲜度、过滤查询支持差，常靠周期性重建索引并付出召回/吞吐代价。(p.3)
