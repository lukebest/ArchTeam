## 四视角独立批评

### 微架构

Tiled 2-D mesh: each tile has a MAC array, four-bank KV SRAM, partial-sum scratchpad, and a two-VN router. Fig. 2 is 4×4; text says scalable to 8×8. A per-column controller broadcasts descriptors (ℓ, h); tiles resolve home π(ℓ,s) and inject KV_FETCH on VN1. Controller claimed off the critical path (4-cycle combinational TAKV). Three named planes: TAKV places macro-block B(ℓ,s) at load time (lazy occupancy swaps); MARE coalesces, multicasts, and splits VCs; PAD runs PF / TM / RD and credits the router. Macro-block B(ℓ,s) covers P consecutive tokens of layer ℓ across all heads and both K and V; |B| = 2H dh P · bpe. With P=64, H=32, dh=128, bpe=2, |B|=1 MB is the placement and multicast unit. Affine home: π(ℓ,s)=(ℓ mod W, (a·ℓ+s) mod H), a odd and gcd(a,H)=1 (e.g. a=W+1). Authors state this does not shorten mean hops to a fixed home; the claimed gain is spreading injection / bisection load. Occupancy swap every K=128 steps: sample q̄e from credit counters; swap two homes iff Σ q̄e² drops and per-tile capacity Nmax is preserved (4 comparisons, 2 register writes, one control cycle). Nmax = L⌈T/P⌉/(WH); example 256 MB logical KV at L=32, T=32768, P=64, W=H=8. U280-class platform: HBM2 8 GB / 460 GB/s plus DDR4 32 GB; 16 GiB slab does not fit HBM. 512 URAMs → eight URAMs (288 KB) per tile—a four-bank streaming window, not a 1 MB block—so homes promote HBM/DDR into URAM under tile-local prefetch descriptors. MARE flits (Table I): KV_FETCH / KV_DATA on VN1 (512-bit payload); PART on VN0 (512-bit partial logits + softmax running stats). Home merges head masks in Wcoal=12 cycles, then an XYM spanning tree over D(M) (O(H log H) build, H=32, +4 control cycles). Replication only at tree branches; 16-entry exact (seg,ℓ) tag table plus 256-bit bloom over Wb=96 cycles; suppress only on exact hit, so bloom false positives never drop a first arrival. Deadlock: VN0 unicast PART on dimension-ordered XY; VN1 FETCH/DATA on XYM-restricted turns; no flit holds a VN0 buffer waiting for VN1 or vice versa. PAD: PF issues KV_FETCH(s+1) iff home injection credit Cπ>0 (one outstanding per (seg,ℓ)); TM writes zs = q Ksᵀ / √dh into scratchpad (≥80% MAC when FIFO nonempty); FIFO F=48 covers RTT 2Lmax+tack≈22 cycles plus Wcoal; RD is FlashAttention-2 online softmax so V-flits never materialize a full attention matrix. Implementation sentence on these pages: 8×8 interconnect, 512-bit wormhole, four-bank tile-local KV SRAM, dh=128 systolic PEs, TAKV/MARE/PAD in the datapath. CENT / SHARED / MESHKV named as same-platform configs; ASIC area, process node, and full PE array size are not on p.1–3.

### 负载

Autoregressive transformer decode on tiled accelerators: one query row (dh≈128) meets a KV slab that grows every token. Prefill amortizes tile hops; decode does not. Cache size Γ(T)=2LHdh T · bpe; FP16 LLaMA-2-7B (L=32, H=32, dh=128) at T=32768 is ≈16 GiB, and every decode step reads all of it. B=1 decode is called out as exposing every byte with no reuse (vs FlashAttention tiled prefill). Instrumented FP16 LLaMA-2-7B at T∈{8192,32768}: layers visited in order (prefetch window = L layer traversals); heads that share a prefix span request identical segments (Mistral-7B GQA G=4; LLaMA-2-7B multi-head). At T=32K, 78% of segment requests arrive within 12 cycles at the same router. Named unread eval models: LLaMA-2-7B and Mistral-7B at 8K–32K. Compression / eviction / DRAM paging are treated as complementary, not replaced.

### 仿真方法学

Abstract: on an 8×8 FPGA with LLaMA-2-7B and Mistral-7B at 8K–32K, “reduces interconnect traffic by up to 58%, improves KV bandwidth utilization by 2.1×, and delivers up to 1.9× multi-stream throughput.” Fig. 1 (T=32K, LLaMA-2-7B, B=1) is a bisection link-cycle breakdown: CENT drawn at 41% back-pressure; SHARED and MESHKV bars are drawn, no other numeric table. Evaluation chapter is §IX (unread). Treat 58% / 2.1× / 1.9× as unpaid until unread plots. 41%, 40–60% spoke–hub, 78%/12-cycle, 16 GiB, 8 GB / 460 GB/s, 288 KB URAM, F=48, ≈22-cycle RTT are author-stated setup / characterization numbers already on p.1–3.

### 工业可行性

Product move is replace point-to-point KV buses with an attention-aware fabric on a mesh that already has private SRAM. Adoption constraints already on these pages: 1 MB multicast units vs 288 KB URAM windows, so HBM/DDR prefetch stays in the loop; two VNs plus credit FIFOs plus a 16-tag/bloom safety net; occupancy swap is a 128-step, one-cycle heuristic, not a closed placement solver. 8×8 FPGA with 512-bit wormhole is the only implementation sentence; no process node, router area, or HBM channel count on p.1–3. Multi-stream 1.9× is unpaid.

## Master Class

1. **The Real Abstract** — Decode is not only DRAM-bound: a growing KV slab plus one logical home turns the mesh into a spoke–hub. Treat resident KV as packetized flows—spread homes, multicast each payload once, and hide NoC RTT behind a credit-aligned prefetch / multiply / softmax pipe.

2. **The Rashomon Synthesis** — Serving people page or compress KV behind a controller; NoC people route generic GEMM on a 2-D mesh; attention people tile softmax on a GPU. The leftover problem is structured gather of the same prefix segments to many heads on a fabric that was never a KV interconnect.

3. **The Magic Trick** — Affine-stripe KV homes; multicast once per tree branch with exact-tag duplicate suppression on a VN0/VN1 split; overlap prefetch, tile multiply, and streaming softmax behind FIFOs sized to the NoC RTT.

4. **The Skeleton in the Closet** — 58% / 2.1× / 1.9× have no config table on p.1–3; 1 MB blocks vs 288 KB URAM puts HBM prefetch on the critical path; occupancy swap every 128 steps is a local Σq̄e² heuristic; bloom+16-tag miss/false-forward behavior is unread; 8×8 FPGA ≠ an ASIC mesh.

5. **可提取的问题线索**（仅 p.1–3，有数字，无机制名）

1. 自回归解码时，单条查询行（头维约 128）要对着随 token 不断增长的 KV 板读取；预填可摊平片上跳数，解码不能。(p.1)
2. FP16 下 LLaMA-2-7B（32 层、32 头、头维 128）在上下文长度 32768 时，KV 约占 16 GiB，且每一步解码都要读完整份缓存。(p.1–2)
3. 当 KV 落在单一逻辑内存控制器时，网格退化为辐辏：多请求者挤向同一注入点，bisect 链路上约 40%–60% 的链路周期耗在背压上（文中集中式配置示意约 41%）。(p.2, Fig.1)
4. 在上下文 32K 的仪表化解码中，约 78% 的段请求在同一路由器处于约 12 个周期窗口内到达，说明访问在时间与头组空间上高度聚集，集中式路径更易热点。(p.2)
5. 16 GiB 量级的 KV 板放不进单块 HBM（文中平台 HBM2 约 8 GB、460 GB/s），片上窗口只能是流式暂存，远程访存与片上搬运叠加。(p.3)
