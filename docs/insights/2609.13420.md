## 四视角独立批评

### 微架构

Visible by p.3 only as claimed blocks: inter-tree control “toolbox”, KD-tree subsystem (incl. balanced constructor for dynamic replanning), Parallel-Query Retrieval for multi-bank memory balance, Look-ahead Planning Engine with in-order commit. Story is irregular SBMP/FMT*: latency-variable nearest-neighbor + collision queries, unstructured parallelism, evolving active set. Port counts, bank depths, cycle schedules, and how look-ahead speculation interacts with commit are after p.3. Headline ASIC comparisons (FMT* baseline, MOPED) are author claims until eval is opened.

### 负载

Robotics / autonomous / embodied / humanoid / manufacturing motion planning in high-DoF and unknown scenes. Motivation numbers: MPCC at 100 Hz with per-step replanning; topological replanning windows ~5–7 ms search + 10 ms optimization; nano-drone class ~10 cm / 27 g; 6-DoF planners tens of seconds; Kuka 7-DoF GPU tens of seconds; Jetson TX-2 planning 3.5–8× slower than perception+control (MAVBench); ARM Cortex ~5 s / ~1 W per indoor query vs ~10× power / ~100× throughput desire. Fig. 2: FMT* path/runtime trade-off vs PRM*/RRT*/BIT*; FMT* runtime dominated by neighbor search (not collision). Profiling host named: OMPL on Threadripper 3960X @ 3.8 GHz.

### 仿真方法学

p.1–3 are intro + background + motivation (Fig. 1 FMT* iteration cartoon; Fig. 2 planner compare + runtime breakdown). Synthesis node (16 nm), 500 MHz, and all speedup/area/power geomeans appear as claims; RTL/bench methodology unread. Treat >10³× / 8.8× class numbers as unpaid until eval section is opened.

### 工业可行性

Product story is on-device real-time planning under battery/form-factor and closed-loop ms budgets—closer to robotics SoC IP than datacenter AI. Retargetable “FMT* family substrate” (control layer vs fixed datapath) is the adoption hook, but integration with perception/control stacks, safety certification, and dynamic map updates is absent on p.1–3. Competing prior HW (RACOD collision parallelization; MOPED RRT*) already exists; the gap claimed is FMT*-specific neighbor-search + wavefront structure.

## Master Class

1. **The Real Abstract** — Sampling planners that minimize collision checks still die on high-dimensional nearest-neighbor search; build a dedicated irregular-spatial accelerator substrate for FMT*-family wavefront expansion under ms/power envelopes.

2. **The Rashomon Synthesis** — Algorithm people see FMT* as the quality/runtime sweet spot; systems people see planning as the PPC bottleneck (3.5–8× vs perc+ctrl on TX-2); architects see unstructured, memory-intensive, data-dependent search that GPUs load-balance poorly.

3. **The Magic Trick** — Expose inter-tree and intra-tree parallelism without wrecking path quality, and put KD-tree + multi-bank query + look-ahead commit in silicon.

4. **The Skeleton in the Closet** — All ASIC/CPU speedups and area/power factors are unread beyond p.3; “first FMT* accelerator” is a positioning claim; §III starts the actual algorithm on the next page—first-three-page readers must not invent those mechanisms.

5. **可提取的问题线索**（仅 p.1–3，有数字，无机制名）

1. 运动规划要在高维构型空间里探索大量采样点才能兼顾成功率与路径质量，计算开销很大；安全关键场景又要求本地实时规划，云端卸载因网络时延不可预测而不合适。(p.1)
2. 即便选中相对友好的波前动态规划类采样规划器，高维真实环境里最近邻搜索仍是主计算成本；剖析显示其大部分运行时间花在邻居搜索而非碰撞检测上。(p.1–2, Fig.2)
3. 敏捷飞行器一类闭环里，MPCC 控制可跑到 100 Hz 且每步在线重规划；拓扑重规划窗口可被压到约 5–7 ms 搜索加 10 ms 优化，最坏情况时延是一阶约束。(p.3)
4. 电池与外形极度受限的平台（如约 10 cm、27 g 的纳米无人机）同时收紧功耗与算力预算；感知–规划–控制任一环延迟都会进入闭环并恶化响应。(p.3)
5. 感知与控制已被大量优化后，运动规划成为端到端流水线主导瓶颈：6 自由度场景上优化后的规划器仍可达数十秒；GPU 上 7 自由度机械臂规划也仍可达数十秒量级。(p.3)
6. 在 Jetson TX-2 一类边缘板上，MAVBench 负载中规划可比感知+控制慢约 3.5–8×；ARM Cortex 级 CPU 室内导航查询约 ~5 s、~1 W，而典型微型移动机器人希望再低约 10× 功耗并高约 100× 吞吐。(p.3)
7. 该类采样规划负载高度不规则、数据依赖、局部性差、控制流发散，活跃节点集动态演化，GPU 上难做有效负载均衡；需要能吃动态访存与实时响应的专用结构，而不是套用常规 AI/视觉核。(p.3)
