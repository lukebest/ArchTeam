## 四视角独立批评

### 微架构

主张不是「又一个全局 SRAM + PE 阵列跑注意力」，而是把 MHSA 拆成级联模块并在模块边界放专用缓冲：SpikeQKV 三路并行产 Q/K/V 尖峰矩阵，Head Separator 做时分路由与 K/V 在线转置；SpikeAtten 用重排后的单头路径；RepConv 吃稀疏尖峰做局部空间依赖。SpikeGen 把 LIF 的 τ 固定为 2，把 1/τ 收成右移以砍除法器。反向工程：缓冲深度相对 T×N×(H×D)、三路流水与全局存储带宽的权衡、O(ND²) 数据流在多头/多时间步下的控制复杂度——均在未读节。

### 负载

动机负载是边缘视觉上的 Spiking ViT（含 Spikformer / SDT / SpikingResformer / SDTv2），痛点是参数量大 + MHSA 复杂，相对 ANN-ViT 虽用尖峰替换浮点乘加，内存访问与计算延迟/能量仍高。前三页点名「紧约束、长续航」场景（如轻量移动自主体/机器人），并批评既有 FPGA 方案功耗常 >4 W、专用 ASIC 仍常 >200 mW。负载审稿人还要：时间步 T、token 数 N、嵌入维 D、头数 H 的实际工作点；RepConv / SDTv2 路径是否主导面积；尖峰稀疏度变化时缓冲与吞吐是否塌陷——均 unread。

### 仿真方法学

Abstract 吞吐/功耗/面积/能效数字 unpaid。前三页方法元素：32 nm CMOS 综合叙事；与「全局片上存储 + 高功耗 FPGA/ASIC」对照的定性批评；LIF 公式与 τ=2 的面积动机。完整综合角、时钟、存储编译、以及相对 Chen/Xu/Gao/Li/Fang 等 SOTA 的 iso-条件对比 unread。勿把 20.3–29.1 TOPS/W 当作已付清。

### 工业可行性

命题是「为边缘 SViT 做超低功耗数字加速器，避开 >4 W FPGA / >200 mW 级 ASIC」。工业墙：级联专用缓冲是否锁死模型族（SDTv2 / RepConv）；多时间步 T 的片上缓冲容量与片外带宽；尖峰编码与训练工具链是否进产品推理栈；32 nm 数字实现相对成熟 NPU/MCU-NPU 的 BOM 与软件生态。前三页产品叙事清晰（mW 级、mm² 级），工艺迁移、多模型 ISA 与验证路径未给。

## Master Class

1. **The Real Abstract** — Spiking ViTs cut multiply energy but still drag huge parameters and MHSA through memory-bound digital pipelines; published FPGA/ASIC SViT engines sit above ~4 W or ~200 mW and congest a global on-chip memory, missing reparameterized SDTv2-style blocks that edge robots actually need.

2. **The Rashomon Synthesis** — Algorithm people see spike sparsity and LIF; accelerator people see Q/K/V + attention + RepConv as separate kernels fighting one SRAM; edge-systems people see a power envelope measured in tens of mW. Leftover: cascade the MHSA stages and put the working sets in inter-module buffers so global memory stops being the choke.

3. **The Magic Trick** — Cascaded SpikeQKV → SpikeAtten → RepConv with specialized inter-module buffers; reorder QKV so attention cost drops from O(N²D) to O(ND²); cheapen SpikeGen by fixing τ=2 (right-shift instead of divide).

4. **The Skeleton in the Closet** — GOPS / mW / mm² / TOPS/W unpaid on p.1–3; SpikeAtten internals and head-parallel schedule unread; “better than SOTA trade-off” is a claim, not a proof obligation for this note.

5. **可提取的问题线索**（仅 p.1–3，有数字，无机制名）

1. 标准 Vision Transformer 依赖海量参数与复杂多头自注意力（MHSA）才能达到精度，从而阻碍在紧约束应用中的能效部署。(p.1)
2. 即使换成尖峰视觉 Transformer，巨大参数量仍因内存访问与计算的高延迟、高能耗，继续构成性能与能效挑战。(p.1)
3. 既有 FPGA 类 SViT 加速方案运行功耗常超过 **4 W**；专用 ASIC 方案功耗仍常超过 **200 mW**——对功耗苛刻、期望长续航的边缘场景（如轻量移动自主体/机器人）不合适。(p.1–2)
4. 既有设计常依赖**全局片上存储**保存处理中的数据与参数，导致片上访存交通拥堵，并抬高功耗/能耗。(p.1–2)
5. 既有加速器尚未覆盖采用重参数化模块的较新 SViT（如 Spike-Driven Transformer v2），与当前模型结构脱节。(p.1–2)
6. MHSA 运算本身结构复杂，使「再做一个超低功耗加速器」并非平凡工程；朴素注意力计算复杂度可到 **O(N²D)**（N 为输入 token 数，D 为嵌入维）。(p.1–2)
7. SViT 模型族虽整体网络不同，但共享相似 MHSA 结构要素：尖峰卷积层、尖峰线性层与尖峰注意力层——说明瓶颈集中在这一共用子图而非某一独家拓扑。(p.2)
