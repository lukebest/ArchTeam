## 四视角独立批评

### 微架构

Prefix caching 要把超长复用上下文的 KV 放在 GPU 之外的大容量介质上，但块设备路径引入 LLC 争用、主机 DRAM staging 与 NAND 延迟。CXL Type-3 虽给字节寻址与片上 DRAM 缓存（命中 ~100 ns / 未命中数十 µs），通用 CXL-SSD 仍按普通内存语义服务，与 LLM serving 的 chunk 组织脱节。前三页结构主张：以 KV chunk 为跨层共享单位——设备侧索引/发起 NAND 读、在 DRAM 记录 dispatch/完成进度供引擎直读、设备 DRAM 区域作为 GPU 源缓冲；并在此之上叠窗口化预取与层间搬运-计算流水。反向工程：chunk 索引结构、设备 DRAM 钉住/释放策略、与 vLLM/LMCache 的进度寄存器布局、仿真器相对真机的保真——均在未读节。

### 负载

动机负载是 RAG / 多轮 / agent 的长 prefix 复用：数万–数十万 token 的重复系统提示与文档。表征用 Qwen3-4B + vLLM/LMCache、128k prefix、chunk_size=32、每 GPU 32 GB 系统 RAM，对比 DRAM-only / NVMe SSD / SSD+CAT / ramdisk。CAT 隔离显示 P99 TTFT 可回收约 44%；ramdisk 仍约 1.8× 慢于直连 DRAM；stock CXL-SSD 约 3× 慢于本地 DRAM。负载审稿人还要：五模型扫参是否外推、并发会话与 prefix 命中率分布、chunk 粒度敏感性——前三页几乎只有单模型表征设定。

### 仿真方法学

Abstract：五模型上相对 stock CXL-SSD 平均 TTFT 最高约 2.6×（compute-async 预取）与 4.03×（layerwise 预取），平均落在本地 DRAM 的 1.5× 内——unpaid。前三页方法元素：NVMeVirt 上改后端 + 对照 Cylon CXL-SSD 仿真器；关闭异步加载以避免分配失败；Fig.2/3 给 TTFT 与 L3 stall。完整模型列表、流量轨迹与 ablation unread。勿把 abstract 倍数当作已付清。

### 工业可行性

产品命题是“为大容量 prefix KV 保留 NAND 容量，同时去掉块接口根因”，落在 CXL-SSD 与 serving 运行时的共设计。工业墙：真 CXL Type-3 SSD 固件是否愿意暴露 chunk 索引与进度；设备 DRAM 容量与 GPU 直读一致性模型；与 LMCache/vLLM 的 ABI 稳定性；仿真器（NVMeVirt/Cylon）到可采购器件的差距。相对纯主机预取或 GDS，前三页动机成立，但控制器 IP、耐久写放大与多租户 QoS 未给。

## Master Class

1. **The Real Abstract** — Prefix KV must leave GPU HBM, but block SSDs tax LLC, force host-DRAM staging, and still pay NAND; stock CXL-SSDs remove the block path yet stay ~3× slower than DRAM because the device does not share KV-chunk semantics or movement progress with the serving engine.

2. **The Rashomon Synthesis** — Storage people push CXL.mem + on-device DRAM caches; serving people know upcoming chunks and schedules; GDS/prefetch people move or overlap copies. Leftover: a device interface whose unit is the KV chunk, with progress visible to admission and GPU reads sourced from device DRAM.

3. **The Magic Trick** — Make chunks the device-visible I/O unit; expose NAND→DRAM progress; pin device DRAM as the GPU source buffer; coordinate windowed / layerwise prefetch with request scheduling under limited device DRAM.

4. **The Skeleton in the Closet** — 2.6× / 4.03× / 1.5× unpaid; characterization centered on Qwen3-4B + 128k/chunk32; emulator fidelity and real CXL-SSD firmware surface unread.

5. **可提取的问题线索**（仅 p.1–3，有数字，无机制名）

1. RAG / 多轮对话 / agent 反复复用系统提示、检索文档与历史，形成长达 **数万–数十万** token 的 prefix；prefix caching 要跨 GPU 内存扩展到主机与存储，但主机 DRAM 受内存通道与 DIMM 容量约束，难以常驻大容量 prefix 缓存。(p.1)
2. 用 NAND 后备 NVMe SSD 扩容时，块设备 I/O 线程与推理线程争用同一 LLC：仅做 L3 隔离即可把 **P99 TTFT** 改善约 **44%**，说明接口侧缓存争用本身就是显著开销，而非仅有介质延迟。(p.1, p.3)
3. 块接口迫使每个 KV chunk 先经主机 DRAM 中转再送 GPU；即便把介质换成 DRAM（ramdisk / brd 块设备），相对直接访问本地 DRAM 仍约 **1.8×** 更慢——接口与中转拷贝成本独立于 NAND。(p.1)
4. 在 SSD 相对 DRAM 的减速中，NAND 本身延迟约占 **一半以上**；另两块是块 I/O 的 CPU 缓存争用与主机 DRAM staging。(p.1)
5. 主机侧预取可重叠 NAND 延迟，但与“因 DRAM 容量不足才落到 SSD”的动机冲突：预取到的 KV chunk 再次占用主机 DRAM；且预取仍走块接口，staging 与争用成本仍在。(p.1)
6. GPUDirect Storage 可绕过 CPU/主机 DRAM 做传输，但仍先进入 VRAM staging，再经串行 reshape/copy 才进入最终 KV 布局——块取向数据路径未被根除。(p.1)
7. 通用 CXL-SSD（字节寻址 + 片上 DRAM 缓存 + NAND）在 prefix caching 下仍约比本地 DRAM 慢 **3×**，且不优于 NVMe SSD；设备内通用 next-n 预取几乎不改平均 TTFT，却产生无关 NAND I/O。(p.1–2)
8. 服务引擎（调度状态、KV 分块组织）已知将消费哪些 chunk，设备掌握数据位置与搬运状态，但缺共享语义：设备只收到地址而非 chunk，引擎往往只在搬运完成后才得知进度——语义裂缝导致无法协同安置与进度驱动调度。(p.2)
9. CXL Type-3 / CXL.mem 路径上，片上 DRAM 命中约 **~100 ns**，未命中经 FTL 取 NAND 约 **数十 µs**——容量扩展与命中/未命中时延鸿沟并存。(p.3, Fig.1)
10. 表征设定：Qwen3-4B + vLLM/LMCache，**128k** prefix、**chunk_size=32**，块设备配置每 GPU **32 GB** 系统 RAM，异步加载关闭以避免分配失败；多轮 Q&A 下对比 DRAM-only / SSD / SSD+CAT / Ramdisk。(p.3, Table 1)
